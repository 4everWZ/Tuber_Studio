# 新 OC 在正式工作站网关的两次中文短通话

两张成图均在物理 Windows 笔电 Chromium 收到 640×720 的 WHEP 音视频。使用工作站可信 IP 的 9443 隔离 Studio 登录页、普通应用凭据和已切换的正式 Realtime、Avatar 网关及 worker。未使用本机媒体服务、SSH 媒体隧道或旧稿成绩。443 生产库未配置未验选项。两次挂断均从正式会话读回 `closed`，9443 的临时双形象选择文件已经撤除；没有下线容器。

| 笔电接收实测 | mature 成图 | Q 成图 |
|---|---:|---:|
| MP4 可播放时长 | 14.23 s | 15.16 s |
| 原始 WebM 解码帧数 | 346 | 377 |
| 接收录音与模型回复 PCM 的包络相关 | 0.984 | 0.974 |
| 静音／有声帧口内面积中位数（像素） | 0 / 239 | 0 / 326 |
| 首次明显张口减首音 | −11 ms | −135 ms |
| 审核区相对认可成图的平均绝对像素差（0–255） | 5.2 | 5.5 |

每套都核对了登记 ID、Inochi 驱动及 Realtime 源会话。两次均通过浏览器麦克风送入同一授权角色 WAV，产生原生模型语音回复与播放回执。WebM 是浏览器对 WHEP 接收流的双轨录制，不混入本地麦克风。静音和有声以同一录屏音轨 RMS <0.004、>0.025 分组。首音取连续两段 5 ms RMS >0.012 的起点，首次明显张口取口内连通色块 ≥120 像素的首个视频 PTS。负值表示画面先动；两个短样本均在 160 ms 内，Q 的余量为 25 ms。这不是逐音素正确率或长通话性能结论。

回看接收帧，分别对应认可的正面成熟比例和 Q 版，而非母稿裁片。对接收音轨去掉首尾静音后用普通网关独立转写，两条均辨出中文问候“你好呀，我是蓝发…鱼娘”。两次转写的“鲸／金”有分歧，不据此认定同音字。原录屏保留，未改台词、接缝或 INP。未对传输抖动归因。

私有工件在 `runtime/private-artifacts/oc-whep-formal-03`，两套 ID 各有 `received.webm`、`call.mp4`、`metrics.json`、抽帧和转写。两个 MP4 均在笔电 Chromium 打开，实际推进播放时间并解码出音视频。

## 独立复跑

工作站配置普通网关凭据，笔电通过同一普通应用身份读登记与会话。默认执行 `uv run --locked python -m evaluations.oc_whep_call` 只核对笔电工具、语音样本与批准的源图，不发起请求。切换确认后加 `--worker-switched --studio <隔离工坊的可信HTTPS源> --output <新的私有目录>`，使用该副本的 `--storage-state` 或进程级 `OC_QA_LOGIN_TOKEN` 登录。隔离副本须指向正式网关的两个新 ID；不能为跑测而放开生产选择器。两套分目录留档；若只拿到模型 PCM、没有接收端录像，不能认定通话通过。
