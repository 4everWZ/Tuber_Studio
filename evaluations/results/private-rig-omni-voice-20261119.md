# 私有真实 Omni 语音与原画通话

2026-11-19，从独立服务提交 `c072d86` 单独提取 Gateway 和 Avatar 源码，用同一个临时 Studio 业务库依次呼叫常规与 Q 版。Chromium 的文件麦克风读取仓库的 `assets/whale/sample1.wav`。Studio 使用通话页面原有的麦克风采集和 AudioWorklet，发送 16 kHz 单声道 PCM。两次握手均报告 `model_native_duplex`，均在语音输入后收到工作站的 `response.output_audio.delta`。

Studio 使用仅限回环的隔离媒体网关签发浏览器短票。该网关使用普通应用凭据向部署的工作站网关申请另一张短票，以此建立真实 Realtime 上游连接。独立服务的原生来源绑定、Inochi2D 渲染和 WHEP 协商都在隔离媒体网关一侧运行。逐次 GET 会话确认其 Realtime 来源、rig ID、驱动和已接收的回执，挂断后读回 closed。共享网关查询两套测试用 rig ID 均返回 404，现场注册与直接订阅共享端点仍待验证。

声音核对取同一回复最先返回的至多三个 PCM 分段，与收到的 Opus 音轨按 20 ms RMS 包络逐段比对。画面核对分别采样实时播放器和 Chromium 录制的 WHEP 音视频，在两张原稿各自的口部窗口内取色，按相应音频的 RMS 分组。一次较早的 Q 版短测取得了匹配的音轨，但实时口部面积中位数仅从 1 增至 12 px，未过验收线。上表两场均通过实时和录制复核。这里验证语音触发、生成、播放和口部开合，音素准确度与长期性能另验。

修复前，一次 Q 版发送位置落后会话时钟 1225 ms。回归用例把视频读取滞后到 1360 ms，此时旧实现还读取 40 ms 处的静音，当前音轨已有语音。现在已经开始播放的 PCM 驱动视频跳过过期姿态，按当前帧的 PCM 渲染并保留对应 RTP 时间戳。首帧仍沿协商起点，音频按原顺序逐包发送。独立服务 16 项测试通过。

隔离网关连接远端时还需完成签票、准入与升级。调试时曾用时 4.81 秒，超过本地引擎连接原有的 3 秒预算。验收程序在隔离网关使用 Studio 的 30 秒握手期限。固定版本复跑分别用时 0.58 和 0.59 秒。普通凭据始终留在服务进程，未修改共享配置或重启服务。

复跑命令为 `uv run --locked python -m evaluations.private_rig_call`，需要 FFmpeg、Chromium 和相邻独立服务的项目环境（含 PyAV、NumPy、OpenCV）。输出每套形象的聚合指标，临时业务库、票据和媒体文件在结束时清理。[配置与输入文件](../../docs/guides/private-avatar-call.md)
