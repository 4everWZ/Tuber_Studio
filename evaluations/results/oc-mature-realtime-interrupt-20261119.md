# mature 私聊打断后的 Realtime 错误

工作站 9443 隔离 Studio 经正式网关、原生双工引擎及 Inochi worker 建立 mature 单通话，桌面 Chromium 经普通应用授权访问。网关已滚动至参考音色更新版本。每次只在验收浏览器加载适配隔离 Studio 版本的产品候选模块。各场独立计时，不并行调用 Responses，不写入外部平台。

**复现。** 原控制器在窗内 10.523、46.422、65.837 秒收到三次有声打断。第三次点击时收端音轨 RMS 为 0.0568。67.675 秒收到当前回复的 `response.done`，紧接着收到 `invalid_request_error / response_not_active`。控制器执行 `call_end`、关闭会话。第四次 WHEP POST 已获 201，新轨没有呈现首帧。最后一帧停在 65.837 秒，直到窗末仍有 24.163 秒无呈现。

**服务语义。** 已核对运行中引擎的 `engine/duplex/session/runner.py`。取消目标与活动响应不符，或无活动响应且客户端发送无目标的 `response.cancel`，引擎发出 `response_not_active` 并从当前命令返回。关闭中的会话由 `session/manager.py` 返回 `session_closed`。产品共用的 Realtime 消息入口只在握手完成、错误类型和错误码均匹配时保留通话，并记录 `response_error`。其他错误、WS 关闭和错误仍走原终止分支。

**单独验证错误处理。** 保留原取消、清空两条命令，第三次通过页面按钮在已观察到回复结束后打断。52.019 秒点击，52.200 秒收到同码。第四段新视频轨在 55.620 秒首次真实呈现，距点击 3.600 秒，末帧在 89.986 秒。按新轨的音视频 SSRC 核对，56.018 → 89.070 秒视频解码 12 → 833 帧、视频收包 44 → 4279、音频收包 23 → 1635，视频累计丢包 0 → 103。后续两个新响应均收到 Realtime 音频，但第四段 WebM 解码为静音。90 秒窗末网关为 active，90.494 秒按挂断时 Peer 和 ICE 均为 connected，网关读回 closed。

**产品打断改为一次清空。** 运行中引擎的 `resolve_clear_output_audio` 可以选择仍有待播音频的最近回复，`runner.py` 的清空分支会取消活动响应或清理播放游标。运行中 Avatar 的 `Session.ingest` 对下行取消、清空分别推进本地 epoch，并丢弃 epoch 更旧的上行事件；引擎处理无活动响应的取消时可以直接返回。因此同一点击发两条命令会让两侧对进度的判断有机会分歧。双命令场没有保存每个上行音频包的 epoch，无法逐包确认静音原因。产品按钮现只发一次 `output_audio_buffer.clear`，继续执行本地立即停播和 WHEP 换轨。
