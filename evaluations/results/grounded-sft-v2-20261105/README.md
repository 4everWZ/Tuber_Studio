# 大肥鱼视觉 SFT 第二轮

选择 MiniCPM‑V 4.7 续训版与单请求“先材料后问题”输入做 Jetson 隔离实测。新视频里，双来源的事实和引用一起答对的题增多，缺证据时也更常停住。上一轮权重答全事实的题更多。普通问答相近，纠错仍弱，续训有一例原本答对的题退步。

## 工作站对照

从 8 个新 B 站公开视频冻结 40 题。32 题要求回答，其中字幕、画面各 8 题，图文互补 16 题。另外 8 题缺少关键证据。视频 ID 与首轮 12 个视频无交集。人工核对截图、CC 和原答，引用覆盖每一项关键事实才计入共同通过。角色玩笑可以保留，凭空报真实数值、把字幕时码当成数值、漏答一半题目分别记录。暂缓单列，能明确说材料没给的公开回复也记为谨慎回应。25/32 是参考，选型结合原答和用户优先要修的问题。[题目](../../cases/grounded-real-video-v2.jsonl) · [逐例复核](video-review.json)

续训版配合先材料后问题能把氢化植物油与截图里的油瓶分开引用，也能同时回答 24 小时和画面里出现的兼职字样。仍会把起始预算答成余额、把大猩猩认成熊，或答对文字却漏引画面。它有两道缺证据题引入了材料支持不了的说法。对照把逐源提取字段也放进同一请求时，三个 SFT 都对 40 题输出暂缓，原版暂缓 37 题，因此保留简单的输入顺序供后续复核。两类输入调整是在这批回放上探索的，结果会随素材变化。

所有回放使用同一个固定 llama.cpp 构建、同一图文材料、贪心解码、工作站 CPU 和 4096 上下文。为所有权重加上同一画面短编号，回放直接请求推理端点。续训版图文题输入 token 中位数由 630.5 降至 558。输出在 `v2-native-*.jsonl`、`v2-ef-*.jsonl` 和 `v2-sn-*.jsonl`，含原答、来源、token 和耗时。生产浏览、发布权限和直播延迟均有独立的验证入口。

## OC 与训练

24 个固定 OC 场景用同一底模 BF16 和贪心复跑。普通问答三版都通过 4/8，答对 list/tuple、限载、拼餐和单位。三版在涨跌百分比、奇偶数推理上都出错。第一轮和本轮重训能区分免费与开源，续训丢了这道；重训在比赛判据题陷入重复。续训第二轮记住玄关的蓝丝带，也能跟随巧克力交换；多轮对话仍会擅改分工或重复道具梗。通用的短答纠错提示在个别题奏效，也使其他题答偏。完整逐轮原答见 `v2-oc-*.json`，上一轮及原版、旧 DoRA 的同题原答保留在首轮报告目录。[固定场景](../../cases/grounded-oc.jsonl) · [第一轮报告](../grounded-sft-20261105/README.md)

新增 160 条训练和 16 条验证记录，原来的 600/60 条全量保留。补充记录来自 40/4 个已标注的授权短片场景，各衍生四种输入。字幕线索由项目撰写，真实公开视频只用于独立回放。续训用上一轮视觉适配器、学习率 `1.8e-5` 跑一轮。重训用同一固定底模、`3e-5` 跑两轮。两组沿用冻结视觉塔、语言 LoRA r16/α32、有效批量 16 和 4096 序列上限，各用一张 RTX 3090。两组共享对应的 4x 投影器。[续训日志](v2-training-continue.json) · [重训日志](v2-training-fresh.json)

权重保留在 `workstation:~/code/tuber-minicpm-grounding/gguf-v2-{continue,fresh}`，适配器保留在同目录的 `sft-v2-{continue,fresh}/adapter`。[续训 GGUF 清单](v2-bundle-continue.json) · [重训 GGUF 清单](v2-bundle-fresh.json) · [复现步骤](../../../tools/training/README.md)

## Jetson 128K 与 Genie

工作站大文件回传丢包时，经 SSH 取回 LoRA，在本地用与工作站校验一致的公开底模复现导出。Q4_K_M 与 4x F16 投影器均逐文件匹配工作站 SHA256，Jetson 实验路径 `runtime/models/grounded-sft-v2-probe` 加载前再次校验。实验引擎是相同提交的 CUDA 构建，q4_0 K/V、131,072 上下文，GPU 投影器，单 slot。

旧模型仍驻留时，GPU 投影器或 KV 分配失败。减少 GPU 层和微批后曾触发交换空间保护。通过推理 broker 释放已确认空闲的旧文本进程后，视觉候选和真实 Genie INT8 可一起运行。实验进程回收后，使用 broker `/llm/warmup` 恢复原选中模型并核对状态与配置。[在旧模型驻留时的诊断](jetson-resident-old-diagnostics.json) · [恢复记录](jetson-broker-restore.json)

实际送入 130,914 token，服务 usage 确认全部接收，183.354 秒后原样找回开头代号。长输入处理期间，Genie 在 3.693 秒合成另一句非静音音频，合成完成时模型仍在处理。普通单帧回复耗时 1.455 秒，整句 WAV 耗时 4.848 秒。实验期间最低可用内存 2,233 MiB，峰值交换空间增量 4.5 MiB。上述计时来自独立模型和 TTS 请求。[设备原始结果](jetson-128k-genie.json)

### 直播首段送播

Genie 原来在单次请求内按标点分段合成，全部拼成 WAV 后才发送给浏览器。现在本地 Genie 直播路径先送播第一段，播放期间预合成下一段。每段使用独立 nonce，旧确认作废，最后一段播完才写入记忆。人工取消会取消后续合成。

Jetson 用同一条固定台词、热态真实 Genie 和 Chrome Overlay 各跑一次。事件到首段 `playing` ACK 由 6.560 秒降至 1.643 秒，整条播完由 13.715 秒降至 9.058 秒。三段都收到浏览器的 `playing` 和 `ended`，相邻两段的间隔约 0.48 秒和 0.09 秒。固定台词屏蔽了模型生成耗时。完整 Mock 直播的混合负载和 p50／p95 待单独测量。[浏览器原始结果](jetson-genie-browser.json)
