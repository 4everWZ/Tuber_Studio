# 角色卡与个性化验收

- 角色工作室使用独立数据库和真实 Chromium。完整 JSON 从大肥鱼粘贴到新建的 v2，保留 v2 内部 ID。验证表单与 JSON 改名同步、坏 JSON 保留草稿、保存后注入激活错误并重试、刷新后状态、切换替代角色后删除和恢复。API 回归检查已删除的角色版本仍可按原 ID 查询。
- 个性化使用本地运营库的一致性副本，关闭自动运营并采用离线 Provider。1440 px 与 420 px 下验证三行设置、摘要及趣事弹窗、错误重试、键盘关闭和焦点返回。趣事显示 6 个归并后的来源楼，回执链接与记录一致。复测全程平台零写入。
- API 和受控生成回归覆盖记忆开关持久化、账号及角色隔离、切换后拒绝旧写入、关闭及重开后拒绝在途产物、已保存记忆继续管理、续跑从原进度开始。趣事回归验证三入口去重、待核对变为已送达后仍定位原楼。

## 运行实例复测

- 在工作台实际端口复现新版页面访问旧进程时的 405。确认直播和自动运营空闲，重启原业务服务。同一 Chromium 会话刷新后，记忆设置和已删除角色接口均返回 200。
- 在实际工作台点测记忆关闭、刷新后仍关闭、重新启用、摘要管理的搜索和筛选、趣事两个入口、键盘关闭和焦点返回。桌面及 420 px 窄屏通过。当前角色的两个列表为空，开关恢复到原先的开启状态。
- 在运营库副本的同版工作台点测摘要失败后重试、记忆编辑、归档恢复、候选分渠道授权、撤销、删除和补跑入口，并核对 6 个去重后的真实互动及回复链接。角色卡新建、JSON 保存、改名、激活、删除和恢复通过。复测平台零写入。
