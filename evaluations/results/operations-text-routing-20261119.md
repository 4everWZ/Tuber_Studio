# 自主运营文本分流验收

## 工作站回放

从原运营窗口只读提取一条实际评论、楼内已读记录、视频材料和超窗检查点。在临时业务库按同一事件入口执行「继续生成」，平台适配器拒绝写入，前台推理请求也被拦截。文本请求通过真实网关执行，响应由工坊照常计量及校验。

- 原网关组合在文本引擎复现 HTTP 500。去掉网页读取分支里的双段有限重复 URL 正则、保留长度约束后，同一报文返回 200。网页工具执行前仍校验完整 HTTPS 链接和访问边界。
- 文本引擎在启用思考时的一次回放返回 270 个输出 tokens，其中 269 个为思考，正文为空。运营 Chat 使用直接结构化输出模式后，本次回放返回有效决定。
- `llm-default` 模型卡实报 262144 tokens，预估和实际输入均为 4477 tokens，输出 265 tokens。原失败记录留在检查点，新一次生成完成，同一评论事件进入 `drafted`，产生一个绑定原父评论的 `pending_review` 草稿。平台写入为零，草稿无平台送达回执。

独立长文探针使用保存的公开视频字幕，工作站文本引擎对 24711 tokens 的结构化请求返回完整结果，预估计量与实际用量一致。该探针核对长输入通道，真实评论回放单独核对从检查点到审核草稿。两次回放的平台写入均为零。

隔离浏览器验证抽帧上限默认显示 5，手动保存 7 后刷新仍显示 7。配置回归确认取材服务也读到 7。
