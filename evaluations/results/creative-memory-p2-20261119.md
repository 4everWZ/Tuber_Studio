## 复跑入口

在工作站的独立 Core 与 nginx 环境复用已有可信 IP 证书、普通应用凭据与网关。空库使用全新私有卷和新的运行子目录，笔电使用独立 HTTPS 端口 9444。正式 443 属于迁移历史库，9443 属于部署预验。浏览器会校验隔离实例名，两个 Chromium 进程各自从工作站 IP 登录。

Core 镜像的工作目录为 `/opt/tuber`。验收使用已通过审稿回放的应用版本，runner 从同版仓库的 `evaluations/` 只读挂载至工作目录。隔离容器在共享给其专属 nginx 的网络命名空间内启动服务。Core 的 `TUBER_PRIVATE_REALTIME_PUBLIC_ORIGIN` 须等于浏览器访问的完整 HTTPS 源（含 9444），`TUBER_PRIVATE_REALTIME_ORIGIN` 使用专属 nginx 的内侧签票入口，`TUBER_PRIVATE_REALTIME_TOKEN_FILE` 使用已有普通应用 secret。以下命令中的 `p2-run-ID` 代表本轮新目录名。

```sh
python -m evaluations.creative_memory_browser host /data/p2-run-ID --bind 127.0.0.1 --port 9020
```

在笔电使用项目锁定环境运行浏览器。SSH 将本轮隔离 Studio 的登录文件直接通过管道交给 runner；SSH 目标和隔离容器名由当次部署提供。运行目录名会显示在终端。网关的普通应用凭据由工作站通过已有 secret 挂载读取。示例地址使用文档专用 IP。

归档补场按部署指南追加只读来源卷，设置清单及其获准分 P 原网址。浏览器命令再加 `--archived`。Playwright 的 Node 请求客户端可通过 `NODE_EXTRA_CA_CERTS` 读取该工作站的可信证书文件。已开场的专属 Core 需要滚动更新时，原命令加 `--resume`，保留相同卷、运行名及启动基线。正常任务继续会增加修订号，首个实际 edition 单独记录。

```powershell
ssh -T $Workstation docker exec $IsolatedCore cat /data/p2-run-ID/admin-token |
  uv run --locked python -m evaluations.creative_memory_browser browser --origin https://192.0.2.1:9444 --run p2-run-ID --login-stdin
```

将本次浏览器回执目录单独复制或挂载到工作站，以只读方式执行复核。浏览器回执包含当次私有正文，按私有证据保存。运行库、短片和密钥文件留在工作站的隔离运行目录。本次已将浏览器私有回执归档至工作站，随后停止专属 9444 Core 和入口，保留隔离数据卷。

```sh
python -m evaluations.creative_memory_browser receipt /data/p2-run-ID /evidence/browser
```

每次版次落库后可立即在工作站导出原文和逐项视觉绑定。`revision` 取当次真实任务修订号，输出目录名同时含实际成果版号。目录中有数据库原文、edition 行、每项物理短片和带归档窗口及来源的证据清单。

```sh
python -m evaluations.creative_archive_handoff /data/p2-run-ID /source-archive/manifest.json /private-review "$revision" "$task_id"
```
