# 角色卡切换实测

2026-11-20 使用隔离业务库、真实 Edge 浏览器和工作站现用 Omni。样本卡的人设名为「榛树站长」，称呼为「阿榛」，前台显示名为「林线值班室」。B 站绑定和运营登录账号使用两个独立夹具。

| 路径 | 结果 |
| --- | --- |
| 角色卡、Chats | 从角色工作室创建并激活，列表显示自身头像。对话标题显示「林线值班室」，输入框显示「发消息」。SSE 回复及持久记录能承接称呼、背景追问和已核验号主。 |
| 工坊事实、公开网页 | 角色绑定主页与运营登录分别返回各自账号。新卡打开公开示例页，得到真实 `web_page` 回执与标题。 |
| 私有通话 | 浏览器显示当前通话对象。首个 `session.update` 的参考录音与瑶瑶录音摘要一致。收到 `model_native_duplex`、音频帧和转写「旧石桥每晚七点点灯」。通话人设包含原角色名和话题材料。 |
| 直播、评论、私信、动态 | 播控台使用当前显示名。猜中题目的真实事件进入直播队列，Omni 读取结构化结果后生成台词，回放结束于合成阶段。评论、私信生成与动态评估使用新卡，新动态留在隔离审核队列。 |
| 任务 | 后台读取了工坊直播会话状态。改口后，同一任务的新版本生成便笺并以「林线值班室」署名。样本便笺中有一处把工坊会话状态表述成平台状态。 |
| 历史、记忆、待办 | 清空显示名后，标题回退到角色 ID，已有七轮对话和任务成果保留原署名。切回大肥鱼后，原对话、记忆和预约任务可见。两张卡的记忆和待办各自归属原卡。 |

抽查实际发送给文本及语音模型的输入，模型读取人设名称、常用称呼及相关背景。前台显示名始终留在 Web 展示和署名记录。隔离业务库的平台账号写入、私信尝试、发布尝试和任务代回尝试均为 0。

回放定位出两个入口问题。私有通话先取参考录音，再签票和计时握手。后台 Responses 只有在本轮原话或检索回执提供可读网址时才收到打开网页的工具。角色卡与通话、任务与来源限制、直播与游戏、运营渠道的相关 Python 测试通过，前端 Node 测试 67 项通过。
