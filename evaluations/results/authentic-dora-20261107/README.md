# 大肥鱼 DoRA 刷视频实测

workstation 用固定 llama.cpp 的 CPU 构建加载同一发布的 Q4_K_M 和 4× F16 投影器，窗口 16,384 tokens。五支 B 站视频各实时读取三帧故事板，使用同一分 P 的 88 条已缓存平台 CC 摘录。当前凭据被字幕接口拒绝。本次依次运行逐帧观察、运营内容判断、带字幕与画面标签的正文决策，并用一支视频保留模型原答连续聊五轮。正文决策是独立探针，在内容判断请求补画面时也继续运行。全程使用只读素材。[逐例结果](workstation-video.json) · [发布版本](https://huggingface.co/4everImmortality/dafeiyu-minicpmv/tree/68f9542e3c7dee1b41a1be12fe97f3095819b952)

- 15 次逐帧观察、5 次内容判断、10 次正文决策和 5 轮聊天均正常结束。关闭思考时的 5 次正文决策用 45–124 tokens。打开思考的 5 次用 87–218 tokens，均在 1,024 预算内。正文决策耗时约 1.6–3.7 秒，仅计工作站模型请求。
- 五轮连续聊天中，最高相邻台词字符相似度 0.20，仍重复提到同一张买语音模型的截图。去掉来源标签的对照中出现句内复读「选择一或者二选一或者二选二」。
- 五个内容判断已看到逐帧观察，却都要求补画面。正文独立探针 4/10 给出公开回复，4 条都只引用字幕。提到画面时会漏引对应来源。例子包括把蓝色图标猜成下载按钮，以及提到八个图标却只给出字幕编号。
- 五轮对话里的自称只出现「我」。另一条正文使用了「鱼鱼」，当前样本量不足以估计各自称的自然频率。

Jetson 的运营节点加载同批权重与投影器，实际窗口 131,072。认证视觉端点处理了一帧真实故事板。桌面端三帧准入首次遇到充分性与引用矛盾，解码 schema 与现有验证规则对齐后复测通过。三张图各 1,024×1,024，输入合计 1 MiB，最低可用内存 3,245.8 MiB，换页增量 0。该探针验证输入容量和运行资源。
