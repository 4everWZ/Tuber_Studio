# 新 OC 正式驱动：物理笔电四个 90 秒窗

**首包测量限制：** 跨接口监听套接字在整个观察期报告 42 次捕获丢包，未记录被丢包的 SSRC。这不是播放器丢包计数。表中三个数值是按各轨**首个观察到的发送包**计算的最大值，无法独立保证捕获了每条轨的第一个发包。无需发送锚点也能证明的绝对偏差下界，依表顺序为 220、300、150、200 ms。帧率和冻结由笔电直接测量，不依赖此探针。

**四窗均未准入，不启动 20 分钟。** 9443 隔离工坊经可信 HTTPS IP 登录，临时选择表指向已获选的两个新 OC ID。正式普通网关建立原生 Realtime 会话并由已部署的 Inochi worker 提供 WHEP；未替换任何服务。每套先测无附加推理的通话，再测同一通话与独立真实 Responses 并行。四窗各取一次，均读回挂断关闭。比较的是同一窗内的呈现与媒体时钟，不是[短录屏的首音偏差](approved-oc-whep-calls-20261119.md)。

**窗与缺帧。** 从首个播放器呈现回调起计 90 秒，不扣除冷起播、重订阅和断流。同一订阅按浏览器的呈现帧计数差计数，不用解码帧数或编码目标帧率。包含窗末的最长无呈现间隔依表顺序为 42.010、4.091、34.374、3.842 秒。冻结取逐秒浏览器入站统计中各视频 SSRC 最后一次可见的累计值；关闭后无统计的时间不假装成新增冻结，仍计入 FPS 分母。

**相对时钟。** 沿用[传输探针](workstation-whep-ip-20261119.md)的笔电接收统计和时基。在每个视频呈现回调用视频 RTP 和最近音频同步源 RTP 配对；每次重订阅按各自 SSRC 的工作站实发首包归零，视频除以 90、音频除以 48 得毫秒后相减。保留起播与离群点。表中最大值是窗内有效配对的最大绝对值，无帧时不插值。本次首个 mature 窗走公网 IPv6 直连，而首包探针当时只观察 Tailscale 接口。该窗有 820 个有效收端配对，无发送锚点；同一订阅内视频减音频的差值全距最大为 440 ms，加任何未知常数，绝对峰值仍至少 220 ms。后续三窗的探针在建连前已覆盖笔电实际地址。此处不把线路或并发推理列为冻结原因。

**打断与并发。** 探针仅在笔电播放器活动且收到的音轨 RMS >0.025 时点击页面的「打断回答」。实做的八次操作，下一次检测到静音或停播在 68–78 ms，350 ms 附近的采样均静音或已停播，恢复到新 Peer 播放在 692–1356 ms。这是播放器观测，不是物理扬声器时延。没有第三次有声打断的窗不算达标。每个并发窗内约每 15 秒发一个普通 Responses 挑战，按 ID GET 读回、核对完成态与对应答案；推理成功不替代媒体通过。

**复核。** 私有目录 `runtime/private-artifacts/oc-full-windows-01/{single,mixed}/{oc-mature-v1,oc-q-v1}/` 保留每次订阅的双轨 `receiver-*.webm`、逐帧 RTP 配对、逐秒接收器统计、音量与打断时间、并发读回与 `metrics.json`。12 个 WebM 分段均已实际解码音视频；分段不是拼接后假装无断流的 90 秒视频。工作站首包探针只保留发往验收笔电的 SSRC、首 RTP 时戳及观测时间，不存载荷。9443 临时形象选择已撤下，443 未变更。

复跑工具是 `evaluations.oc_whep_call --window 90`（并发窗加 `--mixed`），沿用短测凭据、真实工作站 URL、新输出目录和隔离副本登录状态。发送端另用 `oc_sender_headers.py any <观察秒数> <笔电的候选IP...>`，必须在建连前开始；收尾用 `evaluations.oc_window_review <首包JSONL> <各窗口目录...>` 合并。单独跑采集步骤不产生通过结论。
