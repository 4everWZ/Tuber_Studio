## 私聊浏览器验收

### 两张入选动漫头像的工作站诊断

号主选定 ImageGen 最初的常规动漫版和 Q 版。两张上传副本均为 640×720 PNG，普通 API 接受图像并建立准备任务，两次均在参考图准备阶段失败。另一张工作站自带的二维头像通过准备，半写实对照实际返回音视频。后来调整过五官的试稿也通过准备，但号主选用前两张。

工作站准备日志在固定版本 Ditto 的 `Source2Info.__call__` 第 139 行记录了无法解包 `_crop()` 返回值的异常。源码显示首帧人脸检测返回零个框时，`_crop()` 提前返回。调用方将所有准备异常合并为 `reference_preparation_failed`。[固定版本的参考图处理](https://github.com/antgroup/ditto-talkinghead/blob/c3e47eee2e626500017a0556b470d6d4182f85e8/core/atomic_components/source2info.py)

使用同一工作站容器和部署权重，在独立 CPU 进程比较实际送测的像素。运行时首级使用 `det_10g.onnx`，默认门槛 0.50。另一次只在诊断调用中读取低分候选。

| 参考图 | 最高候选分数 | 默认框数 | 候选框位置（640×720，xyxy） |
| --- | ---: | ---: | --- |
| 常规动漫版 | 0.14811 | 0 | 244,249,429,471，覆盖脸部 |
| Q 版 | 0.05251 | 0 | 309,71,362,132，位于头饰 |
| 服务已有的动漫示例 | 0.82662 | 1 | 255,231,389,403，覆盖脸部 |

进一步在独立进程给原图指定脸框，保持后续 106／203 点裁切及 478 点模型配置。常规动漫版框取 (210,244,452,473)，得到 478 个点。两眼中心回投到原图 (277,339)、(388,328)，嘴中心 (332,427)，在可见嘴线下方约 8 像素。Q 版框取 (170,282,476,511)，在同中心以 0.85、1.00、1.15 倍框宽高测试，三次 478 点网格均为空。对照图的网格和眼部数据正常。该测试只验证注册前半段，各分数是检测器输出。原图的运动生成、口型贴合程度及身份稳定性仍需单独验收。

现有普通 Avatar API 的裁切参数位于首级检测之后，无法给首级指定人脸框。服务端在接收参考图时还会统一缩放填充到 640×720。工坊当前使用已有 Q 版图集随播放开合口，浏览器实录下述行为。两张入选高清原件留作私有创作资产。

### 本地图集与助手播放

运行 `uv run --locked python tests/browser/run_private_call.py`。需要相邻 `omni-avatar-api` 的项目环境、本机 Node/Playwright 与 Chromium；可用 `CHROMIUM_EXECUTABLE` 指定浏览器。使用全新临时业务库、回环网关和模拟语音引擎。未调用工作站、平台发布或直播。

- 助手测试音频为 0.5 秒静音、2 秒有声、0.5 秒静音。Chromium 实际调度 PCM，fixture 将画布像素与闭口图比较，并读取浏览器输出时间戳。本次在 508 ms 观察到开口，在 2529 ms 观察到恢复闭口；这是本次采样，不是延迟指标。
- 麦克风有输入、尚无助手音频时保持闭口。暂停 AudioContext 后接收并排入 PCM，不开口、不增加播放回执；恢复后才按输出时钟驱动。完整三秒响应确认 3000 ms，被打断的一条只确认 501 ms，中途静音的一条只确认 550 ms，静音期间收到的新响应没有播放回执。
- 减少动态效果时保持静态，解除后在同一语音的有声区间可再次开口；挂断后闭口并释放麦克风和 AudioContext。模拟闭嘴图、张嘴图和备用图全部 404 时显示角色名，不妨碍关闭通话。角色测试另外验证同名或复用同一清单的其他角色不会取得大肥鱼的双帧驱动。
- 只证明浏览器这一层的音频输出时钟、画面与回执，不证明声卡或扬声器最终发出的声音，也不验证音素级唇形。
