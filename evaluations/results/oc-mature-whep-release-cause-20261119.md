# mature 通话提前释放的触发事件

本次 90 秒单通话复现了提前释放。第三次有声打断后 462 ms，产品收到了 Realtime WebSocket 的应用层 `error` 事件，通话控制器随即结束整场通话。此时第四次 WHEP 订阅正在等待 HTTP 响应。最后一帧出现在窗内 65.643 秒，余下 24.357 秒没有呈现。

| 首帧起算（秒） | 收端或服务观测 |
|---:|---|

| 64.017 → 65.037 | 第三段 Peer 保持 connected。视频累计收包 1090 → 1230、解码 333 → 358 帧、丢包 21 → 23、NACK 68 → 81，音频累计收包 653 → 703。 |

| 90 | 验收程序点击窗末挂断前，从网关读回 Avatar 会话已关闭。 |

隔离 Studio 的同会话访问日志在服务器 UTC 03:33:19.527 记录第四次 WHEP POST 201，随后在 03:33:19.582、03:33:19.745 分别记录会话和订阅 DELETE 204。四次订阅均获 201，前三段实际呈现，三份收端 WebM 均读出视频和音频帧。末次 201 足以确认服务接受了订阅，不能据此推算跨机毫秒顺序或断言第四段已播放。

**归因边界。** 本次有明确的客户端终止分支。链路在打断前有真实丢包和重传反馈，触发通话清理的直接输入是 Realtime 应用错误。该次诊断只保存了事件类型，保留的网关与引擎日志未给出对应协议错误码。前两次收到同样的三条清除事件后均恢复，单凭第三次与错误的时间邻近，无法认定取消竞态、迟到回执或引擎故障。历史两场的 42.010 秒、34.374 秒空窗仍只定位到提前释放。[历史尾段诊断](oc-mature-whep-tail-20261119.md)

**复测条件。** 桌面 Chromium 通过可信 HTTPS IP 访问工作站 9443 隔离 Studio，使用普通应用授权、原生 Realtime、已部署 Inochi worker 和 mature INP。Studio 的两个模块已与原四窗版本 `615a42d` 核对，只有该验收浏览器加载加诊断的同版模块。网关已切换逐句朗读能力。单通话无并发 Responses，沿用原 90 秒计时与有声打断入口。共呈现 1299 帧，14.43 FPS，接收器各段末次采样累计报告 27 次冻结。此窗仅用于诊断，未采发送时钟锚点，不产生新的 160 ms 验收结论。[原始四窗成绩](approved-oc-whep-windows-20261119.md)

原始事件、三份 WebM、帧、收包及结果保存在本机 `runtime/private-artifacts/oc-whep-release-cause-02/oc-mature-v1/`。临时 QA 角色选择已移除。复测后提交的采集额外保留白名单内的 Realtime 错误码，其他值归为 `other`。浏览器回归覆盖挂断前状态、WHEP 503 后继续语音，以及已知和未收录错误码的脱敏。没有据此改变挂断策略或订阅时限。
