# 工作站至 Windows 桌面的 WHEP 分片与播放缓冲

2026-11-19。活动网关通过普通应用授权返回模型列表 200，内置 `ava` 的音频源会话创建 201、释放 204。同一入口对 `regular` 和 `q` 的登记详情均返回 404，创建 `regular` 返回 400。SSH 核对活动 Avatar 使用 host 网络与控制 socket，镜像内注册表只有 `ava`，缺少 Inochi 驱动。桌面 Chromium 在明文 IP 页面可构造 PeerConnection，`navigator.mediaDevices` 为 undefined。正式 Studio 的 HTTPS 入口、角色清单、实时来源与网关/Avatar 发布由部署负责人联验。

## 工作站原画实测

在同一台工作站运行限两核、700 MiB、无 GPU 的独立进程，使用服务仓库的 Gateway、Avatar、aiortc 1.16 和已有 `regular.inp`，通过普通应用 Bearer 创建单个音频源会话。每轮从桌面发送同一段角色原声，未发起模型请求。桌面通过私网 IP 访问信令，Chromium 156.0.8078.4 接收 Opus 和 640×720 视频。全部样本的选中远端候选均为同一工作站 Tailscale IPv6 host/UDP，接口 MTU 为 1280，各场选中候选对 RTT 中位数为 181–194 ms。SSH 仅作测量控制。每轮释放该会话，退出独立实例。

发送计数在加密后调用 ICE 发送接口处采集，包含两轨及控制数据。数据报长度加 IPv6/UDP 基本头 48 字节与实际接口 MTU 比较。统计覆盖建连至关闭；浏览器计数使用首帧后至末次采样的增量。没有抓取各物理跳的 IP 分片或丢包位置。

| 发送版本与编码 | 数据报个数 | 最大 UDP 载荷 B | 加头后超 MTU | 桌面解码帧 | 浏览器冻结次数 |
|---|---:|---:|---:|---:|---:|
| 原版，指定 VP8 | 2164 | 1334 | ≥908¹ | 401 | 24 |
| 修复，指定 VP8 | 2269 | 1214 | 0 | 401 | 8 |
| 原版，指定 H.264 | 2625 | 1334 | 144 | 403 | 15 |
| 修复，指定 H.264 | 2797 | 1214 | 0 | 407 | 19 |
| 原版，浏览器默认协商 VP8 | 2402 | 1336 | 1127 | 402 | 15 |
| 修复，浏览器默认协商 VP8 | 2424 | 1216 | 0 | 403 | 16 |

¹ 首轮只保存了加 28 B 基本头后超限的数量，实际选中 IPv6，故保留下界。指定编码四轮由桌面控制进程提交浏览器的 SDP；默认协商各轮的创建、WHEP、音频提交和关闭均从桌面页面同源 fetch。每轮浏览器均解码双轨，音轨总能量增量为正。固定编码与默认协商分开比较。

服务提交 `5c65b26` 在 Avatar 创建时把 VP8、H.264 的 aiortc 分片上限从 1300 B 调为 1180 B。编码速率、分辨率、帧率和网络配置沿用原值。默认协商的修复样本中最大 IPv6/UDP 包计算值为 1264 B。H.264 和默认协商对照均显示，消除发送超限后，接收端仍会冻结。

## 相同发送版本的接收端对照

固定修复版、默认编码协商、独立冷连接及同一原声，按表中顺序只改变浏览器音、视频接收器的 `jitterBufferTarget`。平均缓冲为统计窗内 `jitterBufferDelay` 增量除以 `jitterBufferEmittedCount` 增量。视频冻结时长是浏览器的 `totalFreezesDuration` 增量。每秒快照与两端原始计数在本机私有结果目录。

| 浏览器请求 | 实测窗 s | 音频 / 视频平均缓冲 ms | 视频冻结次数 / 时长 s | 视频 NACK 增量 |
|---|---:|---:|---:|---:|
| 默认 | 16.21 | 80.1 / 71.8 | 16 / 3.727 | 124 |
| 240 ms | 16.38 | 205.1 / 220.3 | 0 / 0 | 135 |
| 恢复默认 | 16.27 | 40.3 / 57.3 | 11 / 2.599 | 115 |
| 120 ms | 16.34 | 98.0 / 116.4 | 2 / 0.423 | 115 |
| 再次 240 ms | 16.15 | 196.9 / 219.1 | 0 / 0 | 119 |

两轮 240 ms 在仍有重传请求时保持了连续播放，实际视频缓冲比默认轮多约 147–163 ms。120 ms 的单轮仍有两次冻结。结果支持将接收缓冲作为此链路冻结的影响因素；未控制公网瞬时流量。产品默认缓冲尚需结合通话延迟与打断体验决定。本次的发送修复和上述短窗不覆盖长跑稳定性、唇音时差、物理扬声器或正式 Studio 端到端通话。

桌面探针可用 `uv run --locked python -m evaluations.workstation_whep --output <本地私有文件>` 重跑。指定已部署网关、普通应用授权与 Chromium 后，默认采用浏览器原生编码和缓冲；`--buffer-ms`、`--codec` 用于对照。服务探针在 Linux 通过标准输入接收独立应用票据，读取只读挂载的注册表与 INP，给出单次服务端口和发送数据报计数。[桌面探针](../workstation_whep.py) · [服务器探针](../workstation_whep_sender.py)

本机私有目录 `runtime/releases/dafeiyu-avatar/whep-validation/workstation-ip-20261119/` 保存接入文件 `access.json`、逐秒收端统计以及每场 `*-sender.json`。正式部署前的活动网关核对和隔离媒体数据分别记录。
