# Q 原画 WHEP 发送码率对照

固定 900 kbps 将稳态总媒体出站中位从 1.883 降至 1.329 Mbps（−29%），本次收端视频累计缺包率却从 6.34% 升至 10.86%。两档都出现超过 3 秒的呈现空白，都超过 160 ms 音画偏差门槛。在这条工作站到桌面的路径上，这次实验没有找到满足原条件的稳定预算。

## 工作站实际出站

| 发送后 20–90 秒，Mbps | 自适应 | 固定 900 kbps |
|---|---:|---:|
| VP8 编码负载中位 | 1.472 | 0.904 |
| 原视频 SRTP 中位 | 1.518 | 0.933 |
| 视频重传 SRTP 中位 | 0.322 | 0.359 |
| Opus SRTP 中位 | 0.073 | 0.073 |
| 三者总和，1 秒桶 P10 / 中位 / P95 | 1.730 / 1.883 / 2.052 | 1.125 / 1.329 / 1.615 |
| 三者总和，100 ms 桶 P95 / 最大 | 2.639 / 6.743 | 1.867 / 5.870 |
| 有重传的原视频时戳占比 | 58.11% | 57.88% |

以工作站 ICE 发送成功后的 SRTP 数据报字节数计，包含重传包的头部和加密开销。IP、UDP、私网隧道封装和 RTCP 未计入。每行单独取分位；固定 900 kbps 只作用于视频编码目标，总出站仍随重传和编码突发变化。以上是实发负载，路径可用带宽未直接测量。

## 桌面呈现与音画

| 单 Peer，每组 90 秒 | 自适应 | 固定 900 kbps |
|---|---:|---:|
| 实际呈现帧数 / FPS | 2,135 / 23.72 | 2,157 / 23.97 |
| 冻结次数 / 累计秒 | 72 / 21.08 | 66 / 18.76 |
| 最长呈现空白，秒 | 3.497 | 3.424 |
| 收端视频缺包 / 已收包 | 1,015 / 14,989 | 1,386 / 11,373 |
| 收端视频 NACK 数 | 2,381 | 2,737 |
| 收端音频缺包 / 已收包 | 327 / 4,033 | 651 / 3,861 |
| 最大绝对音画偏差 / 超 160 ms 配对 | 520 ms / 169 of 1,693 | 420 ms / 281 of 1,781 |
| ICE RTT 中位，ms | 179 | 180 |
| 建会话请求 → 首个呈现帧 / 首个非静音音频，秒 | 4.36 / 4.38 | 3.38 / 3.20 |

呈现计数使用同一视频元素的 `requestVideoFrameCallback` 与 `presentedFrames` 增量。两次最长空白期间，呈现计数都只增加一帧；两组原视频末包在整个发送记录中的最大间隔分别为 163 和 174 ms。音画差对音视频各自的首发 RTP 时间戳归零，在实际呈现回调比较视频时戳和音频同步源。首音取元素正在播放时桌面音轨首次 RMS > 0.004 的采样。两次建会话的首帧和首音包含各自当次建链等待；本实验未触发产品打断，无法据此推算固定档的换轨代价。

缺包率取同一 Peer 窗末累计缺包除以已收包与缺包之和。以首帧为起点，把 20–90 秒按每 10 秒的统计增量拆开，固定档有 6/7 段视频缺包率高于自适应组对应时段。两组音频输入与音频策略相同，第二窗音频缺包也更多。每档只测一个先后窗口，足以说明本次降低实发负载没有消除收端缺包；两个窗口间的网络波动仍限制了对码率因果效应的估计。

## 同输入画质

在素材时钟 20、46、73 秒处各取 12 个候选帧，以首发视频 RTP 和 25 FPS 时钟将桌面呈现帧配回工作站编码前画面。只比较两组源 RGB 完全相同、两个浏览器均有对应时戳截图的帧，三个时间段分别有 6、3、8 帧。所有裁片按原尺寸取样。脸部覆盖双眼、嘴线与脸颊，胸前覆盖领结宝石、金纹，发饰取画面右侧蓝蝴蝶结。

每帧分别与自己的编码前原图比较。SSIM 使用 8 位灰度、11×11 高斯窗；边缘误差是在原图裁片 Sobel 梯度最高的 10% 像素上计算的平均绝对灰度差，单位为 0–255 灰阶。17 帧均来自实际呈现，数字描述可见帧的细节保真度。

| 原尺寸裁片 | SSIM 中位，自适应 / 固定 | 边缘误差中位，自适应 / 固定 | 固定档边缘误差更大的帧 |
|---|---:|---:|---:|
| 双眼、嘴线与脸颊 | 0.9805 / 0.9717 | 5.11 / 5.78 | 17/17 |
| 胸前宝石与金纹 | 0.9875 / 0.9798 | 5.00 / 6.14 | 11/17 |
| 蓝色发饰 | 0.9752 / 0.9701 | 5.28 / 5.98 | 16/17 |

17 帧中三个裁片的 SSIM 均在固定档下降。按原尺寸并排看，双眼轮廓、宝石与领结金纹仍可辨；在眼缘、脸颊细线及发饰边缘能看到颗粒和细节损失。固定档节省了实际出站带宽，代价是可测的细节损失，且本次收端仍有明显卡顿。保留正式默认，到此结束码率试验。

## 采集条件

工作站以在役 Avatar 镜像及在役网关代码启动独立测试进程，只读挂载同一份 Q 原画 Inochi 素材。桌面 Chromium 经私网 IP 和普通应用授权订阅 WHEP，两组均协商出 VP8、Opus 和 UDP，使用浏览器默认缓冲。每组单独一个 Peer，从首个呈现帧起计 90 秒。媒体时钟按同一段 4.2 秒原始话音加 2 秒静音循环取样，驱动原有渲染、编码和发送。未调用 Omni，未写入外部平台。这个媒体对照独立于带模型响应、打断和播放回执的产品验收。[既有 90 秒验收](approved-oc-whep-windows-20261119.md) · [产品首音与打断实测](oc-q-whep-buffer-crossover-20261119.md)

编码器自适应组使用镜像原值，初始 500 kbps、范围 250–1,500 kbps。固定组只在隔离进程内把 VP8 的目标和上下限设为 900 kbps，保留原重传、关键帧、分辨率、帧率和音频策略。采用 900 kbps 是因为预试后段编码负载已达约 1.5 Mbps，按六成设置一个对照档。两组按自适应、固定顺序各跑一次。

预试两次留下过视频停发。第二次捕获到发送协程在 PyAV 像素格式转换中抛出资源暂不可用，测试容器的进程数限制命中 23 次。有效对照把隔离进程的 CPU 亲和性与两核配额对齐，两组使用相同限制；未更改生产资源。未把预试的停发时间纳入对照。

两次预试私下保存在 `runtime/private-artifacts/oc-sender-budget-01/`、`oc-sender-budget-02/`。完整对照在 `runtime/private-artifacts/oc-sender-budget-03/`，其中 `summary.json` 为汇总，`quality.json` 为逐帧分区数据，`details.png` 为源图、自适应、固定档的同尺寸裁片。各组保留原浏览器统计、呈现回调、编码器和出站 RTP 观测，`acquisition/analyze.py` 可从原始记录重算结果。

两次会话均已删除，复核时工作站测试容器已退出。传回参考图期间，远端控制读取达到空闲超时，本机最后关闭管道时报错。桌面收到完整结束标记，17 张参考图解码后的 RGB 均与两组工作站原始哈希一致，已用落盘材料重算上述各项。
