# 大肥鱼视觉 SFT 与工作站回放

## 结论

视觉混合 SFT 改善了字幕问答和部分单帧事实，图文互补与证据不足判断未达到准入门槛。两种适配器的 GGUF 和对应 4x 投影器留在工作站供复核。候选尚未进入 Jetson 的 128K、刷视频端到端延迟和 Genie 浏览器播放验收。

| 工作站 native GGUF 条件 | 事实与引用通过，目标 28/32 | 正确暂缓，目标 8/8 |
| --- | ---: | ---: |
| 工作站旧 DoRA 合并 | 2/32 | 3/8 |
| 原版 MiniCPM + 完整角色卡 | 10/32 | 7/8 |
| 文本证据 SFT | 17/32 | 1/8 |
| 视觉混合 SFT | 19/32 | 1/8 |
| 视觉混合 SFT + 逐帧取材 | 19/32 | 2/8 |
| Gemma 4 E2B + 完整角色卡 | 16/32 | 8/8 |

以[固定视频题](../../cases/grounded-real-video.jsonl)和[复核记录](review.json)核对。40 题来自 12 个公开视频，包含 12 个字幕题、12 个图题、8 个图文互补题与 8 个缺证据题。同一套原生 llama.cpp JSON 约束和固定采样，工作站 CPU、4096 实开上下文。逐帧条件另有取材生成。该回放直接请求推理端点，正式浏览入口还包括取材、队列、草稿与权限。对照未写入 B 站。

## 原答中的主要问题

- **图文引用。** 视觉混合组在电鳗题说出了 POOCU 和绿色，但只引用字幕。逐帧方案在跑步题同时说出每天 3 公里与室外草地，却引用了讲以前经历的字幕，漏掉 3 公里所在的那一条。两种方案的图文互补题均未同时满足事实和引用。
- **该等的时候继续答。** 文本组把字幕起止秒数当成水深，把不相关的字幕时间当成平均心率。混合组有些能说明没看见，却仍交付公开回复。Gemma 在这批八题正确暂缓，但图文问题仍会漏掉半个问题或只引用一类来源。
- **角色与简答。** 两个新组在 [24 个 OC 场景](../../cases/grounded-oc.jsonl)中的回复较少回落到旧权重的软垫／摸鱼整段台词。它们能回答列表可变、元组不可变，也能解释单位，仍会把四颗积木答成三颗或两颗，百分比涨跌也没有算出 99。完整逐轮原答见同目录的 `oc-*.json`。
- **证据干预。** [换帧、去帧、换字幕](native-swaps.jsonl)的三条诊断中，画面顺序反转后回复顺序跟随，去帧后暂缓。字幕干预改成每日 5 公里，回复也改成 5 公里，仍漏引 100 天所在片段。

## 训练和权重身份

在 Tailscale 工作站双 3090 上各跑两轮。每组为 600 条训练、60 条验证。混合组用 120 条带真实帧的训练记录，来自 40 段授权短片场景；文本组将同帧替换成对应人工观察。训练视觉样本来自两部动画，验证动画整部留出，公开视频回放与训练分开。二次元对白由本地 Qwen3.5‑4B 改写，再由 Qwen3.5‑9B 和规则筛选。机审与项目手写标签分别记录。

| 策略 | 训练耗时 | 第二轮验证损失 | 产物 |
| --- | ---: | ---: | --- |
| 文本证据 | 161 秒 | 2.280 | [训练记录](training-text.json) · [GGUF 清单](bundle-text.json) |
| 视觉混合 | 201 秒 | 2.391 | [训练记录](training-vision.json) · [GGUF 清单](bundle-vision.json) |

正式训练产物保存在 `workstation:~/code/tuber-minicpm-grounding/sft-{text,vision}-v1`，GGUF 位于同目录下的 `gguf-{text,vision}-v1`。视觉前向和预处理均为 4x，单卡试训从中间 checkpoint 恢复到下一个训练步。旧 trainer 的整段损失、训练验证泄漏和未实际启用的偏好／融合路径仅用于诊断旧报告。

Jetson 上大肥鱼 GGUF 和 `MiniCPM5-1B-Q4_K_M.gguf` 共用 inode 55871928，头部声明 `qwen35`。另存的 `MiniCPM5-1B-Q4_K_M.gguf.base` 头部为 `llama`。Jetson 同名大肥鱼文件 SHA256 为 `689557628aae804d6cb4b04893edbae87f75ca8f5d5b48f5dc83950f3ebd6d49`，工作站旧合并文件为 `44f464ecf2b745baec09a5bb7750099ef1a121557ff0df99f821cc267a5c43e5`。

复制节点文件到工作站后，确认 321 个张量逐个相同，文件只差两个字节。节点副本的 `block_count=24`、`nextn_predict_layers=0`，工作站旧合并文件分别为 25 和 1。当前固定 llama.cpp 对节点副本拒绝加载，`qwen35.attention.recurrent_layers` 仍有 25 项。上表的旧模型行使用可加载的工作站旧合并文件，节点副本记录为加载失败。两种新导出都以固定转换器的 `--no-mtp` 生成一致的 GGUF，并在同一引擎跑完回放。

只读核查 Jetson 的 `/llm/props` 时，节点上该路径已由 `b9438-d749821db` 加载，运行时报告 `vision=false`。工作站固定评测引擎上的加载失败与这个已运行的旧引擎状态分别记录。
