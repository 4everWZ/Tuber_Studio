# 动态合并审核与真实提及验收

工作站现用 Omni 网关，隔离 SQLite，Edge 使用真实工坊页面。B 站提交、详情和评论读取使用测试传输，测试过程中真实平台写入为零。

| 路径 | 实测结果 |
| --- | --- |
| 关闭自动发布，两条原评谈同一个画面 | 工作站 Omni 一次评估生成一份稿，带两条来源和分享要点。Edge 待处理列表只有一条，素材区可分别展开两条原评。 |
| 人工审核并发布 | 确认正文后，隔离传输只收到一次动态提交。重发同一稿件的请求返回原回执。 |
| 真实提及 | Edge 中待审核动态的第三人提及打开与核验 UID 对应的测试主页。评论工作台编辑并保存第三人提及后，提交回执读回对应 UID。文字和图文动态、视频主评和楼内回复、动态评论用实际适配器核对各自载荷和回执。 |
| 原提交超时 | 隔离平台先记录写入，再丢失响应。服务重建后按原正文、提及和账号找回回执。提交总数仍为一条。 |
| 素材持续使用 | 相关历史对待发和已分享使用不同状态。同一素材的新动态可分别发送，相同载荷沿用原回执。私信测试确认动态侧只取得角色感想方向。 |

只读核对 B 站公开动态中的富文本提及和主页跳转。新功能的实际发送请求及读回使用隔离传输。 [B 站 UP 主服务中心公开样本](https://www.bilibili.com/opus/988006374080249861)
