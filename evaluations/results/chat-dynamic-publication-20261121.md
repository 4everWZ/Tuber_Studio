# 私聊动态发布验收 · 2026-11-21

使用当前工坊 Omni 网关、临时 Core 数据库和可控 B 站传输。另用 Chromium 打开同一 Web 界面，通过会话、任务和平台记录核对结果。正式 B 站账号与正式数据库未参与写入。

| 场景 | 观察结果 |
| --- | --- |
| 原话「小鱼，把之前积压的站动态都发出去」及「你发完了吗」 | 初次回放走通用后台，随后生成了无回执的「发了」。修复后的 Omni 选择 `prepare_publication` 和 `task_status`。发布工具断开时，回复明确说没发，平台调用为零。 |
| 工具连通并插入闲聊 | 一条任务先进入待确认。追问读回「等待确认，还没发」。「今天真累」直接由 Omni 接话，任务总数仍为一，确认前平台调用为零。另在空会话实测「帮我想个动态标题」和「先别发，我们只聊聊这标题」，两轮均直接接话、零任务、零平台调用。 |
| 确认、执行、主动交付 | 受控平台收到三次逐项提交，写入两条。原对话新增「已发 2 条，没发 1 条」，并附对应编号。Chromium 点击第一条「查看动态」，打开测试平台返回的对应帖子。刷新后仍是同一条结果。 |
| 已写入但响应超时 | 第一次查询读出待核对。原提交对账找回帖子和链接，平台记录只有一次提交。 |
| 确认边界 | 浏览器验证了取消、刷新后恢复待确认、过期和授权撤销。撤销后确认接口返回 409；四种状态都没有平台写入。接口回归另覆盖仅重审发生变化的草稿、登录恢复及重复确认。 |
| 计划与来信 | 回归验证已有周期计划和来信游标。指定 UID 的下一条入库私信启动一次获准的私有文本任务，完成后从原目标对话可见，其他来信没有启动该工作。 |

浏览器的帖子链接经测试路由指向受控平台。真实 Omni 回放使用隔离业务数据，平台成功、拒绝和超时由受控传输产生。
