# 当前交付计划

交付顺序为 B 站社区运营 → 直播 → 游戏实机。优先完成运营的取材、角色生成、草稿审核、授权提交和回执核对。默认部署由电脑承载业务、局域网内 Jetson 提供推理，运营默认用内建大肥鱼 OC 的自有微调模型。直播和点歌单列验收，游戏模拟与实机目标见[游戏计划](game-livestream.md)。[产品契约](../specs/tuber-studio.md)维护交付要求。

## 运营主线

## 工程收口顺序

### 推理配置与凭证边界

- 已拆分[推理诊断](../../src/tuber_studio/provider_diagnostics.py)和本机模型下载状态。自定义模型列表走 POST，已保存凭证只用于对应地址，常规 Provider 保存不变更节点配对。
- 新 Jetson 安装在已有大肥鱼微调权重时优先使用该模型。配对读取节点实际运营模型和窗口，保留已配置的 Gemma 节点。待在目标 Jetson 验收默认装配、真实生成、运营／直播回切及故障恢复。当前微调装配提供文本，画面取材需要单独配置和验证视觉后端。
- 部署探测和评估统一使用 `/llm`，语音合成继续使用 `/tts`。外部脚本迁移见[部署指南](../guides/deployment.md#电脑业务主机与独立推理节点)。独立推理服务由操作者显式绑定可信网络地址，全本地启动器默认使用回环。

### 角色输入收口

- [角色提示路由](../../src/tuber_studio/persona.py)按当前模型选择输入。大肥鱼微调路径使用短提示，通用路径使用角色卡，切换模型保留角色版本、草稿、历史与任务证据。当前分路已应用于回复、浏览、动态与续接，待用真实模型按[运营验收](#运营主线)复测。
- 素材缓存使用独立记录 ID，重读按来源内容判断变化。旧缓存引用仍可读取。评论筛选只接收最新请求结果，候选卡按实际正文刷新。

### 运营状态、模块与校验

- 推理和语音表单分别维护状态，主工作台与独立直播页共用请求客户端。权限矩阵同时涉及浏览配置和私信策略，验收保存、刷新、覆盖层、部分失败和紧停，以服务端实际状态核对权限提示。
- 设置已突出 Jetson 配对，详细地址探测与资源诊断按需展开，候选列表显示可读来源和发布结果。后续继续用桌面与窄屏核对角色切换、审核和错误恢复，保留紧停与待核对回执的可见性。
- 通用模型基类已移至[数据模型模块](../../src/tuber_studio/models.py)，运营与浏览直接使用。已移除直播互动中对构造器固定对象的重复检查，发送授权和额度在预占事务内核对。
