## 运营主线

先处理[推理配置与凭证边界](#推理配置与凭证边界)，再核验真实账号读取、渠道判断与获准写入。模型语义质量与真实账号发送分别验收，诊断如实保留；运行时依操作者明确保存的审核／自动发送权限，不另设隐式语义门槛。

### 2026-11-10 架构对齐与轻量化升级 (V2 Baseline)
- **直播交互轻量化与活动过滤**：实现 `LiveActivityFilter`，正则拦截投票、打卡与活动刷屏弹幕，仅以汇总事件入模；直播间取消分用户记忆割裂，采用共享房间滚动上下文压缩；挂载 `LiveAmbientEnvironmentTool`（时间、星期）与 `LiveBarrageContextTool`（近期弹幕流），杜绝传统 coding agent 冗长多轮工具调用。
- **战团风格双向好感系统与分层存储**：好感度范围扩展至 `[-100, +100]`，划分为宿敌(<= -60)、恶感(<= -20)、陌生(< 30)、认识(< 60)、熟悉(< 90)、特别熟悉(>= 90)。厌恶区间（-100至-10）以幽默辛辣回怼为主，极端违规直接拉黑；普通观众弹幕走内存 LRU 缓存，仅在深层互动、付费打赏或 `|好感| >= 10` 时持久化落库，杜绝数据库膨胀。
- **连续评论合并与 UID 自我认知边界**：`merge_continuous_comments` 自动合并同作者同楼连续追问为单一回应条目，原子化回写所有被合并来源，杜绝机械化重复回答；严格依据 UID 判定自身身份，第三方 Mention 自动标记为旁观对话，防止自作多情认领。
- **号主手动回复感知与协同接话 (Human Takeover Co-pilot)**：拉取历史时比对平台消息与系统回执，识别号主在网页/APP上的手动回复（`dm_operator_replies`）；自动取消处于待发状态的旧生成草稿，避免重复滥发；新来信时将号主回复作为会话上下文和接力引导注入 prompt，实现无缝接话。
- **离线停机天数感知与吐槽高光**：`check_and_record_downtime` 记录系统离线休眠时长；停工 >= 1 天开机时自动沉淀“工作站小窝简陋、睡了好久”的真实生活感吐槽高光，粉丝问及时生动回应。
- **视频帧预算扩展 (8-16帧) 与去幻觉强化**：视觉接口放宽至 8-16 帧，最大媒体字节扩展至 4MB；确立字幕优先 + 关键帧多模态互证原则，严禁通篇机械复读“本鱼/本鲸”口癖模板。
- **Intelligent UI 极简对话与 Generative UI 卡片**：开辟 `/api/chat/intelligent` 与 `chat.html`，确立号主“饲养员/制作人”专属独立作用域（`scope="operator:dafeiyu"`），不污染公开粉丝记忆；支持自然语言指令驱动动态草稿卡 (`DynamicDraftCard`)、视频巡航卡 (`VideoBrowsingCard`)、直播中控卡 (`LiveStudioHUD`)。
- **AGX Orin 64GB 硬件部署与 256K 上下文 (最新 Qwen3/Qwen3.8 选型)**：基于 32GB 显存配额，利用 4-bit 量化 + 4-bit KV Cache 支撑 256K 超长上下文。全面升级至最新代模型：离线深度运营采用 **Qwen3.8-27B**（原生 256K 上下文、Gated DeltaNet 低 KV 开销、多模态视觉）；直播即时交互采用 **Qwen3-30B-A3B MoE**（总参数 30B、激活仅 3B、解码 45-60+ tok/s）或 **Gemma 4 26B A4B MoE**，在 32GB 显存内实现极速无损调度。

## 工程收口顺序

### 推理配置与凭证边界

- 已拆分[推理诊断](../../src/tuber_studio/provider_diagnostics.py)和本机模型下载状态。自定义模型列表走 POST，已保存凭证只用于对应地址，常规 Provider 保存不变更节点配对。
- 大肥鱼 DoRA 在节点运营档提供文本和专用视觉端点。配对读取实际模型和窗口，画面取材独立验证，失败保留字幕路径。Jetson 的装配、回切及恢复步骤见[部署指南](../guides/deployment.md#电脑业务主机与独立推理节点)。
- 部署探测和评估统一使用 `/llm`，语音合成继续使用 `/tts`。外部脚本迁移见[部署指南](../guides/deployment.md#电脑业务主机与独立推理节点)。独立推理服务由操作者显式绑定可信网络地址，全本地启动器默认使用回环。

### 角色输入收口

- [角色提示路由](../../src/tuber_studio/persona.py)按实际模型选择输入。大肥鱼 DoRA 在回复、直播和动态使用共享短卡，内部判断使用身份锚，通用模型使用完整角色卡。切换保留角色版本、草稿、历史与任务证据。
- 素材缓存使用独立记录 ID，重读按来源内容判断变化。旧缓存引用仍可读取。评论筛选只接收最新请求结果，候选卡按实际正文刷新。

### 运营状态、模块与校验

- 推理和语音表单分别维护状态，主工作台与独立直播页共用请求客户端。权限矩阵同时涉及浏览配置和私信策略，验收保存、刷新、父控制启停保留渠道设置、部分失败和紧停，以服务端实际状态核对权限提示。
- 设置已突出 Jetson 配对，详细地址探测与资源诊断按需展开，候选列表显示可读来源和发布结果。后续继续用桌面与窄屏核对角色切换、审核和错误恢复，保留紧停与待核对回执的可见性。
- 通用模型基类已移至[数据模型模块](../../src/tuber_studio/models.py)，运营与浏览直接使用。已移除直播互动中对构造器固定对象的重复检查，发送授权和额度在预占事务内核对。

### 当前主线的剩余验收

[自主浏览七项验收](../specs/autonomous-browsing.md#验证边界)是当前交付条件，包含整批略过、只计一次观看、已看评论回访、每日成功回复、中断恢复、持续来信下的公平调度和超过16次调用继续。受控回归与真实账号长期运行分别记录；未拿到对应真实证据前保持待验，不降为未来扩展，也不以旧设备报告替代新权重／新链路验收。

既有DoRA回放暴露的图文事实、角色错位和复读按原记录保留。当前不继续逐条质量评分、提示微调或扩样；只针对明确可复现的结构性故障增加必要回归。

[2026-11-07真实自主运营](../../evaluations/results/autonomous-operations-20261107.md)原轮最终仍为paused，budget.model_calls为439、13次观看无重复，保留3个网络检查点，不能标为整批完成。原轮公开与私信提交有回执，原轮公开展示尚未全部独立确认；模型仍出现偏题、复读、对象错位和缺乏来源支持的私信选择。新权重资源准入和真实采帧链可执行，单帧语义误判仍未通过；定向纠错重协议0/1、直接正文0/3、压缩上下文0/3。后续三条明确授权的人工operator_revision已通过真实UI各发布一次并回读可见，不算模型通过。具体错事按公开同楼来源记忆，允许自然meme解构，不要求反复道歉；当前权重自主运营质量及原轮收尾继续待验。
