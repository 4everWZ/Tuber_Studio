## 独立 Omni 部署

两套 Compose 已落地。独立基础设施仓库维护 MiniCPM-o 4.5、共享推理网关和 MediaMTX。业务仓库维护 Core 与 GIF Avatar 媒体桥。AGX 已通过两栈启动及模拟推理下的节目与 Agent 后台共驻。旧 llama.cpp 已停止，业务切换等待原生 Chat Completions 和 Realtime 的实机准入。 [业务 Compose](../../deploy/omni/README.md) · [部署验收](../../evaluations/results/omni-deployment-20261116.md) · [部署契约](../specs/foundation/omni-deployment.md)

1. 当前 AGX 为 JetPack 6／R36.4.7。官方 CUDA 12.9 Tegra 库、重编的 PyTorch 2.13.0 SM 8.7 wheel 和 CPU TorchCodec 已通过容器预检。MiniCPM-o 三阶段、文字与双工语音单路已通，继续核对图像与音频输入、OBS 停播及共驻资源。CUDA 13 的固定镜像留给适配的系统，首测用原精度。
2. 在可信 HTTPS 的测试工作台接输入、输出及 Avatar，再接 OBS。先把现有形象接入确认时钟和播放回执，然后验证 Ditto 及备选驱动。试运行 Remotion 离线产物任务与通用工具，测和节目共驻。
3. 通过[实机准入](../specs/foundation/omni-deployment.md#实机准入与切换)后按能力切换 AGX 生产模型，验旧入口和回退。业务迁到 AGX 时另做唯一写入者迁移和 Laptop 关机续跑验证，可独立回退业务与模型。

- [ ] **Responses 协议待办**。当前部署用 Chat Completions 和 Realtime。后续评估新模型时，若它在现有推理底座的目标版本与部署模式下原生提供 `POST /v1/responses`，再在现有 Provider 层接入并按端点能力选用。用实际回包验证普通响应、流式输出、工具调用与结果回传、取消和错误。Realtime 继续承载双工语音。

旧合成评论协议、题集和专用测试已从主线退役。业务接口回归使用现行生成与提交链路，训练编译、原始语料和冻结持出继续用于现行 9B。 [训练与复现](../../tools/training/README.md)

运营和直播默认使用同一份 Qwen3.5-9B 微调发布，原生 262,144 上下文、Q4 K/V、思考开启。现行运营评估使用实跑留存的 220 条模型候选和 159 条成功回执，155 条发布正文与候选一致。号主反馈大部分满意，逐条语义待明确标注。独立配对评估中，微调版通用题为 93/120，同基座为 100/120，40 个 OC 场景胜 23 个。旧合成运营分数保留在历史评估中。 [实跑模型评估](../../evaluations/results/operations-feedback-20261112.md) · [配对评估](../../evaluations/results/dafeiyu-clean-9b-20261111.md)

- 下一轮模型发布使用 160 条冻结持出。120 条通用题分六类，相对同基座整体最多多错 3 条、单类最多多错 2 条。40 个 OC 场景盲评至少 24 个优于现行角色模型。发送路径另验目标、回执与私域隔离。 [冻结清单](../../evaluations/cases/dafeiyu-release-holdout-v1.manifest.json)
- 只有独立持出案例显示稳定缺口时，再决定补充角色场景或更换底座。训练先按会话与同源变体分组切分，再对训练分片加权。继续保留原始语料和固定基座对照。 [9B 训练指南](../../tools/training/README.md)
- 模型或运行参数更换后，分别验真实窗口、图像输入、解码速度和共驻时的整机内存及换页。外部 LLM／TTS 由使用者核对实际端点、模型、声音、容量和服务用量。 [推理与声音规范](../specs/foundation/models-and-audio.md)
