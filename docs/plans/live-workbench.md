# 直播工作台与双模式点歌

目标：落实[直播规范](../specs/live-and-media.md)中的独立直播工作台、可拖拽场景、直接播放／当前角色音色演唱，以及复用素材的唱歌口型。先用Mock验证，不以真实平台接入为原型前置；真实平台与OBS仍各自验收。本计划维护未完成工作，行为和验收以规范为准。

## 当前实现边界

- `src/tuber_studio/web/index.html`的直播区是Mock事件调试与任务控制，尚无场景编排工作台；`overlay.html`／`overlay.js`提供固定布局角色、字幕与单一播放者ACK。
- `runtime.py`的`submit`明确过滤`song`事件并注明后续适配；尚无可播放的音乐队列、歌词时间轴或演唱流程，不能将事件入口视为已实现点歌。
- `assets/whale/manifest.json`、六套GIF及`third_party/whale-avatar/UPSTREAM.md`记录现有Q版形象和上游图集。`talking.gif`是招呼动作；播放器现有整体浮动效果不等于嘴部动画。先复用这套形象及可用源帧。
- 当前角色`whale`绑定`yaoyao_sovits_v2`，说话的Genie／Mini128K共驻、百句合成及Mock浏览器播放已有[验收证据](../../evaluations/results/yaoyao-v2-voice-20261030.json)。这不证明演唱能力、整曲资源可行性、工作台或OBS本体已交付。

工作台布局、曲库／点歌队列、演唱Provider和overlay渲染分别维护职责，复用现有角色／声音／任务控制。媒体的准备／生成状态与实际播放事实分开；不为新界面复制一套运行时或模型进程。

## 实施前需收敛的取舍

- 演唱技术路径尚未选择：先核实当前声音能否用于候选演唱后端及所需引导输入；若需要新模型／声音训练、用原唱变声代替直接合成，或只能使用另一声线，提交试听与成本后再确认。
- 整曲实时性和8GB设备资源尚未验证：先测瓶颈。若需限制为预生成／缓存歌曲、使用外部服务或改变当前资源驻留，须说明对点歌等待、声音、成本与部署的影响并确认；不得擅自缩小为仅直接播放。
- 截图作为构图与组件参考，现有Q版大肥鱼为角色基线；具体外部美术／嘴型尚未选定。素材来源、许可和风格适配确认后，才决定确需生成的局部。

这些取舍不阻塞规范对齐和现有素材盘点；在证据足够且用户确认必要取舍前，不宣称演唱后端或最终素材方案已经确定。
