# 游戏直播后续阶段实施计划

状态：排队中的后续工作，尚未开始游戏实现或迁移。目标是在拟议双机职责下完成两款游戏的最小闭环、人工控制、OBS与数据恢复验收；先建立可测功能，再优化游戏负载。

合同入口为[游戏直播草案](../specs/game-livestream.md)与[跨主机运行草案](../specs/distributed-runtime.md)。原始输入仍为[原路径下实际v0.2 SRS](../../tmp/Tuber_Studio_Game_Livestream_SRS_v0.1.md)，不改写或另存全文；输入中的参考命令不构成本轮执行授权。现有[运营模型计划](operations-vlm.md)继续独立拥有当前运营推理优化，本计划不改其顺序、配置或证据结论。

## 阶段与退出条件

| 阶段 | 工作与下一步 | 退出证据 |
| --- | --- | --- |
| G0 设计准备 | 核对电脑OS／硬件、两款游戏版本、适配器许可证与兼容、状态／截图／取消／暂停能力；确定协议、进程及可选安装边界。 | 能力差异和未支持项明确，独立存档与本地OBS测试场景可复现。 |
| G1 连接与数据基础 | 模拟适配器验证会话／动作生命周期，再做真实双机连接；盘点既有业务数据，设计唯一写入者及隔离迁移／恢复演练。 | 重复动作ID不重做；断线与未知结果先核对；正常LAN控制确认目标1s内，实际停止另记；演练不覆盖生产。 |
| G2 星露谷首闭环 | 基于支持接口完成游戏日规划、移动、农活、背包、结果与摘要，接入实际语音／弹幕与OBS。 | 独立存档完整游戏日；至少60分钟连续实测，人工接管、无进展和延迟／资源分布有记录。 |
| G3 互动与持续性 | 建议、投票、挑战、跨日目标和经历；验证重启续接、读档事实、用户身份及公开／私域隔离。 | 建议与投票各至少一次改变目标；语音和动作并行、紧急控制与队列有界。 |
| G4 植物大战僵尸 | 在声明版本完成识别、策略、执行、胜负及下一步；分别测实时与可支持的暂停规划。 | 选定关卡闭环和至少60分钟连续实测，不能借用星露谷时长或暂停结果。 |
| G5 联合验收与优化 | 完成两游戏、切换／退出、双机恢复、缓存及OBS验收；随后按同样本测量逐项或明确组合优化。 | AT逐项证据可查；未测项保留；质量与可重复性能共同决定采用，重大取舍先确认。 |

购物／NPC／钓鱼／战斗等扩展以及C/S客户端保留在草案后续范围，首轮通过不冒称已交付这些能力。首轮目标完成后同步合同和证据，再按实际后续范围安排工作，不以无限扩展维持本计划常开。

## 基准与采用门槛

功能闭环与性能实验分别留证据，当前尚无本计划的两游戏连续实测、迁移收益或量化收益。

固定中文OC、多轮工具、图片／字幕、游戏局面、语音并发和点歌样本。拆分采集、媒体处理、上下文、网络、队列、视觉编码、prefill、decode、工具和首播，另报端到端，避免重叠相加。模型记录输入／输出tokens、prefill／decode速率、首个可见输出与完成；可观测思考和正文分开，未暴露阶段标为不可测。

两机记录常驻／峰值／可用内存、交换、CPU／GPU、温度、频率、带宽；共享内存统计不相加。固定模型／引擎版本、量化、上下文、KV、图片、思考／输出预算、功耗、缓存和并发，冷启动／预热分别重复，报告n、p50、p95、最大值、离散与失败率；批吞吐不代替直播响应期限。

先排重复执行与输入包装等已知热点，再按明确条件测batch／ubatch、offload、线程、注意力、KV／前缀复用；改窗口、图片或预算时单列质量影响，重大取舍先确认。projector四位仅作为候选：先核结构、转换支持、实际量化张量范围、算子与执行位置，再测加载精度、视觉时间、额外转换和CPU回退。相同样本与当前可用精度对照，必要时含8位／混合精度；不支持或质量不合格就保原方案，不以文件更小、能加载或单次吐字宣布通过。

跨轮复用记录实际依赖与失效条件；角色、账号、模型、图片或会话变化时按对应依赖失效，避免串上下文。独立I/O可有界并行，推理、TTS和工具保留可观测调度与背压，不能仅增加并发后忽略内存争用和首字延迟。

采用需关键功能与质量无明显退步，并有可重复目标收益；通关／规划、事实引用、视觉、角色表现及错误率分别评审。保留必要回归和可复用benchmark，单次探针放tmp，未解决的空输出／重复／预算耗尽保留失败，先查请求、模板、参数与上游再比较替代模型。
