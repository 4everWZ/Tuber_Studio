# 私信运营契约

正文篇幅与独立运营生成额度沿用[运营正文契约](comment-operations.md)，不采用直播台词120字或角色style长度作为私信硬限；渠道判断的channel_max_tokens只控制路由小结构，和正文额度分别计量。

渠道及正文生成的具体反馈、检查点、平台拒绝修订与未知发送核对沿[运营任务继续契约](operation-continuations.md)；原收件人、来源与私域边界继续由本规范维护。

私信是独立工作区，与评论、动态共用账号配置、角色版本和唯一模型生成锁；不通过直播队列或TTS输出。真实平台能力与发送权限须另做账号验收，隔离传输测试不代表真实私信已经发送。

| ID | 要求 |
| --- | --- |
| DM-01 | MUST 默认关闭，自动读取和自动发送分别默认关闭；手工生成先进入审核。收件人只可来自对方真实来信，或模型选择转私信的当前评论作者，不提供任意目标批量发送。 |
| DM-02 | MUST 模型根据当前公开评论楼上下文选择comment／direct_message，理由为有限分类；沿用已配置的模型思考模式。渠道判断输出额度（含思考）独立配置，默认2048 tokens，可设256–65536；正常回复及摘要额度不变。生成失败、结构化结果不完整或渠道与理由矛盾时显示错误，保留来源，不擅自换渠道或声称发送。 |
| DM-03 | MUST 同一(account_id, platform, platform_user_id, OC ID)跨评论与私信共享关系数值；不按昵称合并，不跨OC或账号串用。评论楼与私信短期上下文分离，私信原文和角色在私信中的故事不进入公开评论或动态素材池。 |
| DM-04 | MUST 发送有来源、角色不可变版本、审核／自动模式、文本与平台消息ID回执。每次只提交一次写请求，超时、取消、无有效消息ID及发送中重启标记结果不确定，禁止自动重发或覆盖。 |
| DM-05 | MUST 自动模式只为启用后收到的近期新来信准备回复，不追发历史；同一来源对同一OC只生成一次。评论转私信沿用私信发送策略；手工选中生成仍待审核。 |
| DM-06 | MUST 有界生成队列、每小时／滚动24小时额度和同用户冷却；失败及不确定尝试计入额度。停止自动收发阻止后续读取／发送，已经提交的HTTP以回执为准。直播待播／生成／播放优先，私信不另驻留模型。 |

当前平台适配接账号范围内的文本或单图片私信，图片来源与选择由[表情包规范](memes.md)维护。图片先上传准备，最终只发一条type=2消息，不自动补发原文字；只有最终提交才预约防重复意图。上传明确失败保留草稿可人工重试，最终提交结果不确定仍不可重发。仅使用固定HTTPS地址和现有登录凭证；不自动解决平台验证，不因可读推断可写。收信先确认登录UID，只导入属于该账号、来自该会话用户的正常文本；忽略本人、群组、撤回、系统或其他收件人的消息，不调用已读接口。最近20个会话、每会话30条是本轮读取上界，不声称已读完整历史。

评论转私信后，公开草稿只显示移交标记，不能当作公开回复审核或发布。私信草稿保留来源评论ID和用户身份；在独立私信页审核、修改、拒绝、复制、发送或重试未发送的生成失败。模型没有修改收件人、关系值或直接调用发送工具的权限。更换账号后，旧来信不能被新账号代为回复。

关系基线为好感度20，范围0–100；按有效、实际处理的来源消息最多增加1，同源幂等、相同内容24小时不重复增加、有效增量冷却60秒、滚动24小时最多增加10。阶段依次为0–29陌生、30–59认识、60–89熟悉、90–100特别熟悉。评论和私信共用同一条关系及增量账本，模型不能接受观众指定数值；匿名用户不建立长期关系。已有确认字段保留，私信原文不作为共享关系字段。

私信收件、发送草稿／回执与关系账本持久保存在本地数据库，与媒体缓存分开。模型活动窗口及来源检索索引沿用对话留存；原始私信和发送审计不因媒体清理或窗口到期被删除。这与原始评论、草稿和回执的独立保留方式一致。

收件／草稿身份、关系和私密scope包含当前已核验账号。同一账号内公私渠道共享关系；切账号不展示或继承旧账号私密窗口。旧无账号记录保留在旧范围，不自动认领给新账号。视频移交持有公开证据引用；父轮取消会收齐其未提交生成，压缩、修复和思考tokens仍计入父预算。直接私信仅在正文含受支持视频标识或延续该用户已关联话题时重读视频材料。

验收覆盖：来信→草稿→审核→单次发送回执；公开讨论／私聊判断；任意收件人字段拒绝；历史不追发；停止、取消和重启不重发；同昵称不同UID／不同OC隔离，同UID跨渠道共享数值；私信不进入公开素材；无凭证、平台拒绝和不确定结果可见。真实模型的渠道选择与真实平台的发送能力分别验收。

缓存及收发路径证据见[缓存与私信验收](../../evaluations/results/cache-and-private-messages-20261031.json)。操作者随后选择保留思考并提高渠道预算，见[渠道额度对照](../../evaluations/results/channel-thinking-budget-20261031.json)：2048及4096额度下各五个合成输入均完整输出，但每组只有三个同时满足预期渠道与一致性校验；较高额度未证明解决误判。渠道质量仍未完整验收，不能将格式完整当作判断可靠。真实平台账号仍待验收，见[外部服务与账号计划](../plans/p0-runtime.md)。
