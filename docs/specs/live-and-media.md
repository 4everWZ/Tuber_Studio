# 直播、演出与音乐契约

本规范维护直播事件、调度、工作台与演出场景、点歌及音画同步的目标契约。资源条件和持续运行边界由[资源规范](models-and-audio.md)维护，实现进度与下一步分别见[外部服务与账号验收](../plans/p0-runtime.md)和[直播工作台计划](../plans/live-workbench.md)。模板仍默认text且关闭直播，设备须由Operator显式启用Mock／live，导航不自动切换；真实B站／抖音直播接入仍后置。本地Mock音画闭环不代表授权Adapter、完整调度策略、点歌／演唱、工作台场景编辑或OBS本体已验收。以下标签保留原优先级，不表示全部条目已完成。

### 不变式

- 人工停止／静音／接管先于自动语音；新礼物默认不打断已开始音频，人工或明确紧急事件除外。
- 每个语音事件只有一个有效状态，WS重连／重启不重放旧礼物或已完成任务。
- 礼物和普通消息同样受内容约束，付费不增加工具权限。
- 默认单LLM／单TTS、有限队列，直播优先于离线评论；模型驻留与生成按资源规范控制。

P1可调建议为普通弹幕60%／礼物25%／主动话题15%，以实际音频时长记账；空队列可借余量，结合aging与同用户冷却防饿死。该比例不是未经测试的公平性结论。优先级依次为人工控制、时效反馈／礼物、选中普通互动、冷场／预录、离线分析／维护。

## 事件与播放状态

PlatformConnector.events() → AsyncIterator[NormalizedEvent]。事件至少包含 event_id／platform／room_id／session_id／type／platform_user_id／display_name／timestamp／text／metadata，时间含时区。平台无稳定ID时生成注明来源的组合去重键，不假设绝对唯一；昵称不决定身份。Scheduler.submit(event) → JobID 不承诺每条消息获得Speech Slot。

会话目标：stopped → connecting → ready → live ↔ paused → stopping → stopped，故障可为degraded／error。paused可收录但不启动后续生成／播放；stopping停新任务、取消可取消生成；degraded可见回退音效／静音／人工接管。

任务语义：received → normalized → filtered/queued → selected → generating → synthesizing → ready_to_play → playing → completed，另有expired／skipped／failed／cancelled，记录状态与时间。仅completed算回应。静音、跳过、停止、切角色／版本取消当前并通知停音，清队列不把任务记播完。

OverlayBus.emit(audio,animation,subtitle) → Ack，以相同播放ID／nonce关联媒体。单一播放者持当前nonce先started再ended才completed；缺播放器、错误、超时、断线、取消、重启不算完成也不重播。第二页待机，断线立即停音／清字幕，忽略过期确认。

持久语义包括events的平台事件键、场次、用户、类型、原始数据、状态；response_jobs的源事件集合、角色版本、状态、台词、情绪、音频引用及耗时。去重与保留期配合，重启取消遗留活动任务并保留完成事实。

## 点歌的两种模式

| 模式 | 行为与输入边界 |
| --- | --- |
| 直接播放 | 播放有相应用途许可的现成歌曲文件／已获准媒体源；无需调用LLM或TTS重新生成歌曲，标明实际演唱者／音源，不冒称大肥鱼合成演唱。 |
| 角色音色演唱（预留接口） | 当前不挂载演唱音频模型，不要求说话TTS唱歌；请求须明确返回模型未接入。后续通过独立Provider挂载能唱歌的模型，沿用当前角色声音身份与播放契约。具体能力由[声音规范](models-and-audio.md#说话与演唱能力)约束；真实模型仍须另做音质与资源验收。 |

Operator在WebUI维护曲库、音乐音量、队列限额／同歌去重／同用户冷却，默认直接播放；未挂载演唱模型时该模式禁用，也不能保存为默认。后续挂载后可在默认设置与单次点歌选择演唱模式。默认模式只作用于新确认项，已入队项保留原模式和声音身份，改变时须显式操作，不在播放中偷换。未来模型配置和资源切换须沿用资源规范，不借接口预留擅自换声或切云端。

点歌流程：识别请求 → 检索候选 → 同名歧义确认 → 检查来源／用途许可与模式能力 → 有界入队 → 准备媒体或生成演唱 → ready → 实际播放。队列显示歌曲、点歌者、模式、准备进度／失败原因，支持跳过、移除和人工调整顺序。缺引导素材、后端不支持、资源不足或超时须明确失败／不可用，不能静默改为直接播放、换声、读歌词或调用外部服务；Operator可显式改模式重新准备。

生成和下载都在有界任务中进行，不阻塞停止／静音；整曲生成须有独立可取消的时限和进度，不能无限延长短句TTS超时来掩盖瓶颈。歌曲／歌词／伴奏、声音模型与生成结果分别检查用途许可。网易云等检索结果仅供候选与元数据，不因此成为获准音频源；模型和观众只可提出歌曲文本或合法曲库ID，不能提交任意URL／路径用于下载或执行。

可选在线点歌复用工作台的独立开关与现有队列。指定NeteaseMusic-API仅供元数据／歌词，指定UNM仅通过波点／咪咕库接口解析；不调用元数据API内的第二解析器或UNM的远端兜底。来源优先时完全移除`SELECT_MAX_BR`，FLAC请求与实际流格式分开记录。保留原始FLAC／MP3及正确媒体类型，不逐首转码。默认320000 bit/s回退、禁止更低码率、音乐池最高15 GiB（新安装默认15 GiB，兼容已有缓存限额）、单曲96 MiB／600秒、下载90秒；当前／下一首及本地曲库引用的缓存不能被淘汰。地址过期后重新解析，任务不持久保存签名URL。请求缓存命中仍须验证文件身份和媒体信息。

在线点歌明确区分broadcast与local_test用途，已有配置默认broadcast并继续要求直播用途确认。本机／OBS技术测试须由Operator显式选择并记录说明，只接受工作台／Mock点歌，不据此填写直播或商业授权；来自真实平台的点歌仍须使用已确认的直播用途。部署时选择online环境安装Node及固定依赖，并持久保存环境选择，普通程序更新不得丢失已安装的组件；依赖不变时复用基础和在线扩展镜像。

在线搜索用规则识别`点歌 歌名`，唯一精确候选入队，同名／歌手／版本歧义返回候选。序号选择仅属于原平台、房间和稳定用户ID，候选120秒过期；主播可确认。标题、所有歌手、版本标记必须一致，有候选时长时先检查；下载后实际时长差不得超过3秒。主LRC缺失时尝试备用歌词接口，仍缺失明确显示未同步。组件未安装、缺咪咕凭证、解析／下载／质量校验失败与进程退出均显示具体状态，可人工重启；不自动调用其他源、降低被禁止的音质或触发演唱。

播放延续单一播放者、播放ID／nonce和started／ended确认契约：准备好、入队、合成结束都不算播完。歌词与进度以播放器实际currentTime为准，有时间轴则逐行同步，无时间轴则显示静态歌词并注明未同步，不伪造逐字高亮。歌曲播放暂停冻结当前进度／歌词并闭嘴，恢复从同一有效播放位置继续；该控制与阻止后续任务启动的会话暂停分别展示，不混用。结束、跳过、停止、断线或失去播放权后停止关联音轨与动画，不重播已取消歌曲。只有收到ended且此前有效started的完整播放才计完成，跳过和取消分别记录。

歌曲人声／伴奏属于同一播放任务，统一暂停／停止和音量控制；讲话、礼物音效和歌曲按配置共享音频预算，限制叠加音源。歌曲与互动语音须有明确仲裁，默认礼物不直接打断已开始歌曲；需要穿插短句时按配置duck或暂停，不能两条未协调的人声同时播出。管理区试听与预览不得向正式overlay提交播放任务或伪造ACK。

## 直播工作台与场景编排

直播工作台是独立任务入口，包含场景预览／编排、事件与点歌队列、播放及开停播控制和状态区；与评论运营各自组织流程。仍复用角色、声音、素材和设置，不另建一套身份或模型实例。进入页面、编辑布局与打开预览不自动启用直播或改变资源模式。

参考用户提供的海底直播间截图拆分视觉元素，默认角色居中偏左、歌曲与队列在侧边、歌词靠近角色下方、弹幕及礼物信息在底部或空余区；这是可调整的初始构图，不把整张截图当不可拆背景。整体可爱、圆润、蓝色海底／鲸鱼主题，使用现有Q版大肥鱼，避免装饰遮住歌曲、歌词和互动文字。

| 场景组件 | 内容与交互边界 |
| --- | --- |
| 背景与装饰 | 海底／房间背景、灯光、唱片、贝壳、气泡等独立装饰层；支持场景或透明输出。 |
| 角色与表演道具 | 现有Q版形象、表情、唱歌嘴部动画，以及可独立摆放的麦克风等道具。 |
| 当前歌曲 | 歌名、实际音源／演唱模式、点歌者、封面、播放进度和状态。 |
| 歌词／说话字幕 | 歌词与互动台词可分开摆放，随对应播放任务更新，避免叠字。 |
| 点歌队列 | 待播歌曲、点歌者、模式与准备状态；空队列显示占位，不捏造点歌。 |
| 弹幕互动 | 有界滚动展示消息与昵称；画面展示不表示每条都已生成回复。 |
| 礼物与陪伴 | 礼物提示／本场心意、感谢效果、陪伴信息；来访／点赞／关注等可选指标仅展示实际可用数据，缺数据用空态。 |
| 标题与状态 | 直播间标题、活动文案、当前演出状态及必要AI标识；平台本身的关注／点赞按钮不照搬为本地控件。 |

角色、信息面板、道具和装饰都应独立定位；背景可锁定。编辑模式支持鼠标拖拽、缩放、图层顺序、显隐和锁定，并提供选中组件的数值位置／尺寸调整，便于精确布置。保存布局至少覆盖画布尺寸、组件ID／类型、位置、尺寸、层级、可见性、锁定与素材引用，刷新／重开可恢复；提供默认布局和重置确认／撤销，避免误操作丢失布局。以明确画布坐标保存并在预览／OBS按比例映射，不依赖管理页窗口像素；初始以16:9桌面横屏为基准，预留画布尺寸调整。

WebUI承担编辑与配置，`/overlay`承担只读演出输出。场景布局与播放会话分离；拖拽、保存和切换预览不重启当前音频或产生额外播放者。工作台预览默认静音，只镜像播放状态／时钟；正式音频仍由获得播放权的单一overlay输出，第二个输出页继续待机。OBS画面不出现拖拽手柄、管理令牌、配置面板、后台日志或启停按钮。

## 素材复用与唱歌动画

素材优先级：仓库现有六套GIF与其上游图集／分层源 → 可用于目标场景的现成图片、口型帧和动画 → 基于既有素材裁切、拆层和简单Web动画 → 仍有缺口时才生成所需局部图片／动画。不先整套重画形象、背景与动作。优先寻找与当前造型兼容的张嘴／闭嘴、眨眼、唱歌／麦克风动作；保持发色、服装、比例、鲸尾和透明边缘一致。来源／许可不清的候选保留待核实状态，不直接当作已获准素材分发。

现有`talking.gif`是招呼动作，不表示口型同步。唱歌至少具有随实际可听人声变化的开／合嘴，优先使用已有嘴型或可拆层帧，不强制Live2D／3D或精确音素级嘴型。口型采用人声音轨包络或与成品对应的人声活动时间轴；前奏／间奏只有伴奏时闭嘴，不能仅靠队列状态或整曲循环张嘴。直接播放也可驱动角色做跟唱视觉，但歌曲卡保留真实音源与模式标识。

暂停、静音、失去播放权、结束、跳过、取消时停止口型并回待机。嘴型／动画资产缺失或加载失败时回退现有完整角色／说话GIF，音频仍可播，工作台明确提示视觉降级，该情况不能算唱歌口型验收通过。新资产继续按角色manifest引用，附来源链接、原许可、修改方式和版本；沿用[上游素材边界](../../third_party/whale-avatar/ASSET_LICENSE.md)，参考截图与社区角色参考不自动获得额外再分发权。
