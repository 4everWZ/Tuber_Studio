# 上下文与压缩契约

## 128K是真实模型容量

实际使用的模型总上下文至少131072 tokens，可在模型原生上限与设备实测允许时调大。配置值、服务实际窗口和原生上限分别记录；真实Provider每次生成前核查llama.cpp `/props` 的实际 `n_ctx`。低于128K、服务容量小于配置、配置超过已确认原生上限均报错，不能把外部历史库／摘要或3K窗口标成128K。

初始MiniCPM5-1B原生上限131072；不为扩大数字默认强扩RoPE。设备初始profile使用单slot、q8 KV、FlashAttention、`--fit off`防止自动缩窗。更长模型替换后仍用同一上下文管理接口。

真实tokenizer和chat template通过 `/apply-template`＋`/tokenize` 计量完整输入；输出预留包括在总窗口内。沿用Codex默认：自动压缩阈值为 `min(配置阈值, floor(窗口×90%))`，有效硬边界为窗口95%；128K时对应117964／124518。该预留不是把模型窗口降成124K。支持total和body_after_prefix阈值计数，后者仍受总窗口硬边界约束。

## 分层与持久化

核心角色／系统规则、模式与权限、按需Lore／经确认关系、活动历史、当前不可信输入、输出约束各自组装。固定核心不被预算逻辑截断，不静默整块丢弃历史。活动历史持续积累至阈值，以模型摘要压缩，不固定只保留最近几轮。

直播按会话＋角色ID＋版本隔离；评论按视频＋角色ID＋版本隔离，模式不互相污染。只有真正completed的语音写入直播上下文；评论草稿写入独立运营上下文，不能冒称已经发布。SQLite活动窗口保存完整逻辑消息、来源ID、截断完整性、压缩代数与错误，重启后可恢复。

## Codex公开本地算法对齐

参考固定为 [openai/codex f021168bde5357009fceb0477835ad90bd54c17c](https://github.com/openai/codex/tree/f021168bde5357009fceb0477835ad90bd54c17c)。保留Apache-2.0许可证和归属。`compaction.py`维护算法，`context.py`维护项目集成；不能用本地截断／关键词摘要替代以下核心。

| 上游归属 | 保留行为 | 本地适配边界 |
| --- | --- | --- |
| `core/src/compact.rs:run_compact_task_inner_impl` | 克隆原历史，追加压缩提示，让模型生成完整摘要；成功才重建与安装历史 | 使用本地llama.cpp完整HTTP响应及finish_reason；没有远端Responses会话 |
| 同上重试循环 | 超窗逐项移除工作副本最旧项，重置重试；中断／不完整输出立即失败；瞬态传输有界退避 | 固定角色规则在独立prefix中保留；不对平台写请求重试 |
| `collect_annotated_user_messages` | 保留真实用户文本，排除旧摘要和系统上下文 | 本项目只接受文本消息，保留来源事件／评论ID及完整性标记；无工具／多媒体消息可重建 |
| `build_compacted_history_with_limit` | 以20000预算从新到旧选择用户消息，最旧一条不足时保留头尾，最后恢复原顺序；追加summary prefix＋模型摘要 | 沿用上游UTF-8字节数÷4向上取整的保留预算，不把它当真实模型tokenizer |
| `utils/string/src/truncate.rs` | UTF-8边界的对半头尾截断，`…N tokens truncated…`标记在保留内容预算外；来源标记不完整 | Python字节切片与UTF-8边界等价实现 |
| `insert_initial_context_before_last_real_user_or_summary` | 在最后真实用户前重注入规范上下文；没有真实用户则在摘要前，均无则追加 | 核心prefix与当前Lore／权限在相同渲染边界重建，逻辑窗口不重复存配置副本 |
| `protocol/src/openai_models.rs` | 90%触发与95%有效边界，压缩后重算token | 用本地模型真实token计数；手动与自动压缩共用算法 |

本项目没有Codex工具调用、多模态消息、世界状态／插件Hook或OpenAI远端加密压缩端点；这些宿主对象不作为删减文本压缩算法的理由。OpenAI服务端加密压缩的内部模型算法不公开，不能声称其本地等价实现。离线固定台词Provider也不能冒称有真实128K或模型摘要能力。

## 失败与验收

模型没有完整stop、摘要为空、传输中断、取消、重建后仍超窗或持久化失败时，不安装半份摘要；原逻辑历史保留，前端显示失败。当前输入／核心自身过大且无可压缩历史时明确报错。手动压缩与自动阈值压缩行为相同。

验收分别覆盖：服务实际128K／原生元数据、接近窗口上限的真实token输入；上游20K选取及UTF-8头尾边界；旧摘要排除／上下文插入；超窗恢复／有界重试；失败原历史不变；SQLite重启与角色／模式隔离；真实本地模型摘要及后续继续生成。长文本可执行不等于关键信息召回质量、压缩语义保持或实时性能达标，后者需有针对性评估。
