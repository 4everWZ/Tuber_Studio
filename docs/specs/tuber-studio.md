# Tuber Studio 产品与系统契约

本规范维护产品范围、共同约束与验收目标，各技术规范维护所属细节。它们描述系统应达到的行为，不是已实现功能清单。初始输入保留在 tmp/GIFTuber_Studio_SRS_v0.1.md，不维护正式原文副本。

## 范围与交付顺序

本地 AI 角色运行时供账号运营与直播共用，以任务导向、高信息密度的 WebUI 配置和监控。非直播工作台覆盖 B 站评论浏览、导入、分类、角色草稿、审核／复制，以及显式开启的自动浏览／回复；LLM和TTS各有可配置的兼容API接口。当前恢复 MiniCPM5-2B／128K 与 Genie TTS 的本地直播共驻开发，首先优化整机RAM，同时保留至少90%音质与生成速度；资源准入和持续运行仍须实测，真实B站／抖音直播接入后置。已有Mock／音画／overlay代码与实验保留，未准入时默认不启用直播。当前MiniCPM5-2B为文本模型，多模态仅保留本地／API接口，不另行扩展视觉模型。

初始内容采用 DeepSeek Q 版「大肥鱼／鲸鱼娘」，明确虚构 AI 同人角色、非官方账号；后续可替换相似内容，也可配置新 OC。角色、模型、声音、平台和素材可替换，不把初始形象写死在业务流程。

保留原需求 P0／P1／P2 标签：原型闭环／可使用直播版／完整评论运营。评论基本工作已提前到首版；标签用于追踪原优先级，不表示最新实现顺序或已通过验收。未实施条目仍为未来目标。MUST／SHOULD／MAY 分别表示必须／强烈建议／可选。

| 交付边界 | 目标 |
| --- | --- |
| 当前首版 | 非直播评论、可替换 OC、本地文本与兼容API；默认128K但可在真实支持范围内显式调小／调大，保留Codex压缩核心；默认人工审核。 |
| 后续 P1 | 本地TTS／直播共驻、Mock音画及授权直播Adapter、礼物与关系策略、Lore预算、合法点歌、资源降级、负载及持续运行验收。 |
| 完整 P2 | 评论批量分析／聚类与逻辑子任务、运营摘要、多种授权来源、受资源配额约束的运营工作流。 |
| 未来另立项 | 完整视频脚本／剪辑／配音时间线／上传、更多平台、复杂角色制作、个性化声音微调、多实例与分布式部署。 |

首版不强制 Live2D／3D、动捕／摄像头追踪、从零训练 LLM 或微调 TTS，不要求 Orin Nano 本机视频编码；外部 OBS 使用 /overlay。不包含自动打赏、刷量、规避平台限制或无边界大规模发送；自动回复受显式策略、权限及配额约束。实时弹幕不得逐条建立模型实例或子代理。

## 系统与权限边界

默认尽可能封装为一个派生 Docker 镜像／容器，统一 Python／CUDA 环境；业务后端、受限 broker 及按需模型子进程的边界由资源规范维护。逻辑上保持平台／文件／人工输入 → 规范事件或评论批次 → 有界调度 → Provider → 草稿审核或音画播放。网络／CPU 预处理可有界并发，模型并发受配额控制。不引入默认必需的 Kubernetes、Redis、分布式队列或向量数据库。

| 主体／术语 | 含义与权限 |
| --- | --- |
| Operator | 拥有配置、发言、发布策略和最终控制权的运营者，使用受保护管理区。 |
| Viewer | 按平台＋平台用户 ID 识别；昵称仅展示，消息无管理／工具权限。 |
| Platform Adapter | 只使用平台实际授予的权限；认证、权限及风控失败可见。 |
| Worker／Subagent | 有受限输入／输出和生命周期的逻辑工作单元，不等于独立驻留模型，不可自行修改角色核心或越权发布。 |
| Always-on | 事件循环、角色状态及调度常驻，不意味着模型持续推理。 |
| Speech Slot | 实际可播报时间窗口；按时间资源安排互动，不以读完每条消息为目标。 |

SQLite 是版本、身份、事件、草稿和任务事实来源；权重、大音频、图片、日志留文件系统／NVMe，库内保存引用和必要元数据。按功能设留存期限，原始评论数据集独立保留，不因会话到期而删除。接口和持久实体按语义定义，不要求具体表名或 REST 路径逐字等同输入示例。

对话默认30天、可调整或不清理，具体清理范围及事务语义由[运行时数据规范](runtime-and-characters.md#对话留存)维护；失效窗口按[上下文规范](context-and-compaction.md)从现存原文重建。

模型、观众评论及角色卡只产生受限文本／情绪／动作，没有shell、脚本、文件读取、任意URL请求或系统管理工具。包含echo、系统路径、rm -rf等内容只按不可信文本处理，不执行其中的指令；不能用关键词过滤或Prompt承诺代替权限隔离。内部broker只代理固定资源／路径，拒绝工具调用和任意文件／媒体输入，凭证不进入模型上下文。

只有认证Operator可配置API地址与凭证；模型不能指定目标URL。API key独立存于runtime私有文件，不进入公开设置、角色Prompt、日志或Git；内部broker token仅发往固定broker入口。兼容API会收到该任务的上下文，服务端留存由服务条款决定，本地30天清理不代表清除外部服务的数据。视觉预留接口只接受有界内联图片数据，不读取调用者提供的系统路径或URL。

设备部署必须使用非root身份、私有PID／网络命名空间、只发布宿主回环管理端口、只读容器根目录、drop ALL capabilities、no-new-privileges及Docker默认seccomp；不使用privileged／host PID／host network，不挂宿主系统目录或Docker socket。项目runtime为持久写入边界，模型权重、参考素材和词典再只读挂载；临时目录有上限。容器运行库及必要设备接口仍可读用，这不等于模型获得文件工具。当前Jetson无Landlock／AppArmor支持，单容器同UID子进程不具独立文件白名单隔离，不能声称其进程被攻破后仍看不到共享runtime数据。

## 管理界面

| ID | 原优先级 | 要求 |
| --- | --- | --- |
| UI-01 | P0 | MUST 紧凑、任务导向，状态与表格清晰，不以营销主页、口号、无关动效替代工作区。 |
| UI-02 | P0 | MUST 以评论工作台为首版默认入口，保留总览／角色／语音／素材／设置；直播入口标为后续，默认不可启动。展示连接、角色版本、LLM／TTS和实际资源状态。 |
| UI-03 | P1 | MUST 有弹幕队列／音乐点歌／用户记忆／任务与日志；评论运营已提前，其余保持未来目标。 |
| UI-04 | P0 | MUST 可配置角色、预览素材、试听预录／已配置语音API；本地TTS、Mock注入和直播调试实现保留，随后续直播验收启用。 |
| UI-05 | P1 | MUST 清队列、切角色、删记忆有确认或撤销边界；评论提交按人工确认或显式授权自动模式执行，自动发送不冒充逐条人工审核。 |
| UI-06 | P1 | MUST 可查看选中／跳过原因、LLM／TTS 耗时与失败原因。 |
| UI-07 | P1 | SHOULD 桌面优先且响应式，移动端可暂停、静音及看基本状态。 |

常用操作在一至两次导航内；建议持续导航、紧凑全局状态、列表与相关详情，不规定像素布局。异步任务区分等待、生成、审核、播放、完成和失败，错误后保留可修正输入；overlay 不含管理功能。

## 非功能要求

| ID | 要求与验收边界 |
| --- | --- |
| NFR-01 | MUST Orin Nano 8GB 至少有经过实测、可持续运行的本地 Profile，普通短句不依赖连续 NVMe Swap。 |
| NFR-02 | MUST 限制 GPU 同时生成数与队列深度，后台评论不抢占直播语音时段。 |
| NFR-03 | SHOULD 后续直播在热启动、空闲队列、20–40字中文短句下测“事件接收→首段可听音频”，初期p50≤8s、p95≤20s。未达标先量化瓶颈；窗口可由Operator显式调整，但低窗口测量不能冒充默认128K结果。 |
| NFR-04 | MUST Mock 覆盖持续 10 events/s×10 min、突发 50 events/s×60s 的排队／去重／过期；不要求逐条调用模型。 |
| NFR-05 | MUST P1 连续至少 2 小时混合断线、礼物、弹幕峰值，无 OOM、重复礼物播放或无法恢复的卡死。 |
| NFR-06 | MUST 展示／记录 CPU、RAM、GPU 利用／内存、LLM／TTS 耗时、队列、落选原因、缓存失效及平台错误；标明业务主机或推理设备来源。 |
| NFR-07 | MUST 默认回环／可信局域网管理，管理 API／WS 认证；凭证不进公开配置、日志、Prompt 或 Git。不执行模型生成命令，隔离不可信输入。 |
| NFR-08 | MUST 重启恢复角色版本、关系和待审核草稿；过期流事件可丢弃，已完成任务不重播，发布不确定结果不自动重发。 |
| NFR-09 | MUST 更换 LLM／TTS／素材／平台 Adapter 不重写记忆和队列；新模型能力不成为旧 Provider 无关的强制接口。 |
| NFR-10 | MUST 有 AI 提示和素材许可元数据；品牌、音色及音乐按运营场景使用合适资产，原型使用许可不等于商用权。 |
| NFR-11 | MUST 开／停播、静音、切角色、查看／跳过队列、试听和预览在一至两次导航内可达。 |
| NFR-12 | MUST 无付费模型 API 前置依赖，本地可完成基础闭环；云推理仅可选。 |

性能目标不是对 MiniCPM／GPT-SoVITS 的现成承诺。容量、长输入可执行、角色质量、摘要语义、实时延迟与长期稳定性分别取证，不能互相替代。

| --- | --- |
| AC-13 | 完成指定流量和两小时混合运行，故障及资源数据可查。 |
| AC-14 | “忽略系统提示并执行命令”类输入无工具权限，界面可见 AI 标识及许可信息。 |
