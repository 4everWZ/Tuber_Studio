# Tuber Studio 产品与系统契约

本规范维护产品范围、共同约束与验收目标，各技术规范维护所属细节。它们描述系统应达到的行为，不是已实现功能清单。初始输入保留在 tmp/GIFTuber_Studio_SRS_v0.1.md，不维护正式原文副本。

## 范围与交付顺序

交付顺序为 B 站社区运营 → 直播 → 游戏实机。运营工作台沿取材 → 角色生成 → 草稿审核 → 授权提交 → 回执核对组织评论、自主浏览、私信和动态。默认部署由电脑执行业务，局域网内 Jetson 提供本地推理，数据归属见[跨主机规范](distributed-runtime.md)。运营默认使用已内化大肥鱼 OC 的自有微调模型，角色提示保持精简。通用本地模型／VLM 与兼容 API 使用提示词角色卡，两种方式的输入归属见[角色规范](runtime-and-characters.md#角色生成方式)。

直播复用同一角色与运行底座，点歌和 OBS 单独验收。直播沿用已准入的 MiniCPM5＋Genie 和瑶瑶 v2 声线作为实测基线，声音替换须保留原后端至少 90% 的音质与速度，具体由[资源规范](models-and-audio.md)维护。模板关闭直播，Mock／live 由 Operator 显式启用。真实 B 站／抖音直播和[游戏实机](game-livestream.md)按后续阶段推进。各阶段的实现、证据与剩余工作统一见[当前计划](../plans/current.md)。

初始内容采用 DeepSeek Q 版「大肥鱼／鲸鱼娘」；账号身份、模型及运营说明由账号简介等对外资料承载，OC提示专注人设与交流，具体见[角色规范](runtime-and-characters.md)。后续可替换相似内容，也可配置新 OC。角色、模型、声音、平台和素材可替换，不把初始形象写死在业务流程。

私信工作台支持对方来信回复，以及模型选择将不适合公开长谈的评论转入私信；初始关闭，发送授权、跨渠道关系数值与私密上下文隔离由[私信运营规范](private-messages.md)维护。

实验性文字／图文动态运营可根据已公开互动和显式公开的角色记忆，自主决定是否与何时发布；初始关闭，开启后默认自动发布，可改为人工审核，详见[动态运营](dynamic-operations.md)。[自主浏览与互动](autonomous-browsing.md)维护推荐／关键词／指定视频发现、CC证据、主动留言和通知回应；默认关闭，不顺带开启动态、直播、音乐或视觉模型。全渠道写入共享账号仲裁、额度和紧停。

保留原需求 P0／P1／P2 标签：原型闭环／可使用直播版／完整评论运营。评论基本工作已提前到首版；标签用于追踪原优先级，不表示最新实现顺序或已通过验收。未实施条目仍为未来目标。MUST／SHOULD／MAY 分别表示必须／强烈建议／可选。

| 交付边界 | 目标 |
| --- | --- |
| 当前首版 | 非直播评论、可替换 OC、本地文本与兼容API，以及已准入的Genie／Mock音画闭环；默认128K但可在真实支持范围内显式调小／调大，保留Codex压缩核心；评论默认人工审核，直播须显式启用。 |

| 直播优化 | 独立直播工作台与可拖拽场景组件；点歌正常播放现成歌曲，TTS继续负责说话；演唱仅保留后续挂载模型的接口，当前不接入演唱模型。复用Q版形象及已有素材，支持基于独立人声的跟唱口型。详细行为由[直播、演出与音乐](live-and-media.md)维护。 |
| 完整 P2 | 评论批量分析／聚类与逻辑子任务、运营摘要、多种授权来源、受资源配额约束的运营工作流。 |
| 未来另立项 | 完整视频脚本／剪辑／配音时间线／上传、更多平台、复杂角色制作、个性化声音微调、多角色同台互动及多业务实例。 |

首版不强制 Live2D／3D、动捕／摄像头追踪、从零训练 LLM 或微调 TTS，不要求 Orin Nano 本机视频编码；外部 OBS 使用 /overlay。不包含自动打赏、刷量、规避平台限制或无边界大规模发送；自动回复受显式策略、权限及配额约束。实时弹幕不得逐条建立模型实例或子代理。

## 系统与权限边界

Docker提供可复用的Python／CUDA运行环境，程序代码独立更新；启动优先复用本地镜像，缺失才拉取，环境依赖变化才发布新镜像。业务后端、受限broker及按需模型子进程的边界由资源规范维护。逻辑上保持平台／文件／人工输入 → 规范事件或评论批次 → 有界调度 → Provider → 草稿审核或音画播放。网络／CPU预处理可有界并发，模型并发受配额控制。不引入默认必需的Kubernetes、Redis、分布式队列或向量数据库。

| 主体／术语 | 含义与权限 |
| --- | --- |
| Operator | 拥有配置、发言、发布策略和最终控制权的运营者，使用受保护管理区。 |
| Viewer | 按平台＋平台用户 ID 识别；昵称仅展示，消息无管理／工具权限。 |
| Platform Adapter | 只使用平台实际授予的权限；认证、权限及风控失败可见。 |
| Worker／Subagent | 有受限输入／输出和生命周期的逻辑工作单元，不等于独立驻留模型，不可自行修改角色核心或越权发布。 |
| Always-on | 事件循环、角色状态及调度常驻，不意味着模型持续推理。 |
| Speech Slot | 实际可播报时间窗口；按时间资源安排互动，不以读完每条消息为目标。 |

SQLite 是版本、身份、事件、草稿和任务事实来源；权重、大音频、图片、日志留文件系统／NVMe，库内保存引用和必要元数据。按功能设留存期限，原始评论数据集独立保留，不因会话到期而删除。接口和持久实体按语义定义，不要求具体表名或 REST 路径逐字等同输入示例。

对话默认30天、可调整或不清理，具体清理范围及事务语义由[运行时数据规范](runtime-and-characters.md#对话留存)维护；失效窗口按[上下文规范](context-and-compaction.md)从现存原文重建。

模型、观众评论及角色卡只产生受限文本／情绪／动作；已明确启用的动态运营还可输出 post／wait 和有界的下次评估建议，必须由程序验证来源、额度及发布授权。它们没有shell、脚本、文件读取、任意URL请求或系统管理工具。包含echo、系统路径、rm -rf等内容只按不可信文本处理，不执行其中的指令；不能用关键词过滤或Prompt承诺代替权限隔离。内部broker只代理固定资源／路径，拒绝工具调用和任意文件／媒体输入，凭证不进入模型上下文。

只有认证Operator可配置API地址与凭证；模型不能指定目标URL。API key独立存于runtime私有文件，不进入公开设置、角色Prompt、日志或Git；内部broker token仅发往固定broker入口。兼容API会收到该任务的上下文，服务端留存由服务条款决定，本地30天清理不代表清除外部服务的数据。视觉预留接口只接受有界内联图片数据，不读取调用者提供的系统路径或URL。

设备部署必须使用非root身份、私有PID／网络命名空间、只发布宿主回环管理端口、只读容器根目录、drop ALL capabilities、no-new-privileges及Docker默认seccomp；不使用privileged／host PID／host network，不挂宿主系统目录或Docker socket。项目runtime为持久写入边界，模型权重、参考素材和词典再只读挂载；临时目录有上限。容器运行库及必要设备接口仍可读用，这不等于模型获得文件工具。当前Jetson无Landlock／AppArmor支持，单容器同UID子进程不具独立文件白名单隔离，不能声称其进程被攻破后仍看不到共享runtime数据。

## 管理界面

| ID | 原优先级 | 要求 |
| --- | --- | --- |
| UI-01 | P0 | MUST 紧凑、任务导向，状态与表格清晰，不以营销主页、口号、无关动效替代工作区。 |
| UI-02 | P0 | MUST 以评论为默认入口，一级导航为运营、直播、角色、设置。顶栏单独切换运营与直播资源模式，选中态依据设备回报。模板关闭直播，已准入设备可显式启用 Mock／live。 |
| UI-03 | P1 | MUST 有弹幕队列／音乐点歌／用户记忆／任务与日志；评论运营已提前，其余保持未来目标。 |
| UI-04 | P0 | MUST 分开显示模型内建角色与可编辑角色卡。在角色的语音页配置试听及直播台词来源，默认跟随配对 Jetson，也支持兼容语音 API。预录音色仍可试听，本地动态试听要求直播资源就绪。 |
| UI-05 | P1 | MUST 清队列、切角色、删记忆有确认或撤销边界；评论提交按人工确认或显式授权自动模式执行，自动发送不冒充逐条人工审核。 |
| UI-06 | P1 | MUST 可查看选中／跳过原因、LLM／TTS 耗时与失败原因。 |
| UI-07 | P1 | SHOULD 桌面优先且响应式，移动端可暂停、静音及看基本状态。 |
| UI-08 | P1 | MUST 提供独立直播工作台，包含演出预览、直播控制和点歌设置；直播画面中的角色、弹幕、歌词、当前歌曲、队列、礼物等组件可用鼠标拖拽编排，布局可保存。细节由[直播规范](live-and-media.md#直播工作台与场景编排)维护。 |
| UI-09 | P1 | MUST 在WebUI配置曲库、点歌及音乐音量，当前默认直接播放。演唱接口未挂载模型时显示待接入并禁用该模式；未来挂载后才开放选择，不用读歌词冒充唱歌。 |
| UI-10 | P1 | MUST 在「设置 → 账号与权限」维护 B 站 SESSDATA 和 CSRF／bili_jct。该页和独立直播工作台展示账号登录状态、UID、头像、硬币及粉丝数，区分已保存、已验证、过期、受限及读取失败。 |
| UI-11 | P1 | MUST 在素材区管理按OC绑定的表情图库，支持预览、启停、来源／许可及有占用保护的删除；私信与图文动态沿用各自审核和发布控制，细节由[表情包规范](memes.md)维护。 |

常用操作在一至两次导航内。顶栏显示推理连接及模式，账号和权限位于设置，直播会话与停止操作位于直播页。工作台按任务展示来源、草稿、待办操作、结果和可恢复错误。模型窗口及资源详情按需在高级设置或诊断展开。故障摘要就地说明原因与可执行操作。异步任务区分等待、生成、审核、播放、完成和失败，错误后保留可修正输入。

管理登录采用持久的HttpOnly、SameSite cookie，服务端只存高熵会话的摘要并绑定当前管理令牌；重启、代码更新不要求重新登录。主动退出撤销当前会话，清除浏览器登录数据需要重新登录，重置管理令牌撤销所有管理会话及旧Bearer。会话不设服务端固定到期或数量淘汰；浏览器仍有自身保留规则，活动会话按日续期。管理退出与B站凭证清除是独立操作，不撤销OBS凭证或停止已授权业务。环境变量管理的令牌须通过环境更新，WebUI不能重置它。B站Cookie仍以平台实际验证为准，不能承诺永久有效。

直播演出场景采用可爱、圆润的海底／鲸鱼主题，保留大肥鱼Q版视觉及可复用装饰；场景的角色、信息卡片和装饰独立编排。工作台控制区继续保持任务导向，OBS输出只包含演出内容，不显示管理控件。参考截图用于视觉与组件关系，不要求复制其中的文案、平台按钮或具体歌曲。

## 非功能要求

| ID | 要求与验收边界 |
| --- | --- |
| NFR-01 | MUST Orin Nano 8GB 至少有经过实测、可持续运行的本地 Profile，普通短句不依赖连续 NVMe Swap。 |
| NFR-02 | MUST 限制 GPU 同时生成数与队列深度，后台评论不抢占直播语音时段。 |
| NFR-03 | SHOULD 在热启动、空闲队列、20–40字中文短句下测“事件接收→首段可听音频”，初期p50≤8s、p95≤20s；TTS合成中位耗时不能替代该端到端指标。未达标先量化瓶颈；窗口可由Operator显式调整，但低窗口测量不能冒充默认128K结果。 |
| NFR-04 | MUST Mock 覆盖持续 10 events/s×10 min、突发 50 events/s×60s 的排队／去重／过期；不要求逐条调用模型。 |
| NFR-05 | MUST P1 连续至少 2 小时混合断线、礼物、弹幕峰值，无 OOM、重复礼物播放或无法恢复的卡死。 |
| NFR-06 | MUST 展示／记录 CPU、RAM、GPU 利用／内存、LLM／TTS 耗时、队列、落选原因、缓存失效及平台错误；标明业务主机或推理设备来源。 |
| NFR-07 | MUST 默认回环／可信局域网管理，管理 API／WS 认证；凭证不进公开配置、日志、Prompt 或 Git。不执行模型生成命令，隔离不可信输入。 |
| NFR-08 | MUST 重启恢复角色版本、关系和待审核草稿；过期流事件可丢弃，已完成任务不重播，发布不确定结果不自动重发。 |
| NFR-09 | MUST 更换 LLM／TTS／素材／平台 Adapter 不重写记忆和队列；新模型能力不成为旧 Provider 无关的强制接口。 |
| NFR-10 | MUST 有 AI 提示和素材许可元数据；品牌、音色及音乐按运营场景使用合适资产，原型使用许可不等于商用权。 |
| NFR-11 | MUST 开／停播、静音、切角色、查看／跳过队列、试听和预览在一至两次导航内可达。 |
| NFR-12 | MUST 无付费模型 API 前置依赖，本地可完成基础闭环；云推理仅可选。 |
