# Tuber Studio 产品边界

这是首版的规范入口，维护用户授权的目标，而非实现进度。最初输入为 `docs/inputs/giftuber-studio-srs-v0.1.md`；原文作为基线保留，不据实现结果改写。

## 交付顺序与授权对齐

1. 首版优先 B站评论浏览、分类、角色回复草稿、审核／复制及可选自动回复，同时保留 Mock → 本地模型 → 语音 → overlay 离线闭环。
2. B站真实直播、抖音直播适配后置；不要求开播或平台审批才能验证首版。
3. 新 OC 必须可通过角色配置、音色和素材引用建立，不把大肥鱼特征写死在业务流程中。
4. 实际模型上下文至少128K（131072 tokens）。设备与模型允许时可增加；不能以外部历史库或摘要替代真实窗口。
5. 压缩参考 Codex CLI 公开的本地实现，保留其核心算法，仅适配本地模型、项目状态和存储。
6. 初始原型使用 DeepSeek Q版「大肥鱼／鲸鱼娘」，后续可替换相似内容；来源和使用约束保留。所有自动外部回复默认关闭。
7. 使用 Jetson 与外部 OBS；Git 管理源代码、配置模板、维护文档、回归测试和长期工具，忽略凭证、数据库、权重、缓存及临时探针。不自动推送。

## 规范归属

- [评论运营](comment-operations.md)：读取、导入、分类、草稿、审核、自动策略及真实发布状态。
- [角色与运行时](runtime-and-characters.md)：可替换 OC／Provider、事件队列、声音／素材与播放确认。
- [上下文与压缩](context-and-compaction.md)：128K容量、分层状态、Codex算法对齐和压缩验收。

每项行为只有上述一个维护归属；运行进度和未完成验证放在当前工作计划，部署步骤放使用指南，不在规范中累积运行日志。

## 共同约束

单 Python 后端、SQLite事实源、本地模型，不引入必需的 Redis、向量数据库或分布式系统；无需付费推理 API。管理API／WS认证，默认回环绑定；平台凭证只在本地受限runtime保存，不进Prompt／日志／Git。弹幕、评论、模型产物均是数据，不授予工具权限。

设备容量、长输入可执行性、回复质量、实时延迟和长期稳定性是不同验收结论，分别用对应证据支持。OBS本身、真实发布和真实直播授权需独立验证。
