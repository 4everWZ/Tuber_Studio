# Tuber Studio 产品与系统契约

## 范围

Tuber Studio 在同一工作台提供 B 站社区运营、号主对话和直播。运营统一启停，按各渠道保存的权限取材、生成草稿、审核、提交与核对回执。视频、评论和私信分别保存进度。新安装先由人工审核，自动发送按渠道开启。当前优先验收真实账号运营，其次是直播。游戏实机作为[后续扩展](live/game-livestream.md)。

电脑通常持有业务数据库、账号、任务和 OBS，Jetson 提供推理。运营和直播默认使用同一 Qwen3.5-9B 微调发布，直播语音使用 Genie。工作台和接口支持更换模型和 Provider，各模型读取所选角色卡。默认角色为 Q 版鲸鱼娘大肥鱼，可在工作台新建、编辑和激活其他卡片。角色卡的表达、账号资料、任务材料和对话分别维护。

直播工作台提供节目预览、弹幕、点歌、场景及 OBS 输出。默认采用图片／GIF，Live2D 可选。演唱模型保留挂载接口。完整视频剪辑上传、多角色同台和实机游戏另行实施。P0、P1、P2 标记保留原需求的优先级。

运营动作限于已授权的平台接口和本系统提供的渠道。打赏、刷量与绕过平台限制不在业务范围内。

## 验收现状

30 个真实视频的审核回放取得字幕与画面，平台写入为零。后续实跑已有评论与动态的本地成功回执，同时发现公开回复正文残片、工作台状态与记录可读性问题。浏览器已验证角色编辑、单条评论审核、私信记录、动态草稿和共享图库。OBS 本体已验证可选 Live2D 的对白口型、静音与 GIF 回退。真实通知和私信、修订后的平台提交、直播首音和持续混合负载见[当前计划](../plans/current.md)。

## 系统与权限边界

Docker提供可复用的Python／CUDA运行环境，程序代码独立更新；启动优先复用本地镜像，缺失才拉取，环境依赖变化才发布新镜像。业务后端、受限broker及按需模型子进程的边界由资源规范维护。逻辑上保持平台／文件／人工输入 → 规范事件或评论批次 → 有界调度 → Provider → 草稿审核或音画播放。网络／CPU预处理可有界并发，模型并发受配额控制。不引入默认必需的Kubernetes、Redis、分布式队列或向量数据库。

| 主体／术语 | 含义与权限 |
| --- | --- |
| Operator | 拥有配置、发言、发布策略和最终控制权的运营者，使用受保护管理区。 |
| Viewer | 按平台＋平台用户 ID 识别；昵称仅展示，消息无管理／工具权限。 |
| Platform Adapter | 只使用平台实际授予的权限；认证、权限及风控失败可见。 |
| Worker／Subagent | 有受限输入／输出和生命周期的逻辑工作单元，不等于独立驻留模型，不可自行修改角色核心或越权发布。 |
| Always-on | 事件循环、角色状态及调度常驻，不意味着模型持续推理。 |
| Speech Slot | 实际可播报时间窗口；按时间资源安排互动，不以读完每条消息为目标。 |

SQLite 是版本、身份、事件、草稿和任务事实来源；权重、大音频、图片、日志留文件系统／NVMe，库内保存引用和必要元数据。按功能设留存期限，原始评论数据集独立保留，不因会话到期而删除。接口和持久实体按语义定义，不要求具体表名或 REST 路径逐字等同输入示例。

对话默认30天、可调整或不清理，具体清理范围及事务语义由[运行时数据规范](foundation/runtime-and-characters.md#对话留存)维护；失效窗口按[上下文规范](foundation/context-and-compaction.md)从现存原文重建。

模型、观众评论及角色卡只产生受限文本／情绪／动作；已明确启用的动态运营还可输出 post／wait 和有界的下次评估建议，必须由程序验证来源、额度及发布授权。它们没有shell、脚本、任意文件读取或系统管理工具；运营可由模型按需选择公开网页取材。直播启用后可选一次短读取，限额由直播规范维护。工具结果不能改变发送授权。外部内容仅作为任务材料，工具权限由应用接口执行。内部broker只代理固定资源／路径，拒绝工具调用和任意文件／媒体输入，凭证不进入模型上下文。

只有Operator可配置Provider API地址与凭证；模型可在获准场景选择公开 HTTPS 网页取材，不能修改Provider地址或凭证。API key独立存于runtime私有文件，不进入公开设置、角色Prompt、日志或Git；内部broker token仅发往固定broker入口。兼容API会收到该任务的上下文，服务端留存由服务条款决定，本地30天清理不代表清除外部服务的数据。视觉预留接口只接受有界内联图片数据，不读取调用者提供的系统路径或URL。

设备部署必须使用非root身份、私有PID／网络命名空间、只发布宿主回环管理端口、只读容器根目录、drop ALL capabilities、no-new-privileges及Docker默认seccomp；不使用privileged／host PID／host network，不挂宿主系统目录或Docker socket。项目runtime为持久写入边界，模型权重、参考素材和词典再只读挂载；临时目录有上限。容器运行库及必要设备接口仍可读用，这不等于模型获得文件工具。当前Jetson无Landlock／AppArmor支持，单容器同UID子进程不具独立文件白名单隔离，不能声称其进程被攻破后仍看不到共享runtime数据。

常用操作在一至两次导航内。顶栏显示推理连接及模式，账号和权限位于设置，直播会话与停止操作位于直播页。工作台按任务展示来源、草稿、待办操作、结果和可恢复错误。模型窗口及资源详情按需在高级设置或诊断展开。故障摘要就地说明原因与可执行操作。异步任务区分等待、生成、审核、播放、完成和失败，错误后保留可修正输入。

直接通过 `localhost`、`127.0.0.1` 或 `::1` 访问个人工作台可免令牌，服务同时验证连接地址和请求主机。远程或代理访问使用管理令牌。显式设置 `TUBER_ADMIN_TOKEN` 时也对本机访问启用管理登录。远程管理登录采用持久的 HttpOnly、SameSite cookie，服务端只存会话摘要并绑定管理令牌；重启、代码更新不要求重新登录。退出撤销当前会话，重置管理令牌撤销所有管理会话及旧 Bearer。活动会话按日续期。B站凭证和OBS凭证各自管理。环境变量管理的令牌须在环境中更新。

直播演出场景采用可爱、圆润的海底／鲸鱼主题，保留大肥鱼Q版视觉及可复用装饰；场景的角色、信息卡片和装饰独立编排。工作台控制区继续保持任务导向，OBS输出只包含演出内容，不显示管理控件。参考截图用于视觉与组件关系，不要求复制其中的文案、平台按钮或具体歌曲。

### 号主对话与任务

号主对话使用独立的私聊作用域和对话留存，清空入口在顶栏菜单。对话顶栏显示当前角色和简短的推理连接状态，工作区切换集中在侧栏。消息与底部输入区同宽，桌面占可用宽度约 88%，上限 1440 px。输入区以「＋」菜单调用快捷操作，圆形箭头发送。生成时发送键原位切换为停止键，取消当前生成并保留输入，已入队任务可从任务卡控制。Enter 发送，Shift+Enter 换行，中文输入法组字期间保留选字行为。默认加载最近一页，取更早消息时保持阅读位置和草稿，生成失败保留重试入口。

自由输入由当前 9B 按结构化意图理解，快捷菜单提交同一意图结构。程序从已验证的运营记录取时钟、观看数量、原话、作者和回执。事件列表保存实际展示顺序，追问用原来源，按账号和角色重新核验。待确认的公开经历可编辑后保存。记忆资格由[角色与记忆规范](foundation/runtime-and-characters.md#号主可查看的记忆)维护。

对话卡引用实际动态草稿、视频任务、运营和直播状态，按后端状态刷新。运营卡查看与修改共用授权并启动或收尾。自然语言请求开启直播时，确认后调用现有直播工作台的会话入口。启动与授权确认绑定账号、角色和策略，状态变化后需重新确认。明确的只读视频任务直接入队，取消后可续跑，同一请求重试复用原任务。动态须经卡片或现有工作台提交并显示实际回执。
