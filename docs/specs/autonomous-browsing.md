# 自主浏览与互动

本规范维护视频发现、内容证据、通知回应和自动化调度的共同契约。评论审核、私信正文与关系分别由[评论](comment-operations.md)、[私信](private-messages.md)和[角色／记忆](runtime-and-characters.md)规范维护；上下文计量沿用[上下文与压缩](context-and-compaction.md)。原始需求编号在[当前计划](../plans/current.md#自主浏览需求映射)保留映射；持续维护的行为以本规范为准。

## 授权与配置

自主运营只有一个运行开关，冷启动保持待命。视频、顶层留言、公开回复、通知读取／回复、私信读取／回复和动态按「运营设置」中实际保存的权限运行；开始不修改权限，不强开其它通道。停止收齐已选通道的在途任务并保存进度，设置偏好保持。直播、音乐、ASR和视觉资源启用仍分别配置。

启用前展示实际账号、OC及版本、功能、直接发送方式和额度，核验登录、平台能力与模型。缺失必要能力应阻塞对应功能并说明原因。预览不发送；已有草稿和首次启用前的平台历史通知不取得自动发送资格。已采集的待处理通知及未完成分页在暂停与重启后保留，用户重新开启后继续处理。同级公开回复兼顾最新和等待最久的消息，临时网络失败及日额度等待保留唤醒时间。停止本轮取消在途执行并保留子任务进度和草稿；普通关闭保留权限偏好；紧急停止持续抑制所有自动收发，重启不能解除。已提交请求仅收取回执。角色、账号、配置版本和来源在提交前须再次有效。

「自主运营」首页只有开始／停止按钮，并显示当前开放权限。大肥鱼自行发现、取材、判断和写稿；自动发送或待审核由明确保存的权限决定，模型语义诊断结果不增加第二层隐藏授权门槛。既有草稿沿用原状态。视频与收件箱是同一控制器的子任务，共用调度器；不再运行独立发现控制循环。关网页继续运行，服务重启后待命。

每轮检索得到一批候选，大肥鱼选择视频顺序及独立视频子任务的并发数，并发不超过用户设置与推理节点承载能力。候选、检索页位置、逐项选择及其具体理由、子任务和批次状态持久保存。模型只提交一份按优先顺序排列的行动选择，程序据此派生执行列表，不要求重复填写另一份视频清单。自动批次保留实际调用与 token 计量，不设置隐藏的调用次数、累计 token 或固定整批时间上限。单次请求超时、输出长度、真实上下文窗口及用户配置的发布上限继续有效。信息足够时，一次调用直接选择行动并给出正文；补读、补看画面、联网取材或继续翻评论按模型的实际选择执行。每个行动保存结合当前标题、材料或会话的具体理由，程序等待不填作角色判断。

评论区任务不以观看视频为前置，未看视频也可以直接逛评论。仅浏览评论时只获取视频身份和真实楼内文字，复用已有视频材料但不自动补读字幕或画面，不新增观看次数、观看进度、视频偏好或主回复决策。评论文字不能冒充视频内容；尚无视频材料时，回应只引用实际读取的评论。以后选择观看时才按观看任务计数。未开放评论权限时，该行动不出现在本批选项中。评论任务的恢复、重读仍保持评论任务类型，不转成观看任务。

候选批次持久调度，视频内容阅读、视频主回复决定、评论区／目标回复、消息收件箱分别保存独立进度。视频进度保存原字幕、画面观察、已读范围及来源，区分开始观看、读过部分材料与完整读完；取样画面不冒充看完整片。看后不发言也保存观看与主回复决策。自主观看行动同时记录对视频的真实偏好与具体原因，喜欢内容与是否发言分别表达；只看视频也可结束观看，不为填写偏好另加模型调用。后续评论复用已有材料，主回复决策按账号、角色和视频去重，评论回复按账号、角色和目标评论去重，不以角色版本或已看状态封闭整个视频。评论区回来时先检查最新，再从持久游标继续向下；本次深度处理完后保存位置并让出调度。同楼会话串行，等待后刷新上下文，不同视频或讨论可并行准备。

公开回复、私信、新视频共用 2∶2∶1 模型处理机会，空闲份额可借用。同级按到达顺序，自己的视频新评论优先，随后是别人回复自己的内容与其他讨论；新私信在下一次模型调度时插入，不打断正在生成的请求。已看视频的评论回访进入公开回复通道，不占新视频份额，也不增加观看次数。恢复中的观看任务与新选视频共享视频通道。候选包含观看状态、上次访问和评论进度；同批同BV合并来源，同视频在途任务合并，不重复开Agent。原样重现的已略过标题沿用原选择，继续获取其它候选；稍后继续的项目保存到后续队列。

网络中断、人工暂停及服务重启保存原批次、当前动作、材料、已读范围和评论游标，恢复后继续未完成项目，不重新筛选已处理项，也不重新占用已开始观看的名额。重启保持待命，由用户恢复自动任务。相同任务的相同失败合并次数和最新错误，异常只影响对应任务。候选都有去向且本批在途子任务已收尾即可结束，待审核草稿和待核对回执不阻塞下一批。全批略过仍遵守检索间隔，不高速重取同批。发送结果不明确时只核对原提交。登录与模型配置等整条链路的阻塞显示在首页。

## 每日计数

业务日统一按 `business_timezone`，默认 `Asia/Taipei`。`daily_watch_limit` 与 `max_replies_per_video` 为 `0` 时分别不限。

| 行为 | 观看次数 | 视频回复次数 |
| --- | --- | --- |
| 读标题、封面后略过 | 不增加 | 不增加 |
| 观看任务首次开始执行 | 增加一次 | 不增加 |
| 继续同任务或中断恢复 | 不重复增加 | 不增加 |
| 看完不发言、只逛评论、回访与翻页 | 不增加 | 不增加 |
| 生成、保存、拒绝、复制草稿 | 不增加 | 不增加 |
| 平台确认发布成功 | 不增加 | 增加一次 |

同一视频的每日回复合计主评与楼内回复。明确失败释放预占，未明确结果保留占位并先核对，同次提交只结算一次。数据库事务同时预占最后名额与发送尝试，避免并发超额；草稿不占成功次数。达到观看上限后，已开始任务、评论与私信继续；某视频用完回复名额不影响其它视频。

发送结果跨午夜确认时，成功按回执的发布时间或确认时刻归日；未确认提交跨日保留待决名额，重复核对不改变已确定的成功日期。日额度等待保存唤醒时间，本批可以收尾并处理其它内容，到期后恢复原任务。

## 模块职责

`discovery.py` 获取候选、合并来源并维护跨批搜索分页；`batches.py` 保存批次选择与生命周期并执行独立视频、评论任务；`decisions.py` 生成行动、具体理由与正文；`evidence.py` 保存真实材料和来源；`progress.py` 执行可恢复观看与租约；`comment_reader.py` 保存逐评论处理结果并读取新增、旧页和讨论楼；`quotas.py` 维护业务日计数；`publication.py` 发布和核对；`repository.py` 负责数据库事务；`task_views.py` 统一持久任务与无需Worker的标题选择视图。`service.py` 保留装配和业务入口，沿用 `operation_turns.py` 与运行时会话锁。

批次标题选择与全部逐项去向一起提交事务。程序不会因旧评论模块的历史 `auto_browse` 设置另启轮询链路；统一开关关闭与服务重启待命都覆盖自动浏览。清理空中断轮次只移除没有材料、判断、回复、继续任务或重试引用的记录；真实观看、发送结果、去重和可恢复进度保留。

左栏只保留自主运营一级入口，活动、评论处理、私信、动态与运营设置在内部切换。首页按业务日展示全部运营活动，横向筛选全部／视频／评论／私信／动态，简单统计与分页同属这份结果。视频行展示真实阅读范围、是否主评、兴趣与暂不发言原因；评论区分主评和楼内回复，私信显示对象、方向与结果，草稿不会冒充已发送。排队和取材放在详情，程序状态不作为角色判断。列表没有内嵌滚动区。评论工作台仍负责审核、编辑、发布及回执核对。

告警可以清除已读计数；确认状态持久保存，刷新不恢复旧计数，同错误再次发生仍出现并仅计新增次数。达到发送名额上限属于正常延期，保存唤醒时间，不制造重试错误。旧运行记录可归档退出日常展示，已批准草稿、平台回执与防重标识保留；回访不会使已归档的旧正文重新显示，新发生的真实行动仍单独记录。历史视频未存真实偏好时显示未知，不从主评、点赞或程序状态推断模型喜好。

## 发现与材料

发现支持首页推荐、用户词、获准的OC词、显式热门和指定视频。空词默认推荐；推荐失败不得暗换热门或固定词。候选合并来源去重后交给模型选择；排除词、作者、分区、时长和时间条件先于昂贵准备。大肥鱼可以选完本批、全部略过或明确稍后继续，可以零留言。只读预览保留独立资源预算，不用于中断自动批次。

细看必须获取完整简介、真实标签、作者UID、时长及分P/CID，搜索摘要不得冒充全文。按语言顺序、同语言人工优先选择CC，保留人工／AI标识、有时间的片段、轨道、覆盖、获取时间及材料版本。缓存记录 ID 与来源版本分开，文件格式和取材时间变化不影响来源判定。发布复核以来源身份及实际材料内容为准。无CC、空或仅署名、权限／风控、网络与格式失败分别记录。没有有效CC且尚未取得真实画面材料时，不生成视频相关自动发言；不能用热评、标题、封面或平台摘要冒充字幕／画面证据。可用视觉材料的条件由下文视觉契约维护。

字幕按真实token有界分段，记录未读P和片段范围；派生笔记须引用仍存在的原文。兴趣、值得发言和是否已看分别保存；临时错误不永久归为不喜欢。模型只能返回受校验的有限计划、兴趣、意图、正文与证据引用。不存在的引用、未完整输出、超窗、依赖未读画面或材料过期均不能产生可发送候选。外部文字是数据，无执行、改策略或指定任意目标的权限。

内容判断按视频部分与材料类型呈现自然文本行，标题明确标为“视频第x部分（Px）”，内容块用[e1|00:15]这类短编号与起始时码标记。相邻短字幕可按停顿、标点及段落长度合并，保留全部非空原文和顺序，不删拟声词、不摘要或截断单个原段；空白行可省略呈现，后台原段仍完整保留。不同视频部分、轨道／版本或视觉帧不合并，未读原段之间不拼成连续块。模型只看到一次标题、编号、来源类型与覆盖情况；真实CID、轨道GUID、Provider版本和逐段精确时码保存在本次调用的typed绑定与原始材料。segments短表仅供后端生成允许引用的schema枚举，不在实际模型正文重复序列化。模型最多选择8个内容块；返回后用独立ResolvedContentDecision展开为所有被选原段，内部展开数不冒充模型选择数，也不绕过ContentDecision的8项校验。未知或直接返回原ID均拒绝，缓存、任务、证据、意图与草稿继续使用真实segment.id；短编号只在当前调用中有效。同一内容呈现工厂统一服务分块计量与实际模型输入，source_kinds／has_visual及coverage继续明确本次材料。性能核对分别记录字幕本体、格式包和完整实际messages的token；schema仅在Provider实际写入prompt时计入，不用仅格式包的结果代替整请求。兴趣与发言判据沿用原约定；正文按模型身份使用对应的短身份锚或完整角色卡，分类的显式兴趣摘要另行匹配与验证。内容判断的机器任务提供理由与字段组合的中文释义，先决定是否准备回应，公私信由后续步骤选择。interest=like、worth_commenting=true、coverage_required=provided表示准备回应，该组合的reason为specific_detail；冲突进入共用生成续接并反馈具体字段，Agent可重选参与、暂不参与或补读材料的意图。既有一致性规则也以互斥分支表达在原生grammar，后验校验不变；该校验不检查或改写OC台词。

已登记大肥鱼的ContentDecision默认采用C6i分类视图：身份、人格、兴趣和情绪摘要绑定完整core／style／rules指纹；编辑人物卡或未登记人物回完整卡。任务清楚区分已有材料和仍需内容，保留原意图类别。只有分类中间块可在原相邻段基础上按480原字符／90秒目标继续合并；不跨分P／轨道、间隔、重叠或视觉帧，长原段不切，全部原文、原ID和精确起止时间留在后台，正文仍逐原rN引用。fetched_at及空tags保留在后台原材料，不进入分类投影；完整简介、非空标签、发布时间、覆盖和缺失信息继续提供。重复命令只在至少3行共享完整shell单词前缀、无别名冲突且有净字符收益时使用明确的可逆映射。分块继续依据真实窗口及只读预览的显式父轮预算，不对所有视频设1500–2000 tokens上限；指定教程及同素材对照见[字幕输入结果](../../evaluations/results/subtitle-input-e2b-20261102.md)。

正文ResponseDecision采用独立呈现：每条已选原段对应一个短编号[r1|起止秒]，移除逐段JSON及真实CID／轨道ID包装，保留全部已选原文、精确时码，以及完整thread和recent_public_responses。正文不合并原段，最多8条引用仍对应最多8条真实原段；纯文字来源也通过本次一一对应映射引用。共用生成恢复只验证短编号wire结果，未知编号或直接返回旧原ID均反馈续接；仅在最终返回边界恢复canonical ID并重新通过ResponseDecision校验，缓存、意图和后续目标绑定继续使用真实身份。正文输入格式版本纳入生成绑定及容量快照签名，旧格式wire检查点不自动复用；本次不新增正文词面或长度判据。

## 互动与发布

公开正文按交流情境自然决定篇幅，旧 public_max_chars 配置兼容读入后退役。decision_max_tokens 默认 8192，保留已有显式值，可配置至 65536。思考计入同一额度，实际请求受真实窗口与单次输出设置约束；只读预览另受其父轮额度和期限约束。VideoVisionConfig.max_output_tokens 通用默认 2048，可配置至 65536。配对的 Gemma 和大肥鱼视觉档使用 8192。正文资源、未完成输出与长重复段诊断沿用[运营正文契约](comment-operations.md)。

顶层留言与定向回复使用不同root/parent语义。@和收到的回复必须来自当前账号的平台通知，并读取真实原文及必要根楼／父消息。涉及视频内容的回应使用视频证据；仅讨论评论原文可引用已核验楼内文字，不自动补看视频。文字动态使用原动态及楼内文字；不支持类型明确跳过。首次轮询建立高水位，分页事件先持久保存再推进游标，不标已读。点赞／关注不触发发言。事件别名以原始消息身份合并；视频已看不能吞掉新事件。同楼、同用户保持来源顺序；广告、循环、无内容或冷却可解释地跳过／等待。

公开回应与私信移交共享意图，不能各发一份。私信仅联系真实来信人或当前已核验评论作者，来源公开楼及必要视频引用可单向带入私信。私信原文和私密记忆不进入公开候选或搜索。关系沿用UID＋OC及现有幂等增量；视频事实不写成角色经历或用户偏好。直接私信只按其实际关联补入视频，不使用当前浏览视频作为公共背景。

所有渠道经过同一账号写入仲裁，原子预占共享额度、渠道子额度和用户冷却。每个意图保留唯一首记录；明确拒绝后，后端可签发绑定原目标／来源、修订正文、审批方式及当前权限版本的一次性票据，追加子attempt，原始记录保持。所有attempt计入账号与渠道额度；同意图已明确拒绝的尝试不冒充已投递的用户冷却。票据原子消费，旧票、分支重投及目标变化均无资格。不确定结果先核对平台状态，确定读回成功才追加resolution；查不到仍待核对。不确定状态只冻结原意图，其他视频与会话继续处理；重启后仍只核对原提交，不重发。顶层留言按账号＋OC＋视频长期防重；角色版本升级、跨日或清缓存不恢复资格。成功须平台码和有效ID；可见性另记visible/not_visible/not_found/check_failed，查不到不回退发送状态、不补发。近期正文相似度与大量重复段落属于生成诊断，由模型结合表达意图选择保留、修订或暂缓，正常口癖与玩梗保留表达自由。

## 任务继续与平台反馈

生成反馈、平台拒绝修订、预算检查点及只读回执核对统一遵守[运营任务继续契约](operation-continuations.md)。

字幕分块按实际Provider计数完整角色、任务、原文和Schema消息，保留显式输出预留及窗口余量，不以仅材料token数代替实际生成输入；计数探针同样共享生成锁。原文全部顺序分块。固定消息和最小片段已超过容量时保留容量检查点，同一容量配置的后续发现不反复尝试该视频；调整容量或显式重读可重新准备。

内容判断申请视觉补读仍遵循前述一次补读、CC优先及Provider身份规则。

浏览续轮仅复用同账号、OC和真实来源版本／canonical片段对应的已完成判断，角色或模型变化时重新核验判断的适用性；主回复长期防重不因OC版本变化解除，不重复消耗已完成chunk。ResponseDecision原输出若包含私信动作或路由尚未可靠解析，公开任务／通知DTO仅返回状态和私域入口；完整原文由私信列表的private_continuations按当前账号与OC展示，未因此创建私信草稿或收件人。私信内容与恢复记录仅在私信区域展示。

## 并发与资源

每账号可同时有一个视频轮次和一个公开互动轮次，分别计量。只读预览与自主运营按视频并发准备材料；自主运营为每个候选执行独立子任务；新视频取材与评论回访使用独立执行窗口，在用户配置和节点容量内并发，不让整页评论占住新视频准备窗口。模型继续共享唯一生成锁，平台评论提交也走同一写锁。公开材料在同轮合并在途读取，并跨轮复用有效缓存。任务持久绑定账号、角色版本、来源、输入版本、父轮及带代数的租约；显式预览预算／期限与自动批次的无限累计计量分别保存。占有、心跳、子预算预留、结算与提交校验使用事务；未发送任务可一次接管，旧代数禁止写回，发布中任务不得接管重发。控制存储故障应阻断写入。

父轮取消须收齐本轮子任务。运营模型在公开回复、私信、刷视频积压时按 2∶2∶1 分配生成机会，空队列的机会交给有任务的队列。全渠道运营扫描最近三条可见投稿的新评论，核验当前账号确为视频作者后优先处理，再处理其他公开回复。私信按会话隔离，新来信优先排入该批次。直播按既有资源优先级先行。记录队列／锁等待、阶段时间、合并、命中、防重、接管、迟到拒绝、限流和真实资源峰值。

每日观看及单视频回复按前述业务日计数；既有账号和渠道发送保护沿用滚动 24 小时尝试数。数量额度为 `0` 时取消该项上限，其他非零额度仍分别生效。开启或停止一个轮次不会改变同源防重和平台回执约束。

浏览原始材料进入独立browsing缓存池，统一展示容量、受保护和可回收占用，不重复计入临时或音乐池。任务及待审核草稿引用保护材料；空间不足停止新增准备。清理只移除可回收缓存；独立持久的已读材料和进度继续保留，派生判断仅在全部原文依据均失效时失效；不删审计、防重、关系、账号或私信。音乐最高15GiB保持原有含义。

## 视觉与管理接口

视觉默认按逐帧观察与汇总运行。可显式配置 `frame_strategy=joint` 实验一次最多三帧的联合观察，要求描述按输入顺序逐帧返回，并校验充分性和序号后映射回真实引用。联合协议有独立的资源证明和缓存身份。单次内容判断中的原样请求复用同一 Provider 的精确 token 计数。点赞或收藏判断失败时暂缓对应动作。

实验视觉默认关闭，不随自动化总开关启用。受信任的应用装配代码可通过`create_app(video_evidence_factory=...)`向同一Runtime挂载Provider；默认仍使用disabled实现，不自动下载权重或选择模型。`ApiVideoEvidenceProvider`须完成真实投影器／窗口／多图探测并取得匹配配置的资源证明；每次生成重新核对服务身份。资源证明验证视觉资源能力，模型语义诊断单独保留，不替代操作者的发送权限。视觉生成和计数探针共用生成调度与实际计量；只读预览另外受其显式父轮预算及期限约束，取消须回收所属任务。视觉派生缓存须匹配当前Provider id／version及准入状态；更换Provider后只共享原CC，需要画面时重新观察，不把其它模型的caption交给当前模型。补读更新任务材料与来源版本，且不延长所复用CC的原失效时间。

默认优先读取CC；无有效CC时，或内容判断明确要求coverage_required=visual且本任务尚无视觉材料时，在实验开关和Provider能力均有效的条件下读取实际视频帧。后者最多补读一次，保留原CC并追加当前Provider的视觉材料，沿原任务重新判断，只读预览仍受其显式父轮预算与期限约束；保留补读前判断和补读状态，仍需画面时不循环、不强迫发言。interest表示参与话题的兴趣，like包括吐槽、共情和分享；worth_commenting表示有具体想说的话。内容判断同时接收本次片段的source_kinds／has_visual及材料coverage；coverage_required表示仍需补充的内容，provided表示当前材料够用，visual表示需要新的画面，unread_part表示需要其它分P，已有视觉观察与字幕均可作依据。B站适配器使用指定BV／CID的videoshot、真实秒索引和经核验的分P时长，从有界CDN拼图裁切，不下载完整视频或使用封面冒充画面。索引首项为哨兵，后续项才对应tile；JSON与二进制索引须一致。记录请求时间、实际时间、图像及拼图内容身份、帧／像素／总字节上限。视觉Provider顺序对每张单图生成自然观察，由后端立即绑定真实frame ID／CID／时间；再仅用这些观察和当前问题生成sufficient、使用的整数序号、自然摘要与limitations小结构，序号严格检查唯一、类型及范围，映射回现有公开证据输出。可回答性保留模型自评，不以文字词表或观察非空替代；相同场景可使用相同描述。每个阶段共享计量和生成调度；只读预览另外受显式截止时间约束，并在阶段间让出锁；服务身份改变撤销探测与准入。调用图版本进入identity，旧资源证明不适用于新逐帧协议。程序继续校验体积、真实来源和资源身份，观察内容按实际画面审核。

补读根据内容判断选中的原字幕确定一个分 P 和最多三个时码，缓存按补读来源和取样协议隔离。本轮已有取样画面时，内容判断的结构化选项移除再次补画面，仍可根据现有材料暂缓。顶层评论可同时看到被选片段和同一分 P、时码重叠的字幕或画面观察。正文按实际使用的来源引用，草稿保存经短编号解析后的原始引用。llama.cpp 顶层评论启用长重复序列惩罚，台词仍由角色按情境决定篇幅。实质性复读进入审核。

视觉Provider可独立设置思考开关、输出额度与超时；llama.cpp的显式思考设置进入实际请求。`sampling`子配置支持temperature、top_p、top_k、min_p、presence_penalty、repeat_penalty、seed及reasoning_budget_tokens；温度默认0.2，其余默认None，显式temperature=None时也沿用服务默认。仅llama.cpp适配发送非None值，思考预算放HTTP顶层，思考开关放chat_template_kwargs；完整sampling进入资源配置身份。超时默认60秒，可按实测配置至600秒，只读预览另受其当前轮预算和截止时间约束。

管理接口沿用本机认证与同源写保护；运营设置展示实际账号、OC及允许的通道和发送方式。支持预览、审核编辑／拒绝、只读重读、停止和诊断。运营活动中的私信记录只取当前账号与OC，供操作者查看，不进入公开来源或公开模型上下文。报告从数据库事实生成，不作为额度或防重依据。

## 验证边界

受控平台测试覆盖行为和故障；真实模型另查事实、对象、渠道、重复及结构，不把合法JSON当语义正确。平台读取、图像理解、模型资源和真实写入分别验收；取帧成功不证明模型看懂，局部帧不证明看过完整视频。发送遵守操作者在运营设置中明确选择的自动或审核权限，诊断不会伪写成验收通过。


以下七项为当前主线必须满足的验收条件；未取得目标部署证据的项目保留待验状态，不改变契约：

1. 整批略过不增加观看次数，等待正常检索间隔，不高速重搜同批。
2. 选看任务首次开始只计一次；看完不回复仍保存已看状态及不发言原因，部分材料不冒充完整读完。
3. 回访已看视频先读最新评论，再接持久旧页游标；进入回复通道，不占新视频份额。主回复按账号＋OC＋BV跨版本防重，新增评论按真实目标ID处理。
4. 每个视频每日回复名额独立，主评与楼内成功回复合计；草稿操作不占成功数，未知回执先核对。
5. 网络中断、手动暂停和服务重启后继续原批次、材料与各自进度，不重复观看计数、原判断或提交。
6. 评论与私信持续到来时仍按2∶2∶1及空闲借用给新视频处理机会；同楼有序，独立讨论可并发准备。
7. 同一自动批次超过16次模型调用仍可继续，不制造隐藏累计调用／token或整批期限检查点；单次窗口、输出和明确取消继续生效。
