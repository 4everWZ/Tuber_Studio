# 运营任务继续契约

本规范维护评论、私信、动态与浏览回应共用的反馈迭代、检查点、计量及发送恢复。台词篇幅由[评论运营](comment-operations.md)维护，公开／私信隔离及各渠道的来源资格仍由各自规范维护。

## 生成与修订

评论、私信、动态及浏览回应复用持久化ContinuationCoordinator。明确的平台业务拒绝保留原提交和真实code／message，作为外部任务数据交给模型决定修订、暂缓或放弃；修订沿原账号、OC版本、渠道、收件人、root／parent和原始来源，生成阶段不接受模型改写这些绑定。新增补读材料属于上下文与证据，原始绑定保持。正文修改遵循原审核策略，人工发布产生的修订仍待审，自动发布只在原权限、额度与来源检查继续有效时推进。图片私信修订明确记录图片／文字选择，图库ID及实际文件由后端核验，图片不冒充纯文字发送成功。动态保留正文与最多一张原配图。

结构或引用生成失败同样带原始可见输出与具体校验反馈进入后续迭代，保留原schema和本次允许引用。finish_reason=length、空正文、控制字符及不完整结构不当作完成；正文篇幅由情境决定，沿生成预算、实际窗口和256KiB UTF-8本地资源边界校验。已通过校验的重复文风可由模型选择keep，缺失来源或已被平台拒绝的提交不能用keep跳过失败。

平台明确拒绝后，人工可以在Agent暂缓时自行改稿并重新审核。当前稿已获人工批准、payload确有变化、原绑定仍有效且没有在途恢复者时，后端沿原意图签发一次性人工修订票据，再执行原服务的审批与发送检查；不强制先调用模型。相同旧稿及未知发送状态没有这条修订资格。

## 预算与检查点

检查点表示进度保留，生成、来源或容量失败仍显示错误；模型主动选择wait或abandon才记录正常暂缓。

OperationsPolicy.max_recoveries默认8，可配置0..64，0关闭自动恢复；计数针对一个episode，父轮预算、截止时间与取消优先。初次生成和恢复均计入实际请求，标准Provider沿自己的计量，旧自定义Provider使用统一预占适配，避免双算。无父轮时默认最多32次请求、1Mi输入tokens，输出总额为32×本任务有效max_tokens并封顶2Mi tokens；原生计数只读，远端生成型计数探针也算请求，实际usage按已有结算语义退还预占。预算不足留下可继续的检查点，新授权episode保留旧记录并记录新limits／deadline，不给在途episode悄悄扩额。完整trace持久保留；模型工作包编译为原输出、当前候选、最近失败、有效补读与紧凑历史统计，必要时只摘要旧模型输出，原始来源与证据保持完整。记录仅使用可见content与usage，不保存思维链。

## 回执与管理接口

认证管理API提供GET／PUT /api/operations/recovery-policy和POST /api/operations/continuations/{channel}/{local_id}/resume。恢复由原服务重新核验目标、来源与角色。未知发送分支只读核对原账号／目标／正文及真实回执；唯一正向命中追加resolution并完成本地记录，not_found、unsupported或核对失败保留未知。已保存正向resolution后本地记录失败，可再次只读核对并幂等完成本地记录，独立保留当前可见性。生成检查点可经原任务队列以只读预览继续。
