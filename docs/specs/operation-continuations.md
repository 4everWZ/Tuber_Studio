# 运营任务继续契约

本规范维护评论、私信、动态与浏览回应共用的反馈迭代、检查点、计量及发送恢复。台词篇幅由[评论运营](comment-operations.md)维护，公开／私信隔离及各渠道的来源资格仍由各自规范维护。

## 生成与修订

评论、私信、动态及浏览回应复用持久化ContinuationCoordinator。明确的平台业务拒绝保留原提交和真实code／message，作为外部任务数据交给模型决定修订、暂缓或放弃；修订沿原账号、OC版本、渠道、收件人、root／parent和原始来源，生成阶段不接受模型改写这些绑定。新增补读材料属于上下文与证据，原始绑定保持。正文修改遵循原审核策略，人工发布产生的修订仍待审，自动发布只在原权限、额度与来源检查继续有效时推进。图片私信修订明确记录图片／文字选择，图库ID及实际文件由后端核验，图片不冒充纯文字发送成功。动态保留正文与最多一张原配图。

结构或引用生成失败同样带原始可见输出与具体校验反馈进入后续迭代，保留原schema和本次允许引用。finish_reason=length、空正文、控制字符及不完整结构不当作完成；正文篇幅由情境决定，沿生成预算、实际窗口和256KiB UTF-8本地资源边界校验。已通过校验的重复文风可由模型选择keep，缺失来源或已被平台拒绝的提交不能用keep跳过失败。

平台明确拒绝后，人工可以在Agent暂缓时自行改稿并重新审核。当前稿已获人工批准、payload确有变化、原绑定仍有效且没有在途恢复者时，后端沿原意图签发一次性人工修订票据，再执行原服务的审批与发送检查；不强制先调用模型。相同旧稿及未知发送状态没有这条修订资格。

## 预算与检查点

大肥鱼在刷视频回应、动态评估、评论草稿和私信草稿中可自行决定是否读一个公开 HTTPS 网页。私信与评论一样，由模型按任务需要选择公开HTTPS页面，不要求当前来信先带链接。工具链接字段在原生解码与请求前校验中共用2048字符上界，不允许无界枚举耗尽正文额度。模型直接返回原任务结果时只执行一次生成。选择读取后，DNS、最多两次重定向与取材共用 3 秒，逐跳核验公网地址，最多读取 128 KiB，并把最多 720 字符的摘录或读取状态交给一次后续生成。直播不开放该工具。网页摘录补充本轮上下文，任务记录保存读取状态、成功来源和耗时。字幕／画面引用、动态公开来源、私信收件人和发送授权继续由原任务校验。

检查点表示进度保留，生成、来源或容量失败仍显示错误；模型主动选择wait或abandon才记录正常暂缓。自主浏览的重复诊断或单请求输出耗尽后，若模型已明确选择wait／abandon并给出具体理由，本次目标可正常收尾，不让整批停在检查点，不发布残缺正文；原候选、反馈与模型决定保留在详情。wait保留后续评论回访的资格，不伪装成永久skip或不喜欢；abandon可略过该目标。不同批次再次遇到已明确暂缓的评论时开启新生成episode并保留旧审计，同批恢复不重新初答；新episode在事务内复核原状态、父轮变化和真实模型决定。已看视频保留观看进度与主决策wait，后续自动回访仍处理评论，不因此重新生成主评。没有明确模型决定的网络中断、容量或来源失败仍保存可恢复检查点。修订后若再次耗尽输出额度，或原样返回带同一文风诊断的候选，暂停本轮自动恢复并保留可见原答和反馈。操作者仍可继续检查点。生成在得到任何原答或候选之前被取消时，恢复从原始生成继续；已有输出才进入相应修订步骤，不要求模型修订一份不存在的草稿。公开任务详情同样使用既有生成记录的公私域判定；私信候选及未解析输出只给私信工作区入口，原始输出不泄露到公开任务payload，审计原件保持。

OperationsPolicy.max_recoveries默认8，可配置0..64，0关闭自动恢复；恢复次数按一个episode内有效修复策略计算，不把正常观看、翻评论或工具行动算成整批恢复次数。默认episode的累计模型调用、输入与输出上限均为0（不限），deadline为None（无整批期限）。自动视频、公开互动、独立私信和动态不能经恢复层重新受到隐藏的32次请求、1Mi输入或30分钟截止限制。显式只读预览的父轮预算／期限、单次max_tokens、真实上下文、Provider请求超时和明确取消仍生效。

初次生成、恢复和生成型计数探针均记录实际用量，标准Provider沿自己的计量，旧自定义Provider使用统一预占适配，避免双算；原生计数只读，实际usage按既有结算语义退还预占。显式预算不足或修复未完成时保留可继续检查点，新授权episode保存旧记录及本次limits／deadline。升级只迁移可准确识别的旧内置默认累计上限和隐式期限，不覆盖用户明确配置的不同限制。完整trace持久保留；模型工作包编译为原输出、当前候选、最近失败、有效补读与紧凑历史统计，必要时只摘要旧模型输出，原始来源与证据保持完整。记录仅使用可见content与usage，不保存思维链。

## 回执与管理接口

认证管理API提供GET／PUT /api/operations/recovery-policy和POST /api/operations/continuations/{channel}/{local_id}/resume。恢复由原服务重新核验目标、来源与角色。未知发送分支只读核对原账号／目标／正文及真实回执；唯一正向命中追加resolution并完成本地记录，not_found、unsupported或核对失败保留未知。已保存正向resolution后本地记录失败，可再次只读核对并幂等完成本地记录，独立保留当前可见性。生成检查点可经原任务队列以只读预览继续。
