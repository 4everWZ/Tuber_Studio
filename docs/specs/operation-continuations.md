# 运营任务继续契约

本规范维护评论、私信、动态与浏览回应共用的生成结果、检查点、计量及发送恢复。台词篇幅由[评论运营](comment-operations.md)维护，公开／私信隔离及各渠道的来源资格仍由各自规范维护。

## 生成与修订

评论、私信、动态及浏览回应复用持久化ContinuationCoordinator。明确的平台业务拒绝保留原提交和真实code／message，作为外部任务数据交给模型决定修订、暂缓或放弃；修订沿原账号、OC版本、渠道、收件人、root／parent和原始来源，生成阶段不接受模型改写这些绑定。新增补读材料属于上下文与证据，原始绑定保持。正文修改遵循原审核策略，人工发布产生的修订仍待审，自动发布只在原权限、额度与来源检查继续有效时推进。图片私信修订明确记录图片／文字选择，图库ID及实际文件由后端核验，图片不冒充纯文字发送成功。动态保留正文与最多一张原配图。平台修订模型自身返回无效结构或耗尽输出时立即保留诊断；完整但有正文诊断的新稿只待人工审核，不因旧稿获准或存在修订票据而自动提交。账号身份更新后重新生成的新稿同样遵守这条审核边界。

生成与平台拒绝修订使用同一持久协调器，但不共用自动修补循环。每次生成只有一次任务结果；按需web fetch仍是一次读取和一次结果生成，不属于错答补救。结构、来源引用或finish_reason校验失败进入`invalid`，保留可见原答和具体错误，不追加反馈决策、改稿或跨轮自动重生成。结构有效但存在复读或内部引用泄露的完整候选进入`awaiting_review`，原文可编辑审核，不能自动发送；生成审计记录不等于审核通过。有效模型主动暂缓进入`deferred`，其它有效结果进入`completed`。正常口癖和玩梗不因措辞被改写。正文仍沿单次输出预算、真实窗口和256KiB UTF-8本地资源边界校验。

平台明确拒绝后，人工可以在Agent暂缓时自行改稿并重新审核。当前稿已获人工批准、payload确有变化、原绑定仍有效且没有在途恢复者时，后端沿原意图签发一次性人工修订票据，再执行原服务的审批与发送检查；不强制先调用模型。相同旧稿及未知发送状态没有这条修订资格。

## 预算与检查点

大肥鱼在刷视频回应、动态评估、评论草稿和私信草稿中可自行决定是否读一个公开 HTTPS 网页。私信与评论一样，由模型按任务需要选择公开HTTPS页面，不要求当前来信先带链接。工具链接字段在原生解码与请求前校验中共用2048字符上界，不允许无界枚举耗尽正文额度。模型直接返回原任务结果时只执行一次生成。选择读取后，DNS、最多两次重定向与取材共用 3 秒，逐跳核验公网地址，最多读取 128 KiB，并把最多 720 字符的摘录或读取状态交给一次后续生成。直播不开放该工具。网页摘录补充本轮上下文，任务记录保存读取状态、成功来源和耗时。字幕／画面引用、动态公开来源、私信收件人和发送授权继续由原任务校验。

真实网络中断、取消和容量不足保存`checkpoint`／`cancelled`，恢复时继续原来源的一次生成；它们不冒充有效模型判断。`invalid`、`deferred`与`awaiting_review`是本次自动生成的终态，相同来源和生成绑定不会因更换父轮或重启重新调用模型。操作者可对可继续的原任务显式开启一次新episode；已有待审候选直接沿原草稿编辑审核。旧修补循环中的无效原答保留诊断，不从恢复动作推导视频偏好、主回复或实际发言。观看、评论和私信分别保存进度；无效候选不阻塞其他视频或讨论楼。公开任务详情沿用既有公私域判定；私信候选及未解析输出只给私信工作区入口，原始输出不泄露到公开任务payload，审计原件保持。

OperationsPolicy.max_recoveries默认8，可配置0..64，0关闭平台明确拒绝后的自动修订；该设置不用于生成错答补救，恢复次数按一个episode内有效平台修复策略计算，不把正常观看、翻评论或工具行动算成整批恢复次数。默认episode的累计模型调用、输入与输出上限均为0（不限），deadline为None（无整批期限）。自动视频、公开互动、独立私信和动态不能经恢复层重新受到隐藏的32次请求、1Mi输入或30分钟截止限制。显式只读预览的父轮预算／期限、单次max_tokens、真实上下文、Provider请求超时和明确取消仍生效。

初次生成、恢复和生成型计数探针均记录实际用量，标准Provider沿自己的计量，旧自定义Provider使用统一预占适配，避免双算；原生计数只读，实际usage按既有结算语义退还预占。显式预算不足或修复未完成时保留可继续检查点，新授权episode保存旧记录及本次limits／deadline。升级只迁移可准确识别的旧内置默认累计上限和隐式期限，不覆盖用户明确配置的不同限制。完整trace持久保留；模型工作包编译为原输出、当前候选、最近失败、有效补读与紧凑历史统计，必要时只摘要旧模型输出，原始来源与证据保持完整。记录仅使用可见content与usage，不保存思维链。

## 回执与管理接口

认证管理API提供GET／PUT /api/operations/recovery-policy和POST /api/operations/continuations/{channel}/{local_id}/resume。恢复由原服务重新核验目标、来源与角色。未知发送分支只读核对原账号／目标／正文及真实回执；唯一正向命中追加resolution并完成本地记录，not_found、unsupported或核对失败保留未知。已保存正向resolution后本地记录失败，可再次只读核对并幂等完成本地记录，独立保留当前可见性。生成检查点可经原任务队列以只读预览继续。
