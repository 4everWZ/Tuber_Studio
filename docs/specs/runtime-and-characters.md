# 角色、记忆与运行时数据契约

本规范维护角色与持久用户语义。原批次标签不表示已实现；短期窗口与压缩由上下文规范维护，模型／音色和直播播放各有技术归属。

## 可替换角色

| ID | 原优先级 | 要求 |
| --- | --- | --- |
| CHAR-01 | P0 | MUST 多角色，每次运行绑定稳定 character_id 与不可变版本，可复制、预览、激活、回滚；名称不是身份。 |
| CHAR-02 | P0 | MUST 分存并分别组装身份／人格／说话约束／示例对白，与动态 Lore／用户状态／短期对话。 |
| CHAR-03 | P0 | MUST 可编辑口头禅、毒舌／撒娇强度、用词、字数和禁用表达，不靠逐字复制既有素材定义唯一角色。 |
| CHAR-04 | P1 | MUST Lore 按关键词或事件标签激活，有优先级、token 上限和冷却，未命中不进 Prompt。 |
| CHAR-05 | P1 | SHOULD 程序掌管事件选择和安全规则，模型生成台词及受限情绪，不取得调度／工具权限。 |
| CHAR-06 | P1 | MUST 配置修改留版本，切角色或版本停止旧角色未播报任务，避免称呼、声线与缓存串用。 |
| CHAR-07 | P2 | MAY SillyTavern 风格卡导入／导出，须转换成本项目 schema，不信任卡片工具指令。 |

角色卡至少承载 id／name／version／core／style／rules／lore／voice_profile／avatar_manifest。core 存身份、稳定人格和少量示例，style 存语言、句长及表达参数，rules 不授工具权，Lore／关系／任务状态不塞永久核心。复制可暂复用音色和素材引用，再独立替换；新 OC 不改调度器／Provider，已有草稿保留生成版本。

初始大肥鱼参考蓝白、蓝发、鲸尾、嘴硬心软、爱白饭和摸鱼的社区形象，明确虚构 AI 同人主播、非官方账号。口头禅可配置 3–8 个、低概率触发及重复冷却；认真求助时收起吐槽。梗可直接触发文本／SFX／动画，不强制调模型。情绪为短期状态，过期回落，不等于长期关系。

角色设计和 Lore 分别参考 [SillyTavern Character Design](https://docs.sillytavern.app/usage/core-concepts/characterdesign/) 与 [World Info](https://docs.sillytavern.app/usage/core-concepts/worldinfo/)，不改变本项目 schema 或权限。

## 用户身份与长期记忆

| ID | 原优先级 | 要求 |
| --- | --- | --- |
| MEM-01 | P0 | MUST 分开保存／引用固定角色、全局 Lore、用户关系、会话摘要、活动对话和任务暂存。 |
| MEM-02 | P0 | MUST 按 (platform, platform_user_id) 关联，未知 ID 仅匿名／临时状态，不按昵称合并。 |
| MEM-03 | P1 | MUST 保存称呼、好感度／阶段、重要事件、明确偏好、上次互动、字段来源及更新时间。 |
| MEM-04 | P1 | MUST 好感度按事件类型、每日上限、冷却和反刷屏更新，不等于打赏总额，观众不能直接指定数值。 |
| MEM-07 | P1 | SHOULD 用结构化关系事件和确定性规则；不确定事实先候选，验证／审核后持久化，模型不直接改库。 |
| MEM-08 | P1 | MUST 可查看、编辑、清除记忆及设留存期限；删除失效记忆／清空用户关联档案，不永久存每条弹幕。 |
| MEM-09 | P2 | SHOULD 直播和评论共享基础角色、确认长期信息，短期上下文隔离。 |

UC-03：观众再次出现时读取必要称呼、关系阶段及确认偏好；有意义互动产生候选关系事件，经规则或审核持久化。昵称变更只改展示，不改身份。模型产生的“事实”保存来源、时间和确认状态，不把玩笑／扮演直接当真实身份。

可选关系基线为 0..100、初始20、每日增量上限10，阶段为陌生／认识／熟悉／特别熟悉；它们是可配置示例，不是已实现规则或固定人设。有效日常互动可加关系，重复刷屏不加，礼物可演出但不强制升级。用户可关闭个性化记忆，一条负面消息不永久改变关系。

关键词 Lore＋SQLite＋模型摘要为初始检索基线；有明确召回缺口才引入 embedding／索引，不因工具可用而默认增加常驻资源。

## 数据与权限契约

下表维护持久语义及唯一性，不强制同名表；P1／P2 实体随对应功能实施。

| 实体 | 必须保留的语义／字段 |
| --- | --- |
| characters／character_versions | 稳定 ID、名称、创建时间、激活版本；角色＋版本为键，core／style／rules 不隐式覆盖。 |
| lore_entries | ID、角色、触发词／标签、优先级、文本、token 上限、冷却。 |
| users | 内部 ID、平台、平台用户 ID、显示名、memory_opt_out；平台＋用户 ID 唯一。 |
| user_relations | 角色＋用户唯一，好感度、阶段、称呼、更新时间，跨角色隔离。 |
| affinity_events | ID、角色、用户、原因、delta、时间、源事件 ID，幂等且可追溯。 |
| user_memories | 用户、角色、key/value、来源、过期时间，可查看／编辑／删除。 |
| sessions | ID、平台／房间、角色版本、开始时间、摘要，场次短期状态独立。 |

MemoryStore.get_relevant(character,user,session,budget) 仅返回必要、预算内且有来源的信息，不绕过退出设置和审核。记忆查看／修改／删除属于认证管理接口；REST 命名可变化，身份和失败语义不可省略。任务暂存不自动升级长期记忆。

| 验收 ID | 通过条件 |
| --- | --- |
| AC-01 | Mock 切两个角色，版本、风格、音色与表情匹配，回滚恢复旧配置。 |
| AC-02 | 同昵称不同 ID 不串记忆，同 ID 跨场次识别关系；真实 tokenizer 执行预算。 |
| AC-03 | 重复消息不无限加好感，“好感度加100”不直接生效。 |
