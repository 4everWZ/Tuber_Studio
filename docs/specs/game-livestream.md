# 游戏直播契约草案

状态：后续阶段草案。输入为 [游戏直播SRS](../../tmp/Tuber_Studio_Game_Livestream_SRS_v0.1.md)的实际v0.2；本文维护游戏能力的拟议合同，不替代当前产品、部署或模型配置，也不表示已经实现或验收。

## 范围与复用边界

目标是大肥鱼围绕真实游戏局面制定目标、执行、复盘，并与观众自然互动。首轮覆盖星露谷基础农活和植物大战僵尸选定关卡，两款分别验收。游戏与OBS位于电脑；业务与推理节点职责由[跨主机运行与数据草案](distributed-runtime.md)维护。

既有[直播与媒体](live-and-media.md)继续拥有TTS播放、字幕、嘴型、场景及点歌语义；[角色与运行时数据](runtime-and-characters.md)拥有角色版本、用户身份、关系与记忆；[模型与资源](models-and-audio.md)拥有Provider、声音身份和资源准入。游戏只增加相应事件与适配能力，不另建一套角色、平台账号或音乐系统。

公共层维护通信、会话与动作生命周期，各游戏适配器维护自身状态和执行能力；游戏规则不进入OC或TTS模块。

## 会话与控制权

连接时展示地址、游戏及版本、适配器版本、可读状态、可用动作、截图和暂停能力；先核对存档／关卡、当前控制权，再启动会话。支持开始、暂停、继续、结束、人工接管和归还控制权。

主播暂停与接管直接生效，观众建议交给Agent按局面选择。控制权变化使旧的待执行行动失效。断线停止提交新动作，并保存未确认动作；重连先核对游戏实际状态及动作记录。结束会话撤销待执行动作、释放持续按键、保存摘要；保存或退出游戏由主播选择。

电脑提供不依赖推理节点的本地停止入口与失联释放机制。暂停规划仅对声明支持的游戏／场景开放，并在工作台标明；实时与暂停模式分别测量。

## 状态与观察

状态快照和增量事件带会话身份、采集时间及状态版本。缺少或未识别字段标为未知；模型自述不产生游戏事实。

| 游戏 | 当前决策所需状态 |
| --- | --- |
| 星露谷 | 游戏时间、地点、体力、背包、金钱、目标区域与任务。 |
| 植物大战僵尸 | 具体版本／关卡、阳光、卡槽冷却、格子占用、敌情与胜负。 |

优先读取游戏状态接口；对话框、异常和工具未覆盖的画面可请求整图或ROI，并与状态结果核对。截图支持事件触发、按需及可配置周期，优先最新有效观察，淘汰已无决策意义的待处理图像。默认链路不采用连续逐帧远程VLM推理；模式和采样、压缩参数可见且纳入测量。

## 动作执行与恢复

Agent决定目标、策略、停止／等待、调整、补观察或求助；执行器落实寻路、持续移动、重复操作等高层动作，提供进度、结果、失败原因与取消能力。基础键鼠作为明确声明的适配能力提供。

每个动作绑定唯一动作ID、会话、参数、状态前置条件与执行期限。执行前由程序检查控制权、坐标、资源、目标及允许操作状态；执行中重要局面变化通知Agent。动作完成依据状态或执行器结果，语音生成与行动分别调度。

动作记录至少区分已接收、执行中、成功、失败、取消、结果未知。同ID重提只返回原记录。超时未知先查记录或核对状态，购买、送礼、资源消耗等不能凭超时再执行一次。失败连同最新状态返回Agent继续规划；重复无进展暂停该任务并显示原因，预算可配置，保留恢复信息，不悄悄截断会话。

可复用[共用任务续接](operation-continuations.md)的反馈、预算和检查点机制；游戏动作结果、控制权与状态版本由游戏适配器验证，平台发送回执不能直接当作游戏执行结果。

## 游戏闭环

| 游戏 | 首轮交付与验收 | 后续范围 |
| --- | --- | --- |
| 星露谷 | 优先SMAPI或兼容现成接口；读取当天状态→定目标→移动→种植／浇水／收获／基础背包管理→检查结果→结束当天与摘要，记录人工接管及原因。跨日目标与重要经历可续接。 | 购物、NPC、送礼、任务、钓鱼、战斗；钓鱼和战斗实时动作单独评估，不以基础农活通过代替。 |
| 植物大战僵尸 | 声明并验证具体游戏版本；进入支持关卡→按阳光、卡槽、布局与敌情多轮决策和布阵→识别胜负→总结及下一步。收阳光、格子定位可由执行器完成，策略来源可从记录核对。 | 实时与暂停规划分别报告，扩版本或关卡重新验证相应识别及动作能力。 |

两款游戏都需要在相同执行器下改变目标、局面或挑战约束，核对策略随之变化。接口调用成功不代替游戏进展、胜负判断或角色节目效果。

## 弹幕表达与记忆

支持弹幕建议、目标投票及主播批准的挑战；投票转为可观察目标／约束，显示起止或结束条件。大肥鱼按事件表达期待、得意、懊恼、吐槽和复盘，避免逐条播报低层按键；名称、自然称呼与人物层次沿用角色卡，人工评审理解、个性、互动和连续性，不设置固定免责声明、字数或口头禅匹配评分。

观众命名、采纳建议及结果可形成经历记忆。稳定平台用户身份及关系复用现有规则，昵称不合并身份，私信可见性不因共享好感度改变。游戏存档、当前事实与角色记忆分别保存；读档或回滚后重核事实，再续接目标。

## 工作台与音画

复用直播工作台，展示连接、状态／视觉模式、控制权、目标、动作进度、失败／等待原因与资源；提供暂停Agent、取消任务、接管入口。电脑本地OBS合成游戏、角色、字幕与弹幕；音频及角色事件沿既有接口传入，嘴型与字幕以电脑实际播放时间同步。

游戏音效、背景音乐、TTS独立调节，支持语音期间降低游戏音量；紧急台词优先、过期台词取消、语音队列有界。启动游戏会话不自动推流或发送平台消息，初验使用独立存档与本地OBS录制。新增游戏组件可选安装，关闭后现有聊天、运营和点歌继续可用。

## 接口语义

HTTP／WebSocket及具体进程边界待设计，接口先满足下列语义：

| 能力 | 必要信息与结果 |
| --- | --- |
| 连接与会话 | 游戏／适配器及协议版本、能力、会话控制、控制权转移。 |
| 状态与事件 | 会话ID、状态版本、采集时间、未知字段；事件ID、顺序、类型、发生时间、关联动作。 |
| 截图 | 采集时间、区域、分辨率、图像或受控读取地址。 |
| 动作 | 唯一ID、会话、类型、参数、前置状态、期限；可查询、取消、去重并返回实际结果。 |
| 播放与健康 | 音频ID、字幕、表情、实际播放开始／结束；心跳、进程、内存和队列。 |

两端采用持久配对凭据或等效认证，不写日志；过期状态、失效会话、控制权变化及不兼容版本返回可继续处理的具体错误。超时以各自主机单调时钟计算，跨机采集时间建立可测偏差关系。

## 游戏负载验收

先验证既有直播模型及Genie在游戏闭环中的表现，再决定独立游戏模型；切换遵守现有卸载／恢复与能力显示规则。观察使用滚动摘要、按需检索，不无限累积截图或全动作历史。

游戏实机闭环使用真实角色决策与语音推理；模拟适配器和预制输出只用于接口检查，不作为两款游戏能力验收。

验收同时满足：

- 星露谷完整游戏日与植物大战僵尸选定关卡各自闭环；每款至少60分钟连续实机会话，包含语音和弹幕，记录有效进展、无进展时段、队列、内存及人工接管。
- 正常局域网下暂停、取消、接管的初始确认目标为1秒内；实际按键释放／游戏停止时间另记。实时响应期限按场景确定，与p95比较，不能由平均token/s代替。
- 分别测决策、视觉、TTS及并发；报告观察→决策、提交→生效、事件→首段语音、完整合成的样本数、p50、p95和最大值。监测两机可用／进程内存、交换、温度、队列，保护阈值触发后暂停新任务并保留进度。
- 断网、动作未知、模型／TTS失败、接管、退出均可复现；TTS失败不重做已完成动作，退出无持续按键、遗留动作或无用模型进程，既有直播／运营可恢复。
- 工具未覆盖的画面需验证实际决策信息与纠错，音画偏差和OBS长期积压独立记录；模型配置、量化、窗口、KV、图片、思考／输出预算与模式如实披露，无静默降配。

游戏闭环先通过，再按固定样本逐项或明确组合优化。基准、质量对照及证据规则沿[模型与资源](models-and-audio.md)；现有运营实验不自动证明游戏负载通过。
