# 评论运营契约

首版优先评论浏览、导入、分类、草稿与默认审核，以下原P2标签保留以追踪输入；完整聚类／map-reduce／运营摘要等条目仍是未来验收目标，不表示已全部实现。

## 输入、分类与批次

运营正文按交流情境决定篇幅，角色style的min_chars／max_chars仅用于直播台词，不作为评论、私信或动态的生成／审核硬限。三者共用llm.operations_max_tokens，默认8192，可显式设置1–65536，实际输入与输出预留仍须满足真实窗口；直播llm.max_tokens与120字Reply结构独立保留。运营使用OperationReply与既有结构化Provider，账号、来源与事件引用继续由程序校验。finish_reason=length或空正文不作为完成输出；大量重复长段交由Agent结合表达意图选择保留、修订或暂缓，保留原文，不用口癖或自然笑声判失败，不因正常长文自动缩写。

生成、审核及发送适配器采用统一256KiB UTF-8正文资源边界，不把原有100／120／500／1000字本地数值宣称为B站平台限制。平台明确拒绝与发送结果不确定分别记录，正文不做程序截断。网页完整保留正文供编辑；私信正文只在私信区域展示。

生成错误、平台反馈修订、检查点继续与未知发送核对沿[运营任务继续契约](operation-continuations.md)，继续保持评论来源与原有审批方式。

| OPS-02 | P2 | MUST 按视频、时间、用户和话题去重／过滤／聚类，产生待回应、一般互动、问题、建议／投诉、垃圾等可编辑分类。 |

UC-04：读取／导入指定视频评论 → 受限批次清洗、归类／聚类和筛选 → 角色候选回复 → 默认审核／编辑／选择发布 → 保存回执；无写权限提供复制。人工批次与自动策略的来源必须可区分。

读取B站热门公开视频，接受BV／av／标准视频链接及顶层评论；外站、短链、非法资源不能成为任意URL请求。认证、权限、平台风控失败可见，不伪成功。以平台＋视频＋评论ID去重，以平台＋用户ID识别观众，不按昵称合并。授权的PlatformConnector.publish_comment(...)返回Receipt；接口可替换，不能从读取成功推断具备写权限。

单批导入1–1000条，先规范化预览前10条并显示总数，预览不写入。field_mapping为目标→来源字段名，支持comment_id／platform_user_id／display_name／content／like_count／created_at，标准字段不必映射。修改数据／映射使旧预览失效；错误保留输入。分类为question／suggestion／interaction／spam／general，可筛选和人工修改；人工分类注明operator来源，不被自动重新分类覆盖。

持久语义包括comment_items的平台、视频、评论ID、用户、内容、时间与分类；comment_jobs／drafts的批次、来源ID、输入摘要、角色不可变版本、模型、任务／审核状态及发布回执；job_runs的ID、kind、parent_id、状态、输入／结果引用和错误。重跑不能覆盖既有草稿或重复答复。

## 默认审核与自动策略

正常状态为 imported → analyzed → drafted → pending_review → approved/rejected → published/copied。生成草稿不等于已审核，通过／复制不等于已发布。手工发布可另存Operator完成标记，不冒充API回执。重启恢复待审核草稿，取消未完成批次而不假称完成。

auto_browse和auto_reply均默认false。自动浏览委托[自主浏览与互动](autonomous-browsing.md)调度：指定BV按显式来源处理，空词默认首页推荐，不自动换成热门。视频自动回复必须有有效CC／获准视觉证据。轮询至少60秒、默认300秒；渠道每小时／每天上限默认5／20，还受全账号共享额度与同用户冷却约束，失败和不确定尝试均计数。

独立auto_reply保持显式授权；自动化总开关通过可撤覆盖启用新模式候选，基础策略仍可编辑。旧手工草稿不追发；模型语义未通过时自动化候选保留审核。凭证不证明平台写权限，无SESSDATA／bili_jct不能开启自动回复；凭证仅写本地受限runtime，不回显或放Prompt。紧停跨独立渠道生效，提交中的HTTP只收取回执。

每次发布尝试只发一次平台写请求。成功码和有效评论ID同时存在才published并保存回执；明确拒绝保留原草稿及原因。超时、非JSON、无有效回执、发送中取消／重启、平台成功但本地记账失败均为publish_uncertain或不可重发状态，先只读核对平台。已发布／发送中／不确定草稿不可编辑、覆盖或直接重发。

### 只读回执核对

评论适配器按原oid、type、root、parent读取首屏20条，直接核验原始楼层字段、作者UID和实际发送正文；存在原rpid时只认该ID，无rpid时还须满足发送开始时间并唯一匹配。缺失root／parent不能用读取预览的回填逻辑补猜。type=1视频和type=17动态评论共用此规则，既有视频标识可先读取并验证其aid。

私信先读取当前登录UID，确认仍为原发送账号，再只读最近30条会话记录，核验sender、receiver、消息类型、正文、时间及原msg_key。该读取不标记已读。仅有图片草稿说明、没有原图片消息回执时返回unsupported；不拿说明文字匹配图片。动态文本有已知dynamic_id时读取详情，无ID时读取原账号动态首屏20条，核验作者、完整正文、文本类型及发布时间，唯一匹配才确认；缺少可核对的图片载荷时保留unsupported。

核对结果包含真实读取时间和覆盖范围；visible／not_visible且有匹配回执表示已找到对应记录。not_found、ambiguous、check_failed和unsupported不证明未发送，不生成重发授权。此接口仅执行GET，不提交正文、不调用模型；与修订决策、发布授权和前端工作流分别验收。

## 子任务与资源

首版按conversation thread调度：平台＋视频＋顶层楼ID形成独立scope，同楼保持入队相对顺序，每批最多4个楼的异步工作流并发；token计量、模型生成和来源记录仍经过唯一GPU锁。不是把全视频塞进一个子任务，也不为每个逻辑thread加载独立模型。取消收齐所有楼子任务后再结束批次，待批次可取消；草稿与单次发布防重不因并发放宽。

comments保存thread_id／parent_comment_id；B站root标识楼、parent标识目标评论，顶层自身comment_id作楼ID，导入可映射两字段，旧顶层行回填自身ID。只读取公开返回中已有的楼内预览，不声称已抓完全部楼内分页。压缩与占用查询须指定单楼；旧整视频窗口保留但不混入新楼。楼内发布使用对应root和parent，不能改成另一个回复对象。

草稿保留生成版本及answer_check：来源原句、fictional标记、所问字段、缺项、是否已补答与warning，供审核判断；warning不伪装为已拒绝／已发布。偶发遗漏可以作为首版限制，明确问题仍须如实标记不完整，闲聊不强求所有旧事实。

完整OPS批处理按 map → reduce：有界读取／CPU预处理、有限LLMWorker、合并／去重和审核。生命周期 pending → running → completed/failed/cancelled → merged/archived；每项有受限评论集、任务说明、deadline、取消信号、进度及错误，输出引用来源评论ID。主调度器控制资源并合并，子任务不能直接改角色核心或绕过发布策略。

直播生成、待播和当前播放优先；离线模型任务不抢占语音。网络／CPU并发不意味着多份GPU权重，详细模型驻留和全局锁由资源规范维护。评论与直播的短期上下文隔离，经确认长期信息按记忆权限共享。

| 验收 ID | 通过条件 |
| --- | --- |
| AC-11 | 至少1000条Mock评论可去重、分组、产出批次结果，live模式不耗尽模型资源。 |
| AC-12 | 默认生成停待审核；无写权限可复制但不声称发布。显式自动分支另测开关、限额、停止及回执，不能借此绕过默认分支验收。 |

另验映射／预览无写入、人工分类保持、角色／视频隔离、错误与取消／重启恢复、单次写入和不确定结果防重发。真实写入须以配置账号的实际平台回执验证，不能由隔离传输测试推断。

Adapter接口和浏览候选工作流可参考 [dsh-bili-scroll](https://github.com/c1overzz/dsh-bili-scroll/tree/main)，但不继承其权限、代码许可或自动行为；实际平台能力和授权单独核对。

## 评论转私信

启用[私信策略](private-messages.md)后，模型可基于当前公开楼与共享的OC关系数值选择转入私信。公开草稿仅保存private_handoff标记，不能审核／复制成公开回复；私信正文与平台回执在独立工作台维护，不能写回公开楼上下文。自动浏览产生的移交可按显式私信自动发送策略执行，手工批次仍待审核。
