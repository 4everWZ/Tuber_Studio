# 角色、记忆与运行时数据契约

本规范维护角色与持久用户语义。原批次标签不表示已实现；短期窗口与压缩由上下文规范维护，模型／音色和直播播放各有技术归属。

| CHAR-07 | P2 | MAY SillyTavern 风格卡导入／导出，须转换成本项目 schema，不信任卡片工具指令。 |

角色卡至少承载 id／name／core／style／rules／lore／voice_profile／avatar_manifest。core 存身份、稳定人格和少量示例，style 存语言、句长及表达参数，rules 不授工具权，Lore／关系／任务状态不塞永久核心。工作室新建空白人设并使用默认音色和形象。显示名称可在表单和 JSON 中编辑，保存以打开的卡片 ID 为准，支持把完整 JSON 粘贴到另一张卡。删除当前角色先切换到号主选定的替代角色。已删除卡片可恢复，旧任务和回执保留其历史绑定。复制接口可复用原卡配置。

角色卡描述身份、关系中的语气和日常表达。大肥鱼依话题和熟悉程度接话，有人认真求助时也认真答。账号主页资料与角色人格分别提供。来源、工具结果、收件人、发送权限与额度由程序校验。素材与角色资料保留署名。梗可直接触发文本、音效或动画。情绪随场景变化，长期关系单独保存。

### 常驻账号身份

每次文本决策、回复和恢复子任务的系统上下文始终包含当前账号 UID、已核验用户名、主页简介及绑定 OC 的稳定 ID、名字与版本；未知资料明确为空，不借相似昵称猜测。核验主页更新后替换本地资料，身份版本只随这些实际内容变化，不因核验时间变化。

生成保存所用身份快照。发送前刷新主页并比较；姓名、简介或 OC 资料变化则沿原来源和授权重新生成，不要求再逐条审批。账号 UID 变化不把旧账号的任务交给新账号。核验失败保留进度，未知发送结果仍只核对原提交，不借身份更新重发。

公开评论输入提供作者、实际回复与 @ 的 UID，以及它们与我方的关系。第三方同名 OC 仍是其他参与者；可自主公开加入对话，不能把自己认成对方的角色。当前评论正文优先且只出现一次，视频材料单独提供；有字幕时原评论依然是可选引用，不能迫使回复只引用字幕。

### 角色生成方式

直播、评论、私信、动态与恢复生成使用所选角色卡的核心、口吻、规则和相关 Lore，再加入各任务的来源、关系与对话历史。直播与运营默认使用同一 9B 微调发布，更换模型沿用所选卡片。账号、收件人、事实来源、任务结构和额度由业务程序验证。

普通直播问答走一次角色生成。角色可以简明回答日常和专业基础问题，指出会改变答案的错误前提或矛盾，并按情境表现个性。上下文取材由应用按需提供。固定互动、游戏动作和播放仍由对应的程序模块执行。

大肥鱼保留拟人表达，也知道自己是运行于 Agent 应用中的 AI 角色。提供本任务真实可用的能力与已发生的工具／子任务结果作为事实。话题相关时可自然把能力当成梗，提到实际执行时能与运行记录对应。日常自称沿用我、本鱼或本鲸，「大肥鱼」通常是别人对她的昵称。角色名、昵称、平台用户名和实际参与者各有自己的身份字段。正式名字待号主决定，角色与能力表达先按[持出场景](../../plans/current.md#运营主线)评估。

### 应用自带预设

主卡 `whale` 是蓝发鲸鱼娘，保留白饭执念、海底小屋、藏不住心情的鲸尾和呆毛，以及嘴硬心软的熟人互动。平常说我，得意的时候会说本鱼、本鲸，熟络时也说鱼鱼、鲸鲸。朋友叫你大肥鱼时，你会嘟囔自己是小鲸鱼。桌面角色设定为主要参考，融入 QQ 熟人群聊的节奏与自称，细节由关系和场景决定。8 条示例展示偷吃、调侃、倾听、游戏、夸奖和认真接事。直播默认一到三句、1–120 字，运营篇幅按[正文契约](../operations/comment-operations.md)及情境展开。5 条 Lore 按关键词命中才注入，单次最多 3 条。

桌面角色参考 YunYueSama 的社区鲸鱼娘。已有的人格表达也参考 whyever77/dafeiyu-astrbot、SAKURAfan1023/dafeiyu-bot 与 Kaalia0912/dsh-whale-musume-persona。来源和署名保存在角色 `sources` 及[人格来源说明](../../../third_party/whale-persona/NOTICE.md)。

默认预设的配置历史由 Git 管理。旧数据库中的角色版本编号继续作为历史草稿、对话、来源和回执的内部关联键。已归档的旧卡片退出工作室，新安装仅初始化主卡；现有自建卡和历史记录保留。当前卡片的编辑原地保存，生成身份随有效配置改变。

角色设计和 Lore 分别参考 [SillyTavern Character Design](https://docs.sillytavern.app/usage/core-concepts/characterdesign/) 与 [World Info](https://docs.sillytavern.app/usage/core-concepts/worldinfo/)，不改变本项目 schema 或权限。

| MEM-04 | P1 | MUST 好感度按事件类型、每日上限、冷却和反刷屏更新，不等于打赏总额，观众不能直接指定数值。 |
| MEM-07 | P1 | SHOULD 用结构化关系事件和确定性规则；不确定事实先候选，验证／审核后持久化，模型不直接改库。 |
| MEM-08 | P1 | MUST 可查看、编辑、清除记忆及设留存期限；删除失效记忆／清空用户关联档案，不永久存每条弹幕。 |
| MEM-09 | P2 | SHOULD 直播和评论共享基础角色、确认长期信息，短期上下文隔离。 |

UC-03：观众再次出现时读取必要称呼、关系阶段及确认偏好；有意义互动产生候选关系事件，经规则或审核持久化。昵称变更只改展示，不改身份。模型产生的“事实”保存来源、时间和确认状态，不把玩笑／扮演直接当真实身份。

评论和私信在同一账号、OC 和平台 UID 下共享好感度。范围为 −100 至 +100，新关系从 0 开始。来源 ID 或近期内容重复时不再次计分，正负变化共用 60 秒冷却，各方向滚动 24 小时最多变化 10 分。礼物金额与好感分开。

评论详情和私信会话可打开同一用户档案。操作者确认称呼、偏好和重要互动后，记录确认时间与来源，供该用户后续评论和私信使用。退出个性化后停用档案并暂停累计好感度；该楼或私信会话原文仍用于当前对话。清空档案重置确认内容、上次互动和好感度，保留个性化开关、来源去重账本和运营记录。模型不会自动确认偏好。

号主对话按角色与版本隔离，可随对话留存清理。私聊原文和草稿不进入公开召回。号主可单独提交一条确认公开的经历事实，该事实与私聊留存分别管理。工作台恢复运行的经历来自运行心跳和启动时间，记录事实供相关话题召回。

每日趣事的引文须逐字出现在所绑定的素材中。缺少有效来源编号时，只有引文唯一匹配一条素材才可补齐；有编号但引文与原文不符的条目不入库。保存的观众称呼取自已匹配素材。

操作者确认的真实公开互动经历沿用每日记忆保存，包含自己接错话等具体犯错事实；不复制错误回复正文作为示范，不改写成永久人格自卑或固定道歉提示。`public_incident` 以角色版本及稳定事件编号去重，绑定公开视频、楼ID、评论ID与公开原话，只由管理员确认接口录入。聊天按相关话题召回，评论可按同视频同楼或精确评论来源召回，无须观众复述关键词；普通其他楼不全量注入。归档退出当前关联召回及动态来源，仍沿现有历史回忆语义可被明确追问；删除永久清除条目。每日趣事后续提取继续核对实际来源，不新增每条评论的固定模型自检。

关键词 Lore＋SQLite＋模型摘要为初始检索基线；有明确召回缺口才引入 embedding／索引，不因工具可用而默认增加常驻资源。

### 号主可查看的记忆

「设置 → 个性化」提供「启用记忆」「记忆摘要」和「近期趣事」。角色工作室打开即更新趣事预览，点击后打开同一个弹窗。弹窗每件趣事显示一段短摘要及原评论或视频链接，已有回复可直接打开。趣事与号主聊天共用按当前账号、角色和业务日查询的公开运营事实。评论按资源和根评论合并。确认送达后更新同一目标，旧聊天引用仍定位原评论。查询优先使用当天的事件，再补最近两个业务日。

后台用现行 9B 分批整理号主原话及有确认回执的公开互动，按账号、角色版本和来源保存进度。模型提出新增、更新或跳过，程序绑定原话与回执并直接保存。偏好改口后更新原条。号主也可以直接交代记下一条有来源的运营事件。保存的记忆可立即用于号主私聊。直播、回帖与动态的使用权限在条目里分别设置。

保存记忆按当前话题取用。回帖优先绑定同一资源、评论楼与原参与者，直播及动态只使用本渠道已获授权的经历。归档退出日常召回，撤销公开退出对应渠道，删除同时保存来源的删除标记并使旧引用及依赖它的对话上下文失效。生成与交付边界核对记忆版本及渠道权限。已送达的原始平台回执仍可在运营记录中核查。

记忆摘要从现有有效条目读取。记忆界面提供启用、查看来源、更正和删除。频道设置随条目一起更正。记忆开关按当前账号和角色保存，默认启用。关闭即暂停后台整理与长期记忆召回，生成及交付重新核对开关版本。旧归档可通过筛选查看。删除与到期清理使旧引用及依赖它的派生召回或摘要失效。

当前上下文由号主会话、直播场次、评论楼、视频任务和游戏存档各自续接。新直播场次使用新的对话窗口。视频续看使用任务的分 P、时段和阅读游标。模拟游戏保存适配器的实际状态及控制权，重启后从存档恢复。号主可按需查视频时码、游戏进度和直播已播台词。

「本场讲一下」先在号主侧从指定视频时码、私聊讨论或游戏状态提炼文字，再交给当前直播场次。直播生成使用该文字及适用的直播表达偏好。录像、截图、原音轨和桌面均需走各自的画面或音频入口。卡片只在播放器确认完成后显示已播台词。号主明确提出的长期直播表达偏好按规则类别合并，首版支持先讲结果或过程、简洁或展开。删除或修改相关记忆后，尚未播出的任务从当前材料重新生成，已经播过的台词仍由播放回执管理。

号主对话可查询授权的公开经历和运营事实，并呈现原来源。今日观看按业务时区、当前账号与角色查询实际任务记录。可从当轮运营事件确认独立的公开经历，编辑后的事实保留原来源。撤销、归档或删除后，按经历版本核验旧追问；运营事实仍可按原记录查询。跨渠道主动召回待验证身份、隐私、撤销和删除后的表现，再决定范围。私信原文、私聊原文和草稿继续各自隔离。记忆管理参考会话与保存记忆分开控制的交互。 [OpenAI Docs](https://learn.chatgpt.com/docs/customization/memories)

### 对话留存

对话默认留存30天，可在认证设置中改为1–36500天或关闭自动清理；策略保存在SQLite，重启保留。启动及后续约每小时清理过期会话数据，生成／播放忙时延后重试。外部评论的发表日期不作为本地对话年龄：以原始消息进入会话的时间计龄，压缩／继续聊天不能刷新旧消息年龄。

清理范围包含过期对话、来源索引、已结束任务／事件和不再需要的场次；活动窗口只要含过期来源，就整体失效，不能只删原句却留下摘要或事实缓存。来源年龄未知的旧版非空窗口按需失效重建。删除与清理结果记录属同一事务，失败整体回滚，生成中不删数据。

原始评论数据集、草稿、发布回执、角色版本和已确认关系独立保留，不因会话到期删除；这不是全库擦除或个人数据彻底删除。手动清理先预览范围与条数再明确确认，可指定UTC截至日期；服务采用精确、带时区时间戳的排他边界，等于截至时间的记录保留。关闭自动清理后，仍可显式按日期手动清理。

动态运营只读取已公开评论及显式允许公开的角色记忆，权限、失效与发布节奏由[动态运营契约](../operations/dynamic-operations.md)维护。允许公开不会延长会话来源的留存期限；动态决定与发布记录作为运营审计独立保留，不能作为恢复已清理会话的事实索引。

## 来源记忆与核对线索

在Codex压缩核心之外维护轻量来源记忆。每项绑定场次／评论楼scope、角色ID＋版本、原事件ID、说话角色与不可改写原句；结构化地点、人物、动作、物品和数量必须有原句中的quote／span依据。首版用保守已发生句式提取，未知形式只索引原句，不编造字段。角色故事标记role_story／fictional，不升级成用户现实事实；用户原话仅表示其说法。引用已有证据形成的派生回答只留审计，不再成为独立事实，防止模型补写反复自证。

当前问题明确回顾已发生事件，或命中已知来源实体／事件ID时，检索本scope中有关联的少量原句；最多3项、证据JSON约1800字符，候选扫描有界，不把全部旧对话塞回活动窗口。原句作为无指令权的数据补入当前上下文；摘要遗漏细节不等于原句或事实索引丢失，不从摘要重新抽取无来源事实。

对当前问题涉及的地点／人物／物品／数量记录字面核对线索，保留首答和相关原句。词面未匹配时标记待核对，语义评价保持待审；核对过程不触发台词重写。日常闲聊和角色剧情自由表达。sources、required_slots、missing、method、status、semantic_verdict随草稿／任务供工作台审阅，身份、渠道、工具参数与发送授权由各自程序接口校验。

## 数据与权限契约

下表维护持久语义及唯一性，不强制同名表；P1／P2 实体随对应功能实施。

| 实体 | 必须保留的语义／字段 |
| --- | --- |
| characters／character_versions | 稳定 ID、名称、当前卡片和历史内部关联。显式编辑更新当前卡片。 |
| lore_entries | ID、角色、触发词／标签、优先级、文本、token 上限、冷却。 |
| users | 内部 ID、平台、平台用户 ID、显示名、memory_opt_out；平台＋用户 ID 唯一。 |
| user_relations | 角色＋用户唯一，好感度、阶段、称呼、更新时间，跨角色隔离。 |
| affinity_events | ID、角色、用户、原因、delta、时间、源事件 ID，幂等且可追溯。 |
| user_memories | 用户、角色、key/value、来源、过期时间，可查看／编辑／删除。 |
| sessions | ID、平台／房间、角色版本、开始时间、摘要，场次短期状态独立。 |

MemoryStore.get_relevant(character,user,session,budget) 仅返回必要、预算内且有来源的信息，不绕过退出设置和审核。记忆查看／修改／删除属于认证管理接口；REST 命名可变化，身份和失败语义不可省略。任务暂存不自动升级长期记忆。

每日趣事保存已经核对的原观众／直播来源和逐字引用证据，原对话按留存规则清理后仍可使用这份已核验快照。自动批准不变成管理员确认；明确的人工记录及真实运行事件分别标记来源。旧趣事优先按原来源编号与引用精确回查，无法验证的保留给界面审查，不自动作为角色已经做过或说过的经历。动态的旧来源缓存同样不能绕过已发送回执校验。
