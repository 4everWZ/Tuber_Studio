# 跨主机运行与数据归属

本规范维护业务与外部服务的边界、唯一业务写入、迁移和备份要求。运营、直播、点歌和游戏按本规范使用业务数据及外部服务。业务启动由[部署指南](../../guides/deployment.md)维护，实施与验收见[当前计划](../../plans/current.md#直播点歌与部署验收)。

## 职责与部署模式

Tuber Studio 通过已配置的 API 使用 Omni 推理和 Avatar 服务。业务容器是账号、平台授权、记忆和任务的唯一活动写入者。浏览器和 OBS 使用业务及媒体入口，终端可关机再接续。迁移前的业务实例保有写入权，切换后原卷作为已退役的恢复来源。 [Omni 与 Avatar 接口](omni-deployment.md)

| 主体 | 目标职责 |
| --- | --- |
| 唯一业务主机 | [常驻 Agent](agent-runtime.md)的事件、任务、记忆和工具，平台接入、点歌 Node、凭据与业务缓存。可在电脑或独立主机的业务容器运行。 |
| 推理服务 | 通过已认证端点报告模型及容量，按实际能力提供语言、视觉或语音推理。服务持有模型资产和临时状态。应用工具由业务服务执行。 |
| Avatar 和媒体服务 | 按授权的上下文建立会话，渲染并交付音画。播放状态和回执由业务与实际播放器关联，媒体服务持有自身渲染资产。 |
| 客户端终端 | 浏览器工作台与获准的麦克风／屏幕输入。具备相应能力的客户端可播放、使用 OBS 或运行本地游戏执行器。 |

业务与服务可以分别部署或同机运行，使用同一套接口和业务实现。配置服务地址后须查询并验证真实能力。平台和在线点歌依赖各自的网络连接。桌面壳的选型独立于此契约。

Core 通过网关读取健康、模型卡和窗口。服务未就绪时，业务保存原任务状态并显示原因。

运营、直播及媒体按实报能力验收。资源调度由服务方负责，业务端执行场次、队列和时限约束。[声音与资源验收](models-and-audio.md)

## 数据权威与保留

| 数据 | 权威位置与边界 |
| --- | --- |
| 评论、私信、直播／游戏互动及回复，角色版本、摘要、记忆、关系 | 唯一业务主机的持久数据目录／数据库。按稳定账号、平台用户 ID 与角色关联，保留访问权限。 |
| 配置、登录凭据、任务和动作记录 | 业务主机的持久数据，按身份与权限维护，并纳入备份恢复。 |
| 歌曲／歌词／封面、网页视频、截图、工具结果、可重建音频 | 业务缓存，受容量、活动任务保护、清理与失效规则约束。 |
| 游戏存档、主动保留录像 | 游戏或用户的持久保存位置，按独立规则保留。 |
| 角色声音和配图参考、持久图片工件 | 角色配置绑定来源与版本，私有原件和生成工件随业务数据保存。 |
| 推理资产与服务缓存 | 独立服务维护。会话历史、任务和回执由 Core 持久保存。 |

B 站网页登录在业务主机的私有凭据文件保存 Cookie、平台 UID 和续期令牌，旧版两字段文件可直接读取。续期只接受同一 UID 的新凭据，先原子保存新凭据及待确认旧令牌，再向平台确认。重启后可恢复待确认状态。登录资料缓存保留最近核验，核验时间老化、网络错误和风控分别显示。新凭据在扫码确认并经平台核对 UID 后才替换。业务发送继续按实际身份和原授权核验。 [账号与登录](../../guides/operations.md#账号与登录)

具体身份、版本和留存沿[运行时数据](runtime-and-characters.md)；窗口重建沿[上下文规范](context-and-compaction.md)。业务主机从必要近期对话、摘要、相关记忆与工具结果组装上下文。网关会话失效或服务重启后，由 Core 重建。

业务与 Agent 记忆维护一个可写主数据位置。迁移切换前保留原权威位置，切换完成后由新业务实例独占。模型、渲染、离线素材和其他应用各自持有其资产，通过业务接口取得获准任务与数据。

业务启动先核对数据目录的权威标记，再取得覆盖数据库初始化与完整服务生命周期的OS排他锁。同机第二个业务进程不得打开该目录写入。权威标记区分active、staged与retired：恢复副本初始为staged，只有显式激活且主机身份匹配的active副本可运行；旧目录retired后保留文件用于核验和回退。

## 迁移备份与恢复

迁移前盘点路径、类别、容量及正在执行任务，分别处理持久数据、可再生缓存和模型资产。先备份，再在隔离目录核对数据库、角色版本、用户身份／关系、配置、引用文件与任务／动作状态；凭据备份保持适当访问权限。缓存清理不替代备份，备份恢复也不靠重新抓取历史补齐。

切换须明确旧写入者停止、完整性核对、新主机写入生效与回退边界；避免两端同时可写。原文件在核验后才按明确操作回收，模式切换或迁移本身不自动删除原数据和缓存。恢复演练不覆盖生产目录，恢复后先核对未决外部动作，再继续任务。

数据库快照使用SQLite backup接口，覆盖已提交但尚在WAL中的数据；不把单独复制主数据库文件当作完整备份。清单保存数据库完整性、表计数及业务文件的大小和SHA，凭据原文不进入输出。恢复只接受新目录，核对完整文件集与校验值后，按明确的存储字段重绑旧runtime根目录；评论、模型正文、来源和发送回执保持原始内容。

迁移时复制持久业务文件、已有业务缓存与角色参考材料。游戏存档与主动保留内容按各自规则管理。回退先停止当前写入者并核对切换后的新数据，再显式恢复原主机写入权。

## 服务中断与恢复

前端断开后，在线业务服务继续接收事件并推进已获准工作。业务主机关闭时任务暂停，依赖终端 OBS 或游戏执行器的操作等待相应终端恢复。业务后端重新启动先核对任务、触发时效与未知动作。

推理服务失联时，业务工作台仍可查看历史、配置和执行无需模型的操作，相关任务显示等待或不可用。Avatar 或媒体服务失联时，分别报告会话和取流状态，私有 Chats 可回到文字。更换兼容服务后保留业务历史、关系及游戏存档。模型、TTS、媒体和网络故障按实际阶段处理。

## 媒体地址与可选组件

点歌服务由业务主机按需启停，复用工作台、曲库、队列与 OBS 播放器。业务侧负责搜索、解析、下载和缓存，播放器从可达的音频地址直接读取。

媒体地址按实际播放器所在主机验证。浏览器和 OBS 使用可达的入口和该入口的观看凭据，WHEP 另验证终端实际可达的 ICE 候选。OBS 可从本地采集游戏，并与 Avatar 节目在现场合成。

游戏截图、音频和可再生调试记录有明确的缓存目录、占用显示、容量设置与清理入口，复用现有活动任务保护。主动保留的录像、动作事实记录与游戏存档继续作为持久数据管理。

业务与外部服务各自管理缓存位置、占用和清理，模型资产、存档与持久记忆分别保管。来源、音质、开关、取消、音乐池 15 GiB 上限和受保护文件见[直播与媒体](../live/live-and-media.md)、[媒体缓存](models-and-audio.md#媒体磁盘缓存)。

## 跨主机验收

在隔离目录完成一次迁移／恢复演练，核对对话、角色、身份、关系、配置及未决任务一致性；清业务缓存后这些数据与游戏存档仍在，确认仅有一个活动写入者。

分别验证推理与媒体服务重启或替换、Core 退出后恢复、跨主机音画读取、登录持久性和原业务回归。按部署分别记录资源峰值、带宽、播放及业务延迟，列出冷／热、缓存与并发条件。
