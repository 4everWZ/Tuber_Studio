# 跨主机运行与数据归属

本规范维护业务／推理解耦、唯一业务写入、迁移和备份要求。现有实装覆盖运营、直播与点歌的双机部署，游戏实机接入沿用此边界。安装与数据位置由[部署指南](../../guides/deployment.md)维护，实施与验收见[当前计划](../../plans/current.md#直播点歌与部署验收)。

## 职责与部署模式

业务与 Omni 基础设施独立部署。业务容器是账号、平台授权、记忆和任务的唯一活动写入者。浏览器和 OBS 留在终端，终端可关机再接续。旧电脑业务卷在切换前保有迁移权威，切换后留作已退役的恢复来源。当前目标节点及建设顺序由计划维护。 [Omni 部署](omni-deployment.md) · [当前计划](../../plans/current.md#独立-omni-部署)

| 主体 | 目标职责 |
| --- | --- |
| 唯一业务主机 | [常驻 Agent](agent-runtime.md)的事件、任务、记忆和工具，平台接入、点歌 Node、凭据与业务缓存。可在电脑或独立主机的业务容器运行。 |
| 推理节点 | 模型加载、语言／视觉／语音推理，经共享网关供多个调用方复用。按部署启用 Avatar 和媒体桥。推理服务持有模型资产和临时状态。业务服务执行模型请求的应用工具。 |
| Laptop／手机终端 | 浏览器工作台与获准的麦克风／屏幕输入。在具备能力的电脑上使用 OBS、播放和运行本地游戏执行器。 |

保留同一主机承担业务与推理的全本地可选模式；平台和在线点歌仍依赖网络。两种模式复用同一业务实现，以端点与部署配置切换，不维护两套Agent。业务代码不嵌入Jetson路径或某一模型参数；可替换端点须查询真实能力。C/S桌面壳仍为TBD，不作为本阶段前置。

运营和直播使用各自的 Profile，选型、窗口与准入由[模型规范](models-and-audio.md)维护。模式切换由业务主机发出受认证的资源请求，推理节点负责加载／卸载和实际容量核对，业务端在确认切换成功后更新当前 Provider；失败沿现有资源回滚规则恢复。

## 数据权威与保留

| 数据 | 推荐目标下的权威位置与边界 |
| --- | --- |
| 评论、私信、直播／游戏互动及回复，角色版本、摘要、记忆、关系 | 唯一业务主机的持久数据目录／数据库。按稳定账号、平台用户 ID 与角色关联，保留访问权限。 |
| 配置、登录凭据、任务和动作记录 | 业务主机的持久数据，按身份与权限维护，并纳入备份恢复。 |
| 歌曲／歌词／封面、网页视频、截图、工具结果、可重建音频 | 业务缓存，受容量、活动任务保护、清理与失效规则约束。 |

| 游戏存档、主动保留录像 | 游戏／用户持久保存位置，不归临时缓存清理。 |
| 模型、声音模型及必要推理资产 | 推理节点模型管理目录，独立于业务缓存清理。 |
| KV／前缀及推理临时缓存 | 推理节点，可失效重建，不作为记忆、关系或历史主数据。 |

B 站网页登录在业务主机的私有凭据文件保存 Cookie、平台 UID 和续期令牌，旧版两字段文件可直接读取。续期只接受同一 UID 的新凭据，先原子保存新凭据及待确认旧令牌，再向平台确认。重启后可恢复待确认状态。登录资料缓存保留最近核验，核验时间老化、网络错误和风控分别显示。新凭据在扫码确认并经平台核对 UID 后才替换。业务发送继续按实际身份和原授权核验。 [账号与登录](../../guides/operations.md#账号与登录)

具体身份、版本和留存沿[运行时数据](runtime-and-characters.md)；窗口重建沿[上下文规范](context-and-compaction.md)。业务主机从必要近期对话、摘要、相关记忆与工具结果组装上下文，推理节点重启、卸载、KV失效或换端点后仍能重建，不依赖旧推理会话存活。

业务与 Agent 记忆维护一个可写主数据位置。迁移切换前保留原权威位置，切换完成后由新业务实例独占。模型、渲染、离线素材和其他应用各自持有其资产，通过业务接口取得获准任务与数据。

业务启动先核对数据目录的权威标记，再取得覆盖数据库初始化与完整服务生命周期的OS排他锁。同机第二个业务进程不得打开该目录写入。权威标记区分active、staged与retired：恢复副本初始为staged，只有显式激活且主机身份匹配的active副本可运行；旧目录retired后保留文件用于核验和回退。

## 迁移备份与恢复

迁移前盘点路径、类别、容量及正在执行任务，分别处理持久数据、可再生缓存和模型资产。先备份，再在隔离目录核对数据库、角色版本、用户身份／关系、配置、引用文件与任务／动作状态；凭据备份保持适当访问权限。缓存清理不替代备份，备份恢复也不靠重新抓取历史补齐。

切换须明确旧写入者停止、完整性核对、新主机写入生效与回退边界；避免两端同时可写。原文件在核验后才按明确操作回收，模式切换或迁移本身不自动删除原数据和缓存。恢复演练不覆盖生产目录，恢复后先核对未决外部动作，再继续任务。

数据库快照使用SQLite backup接口，覆盖已提交但尚在WAL中的数据；不把单独复制主数据库文件当作完整备份。清单保存数据库完整性、表计数及业务文件的大小和SHA，凭据原文不进入输出。恢复只接受新目录，核对完整文件集与校验值后，按明确的存储字段重绑旧runtime根目录；评论、模型正文、来源和发送回执保持原始内容。

迁移复制持久业务文件、现有业务缓存及供业务侧核对声音身份的小参考音频；模型、引擎与模型缓存保留在推理节点。旧实验、部署副本与旧备份分别盘点并留在原位置，不混入新的活动业务目录。游戏存档与主动保留内容仍按其持久数据规则管理。回退先停止当前写入者并核对本次切换后的新数据，再显式恢复旧主机权威；不直接启动旧数据库覆盖新进度。

## 节点与业务服务中断

前端设备断开后，在线业务服务继续接收事件并推进已获准工作。电脑承担业务时，电脑关机即暂停。AGX 承担业务时，Laptop 关机后 AGX 继续推进可执行工作，OBS 或游戏依赖本地终端的任务等待终端恢复。业务后端重新启动先核对任务、触发时效与未知动作。

推理节点失联时，电脑仍可查看历史、配置和执行不依赖模型的操作，相关模型任务显示等待／不可用。更换兼容节点保留业务历史、关系与游戏存档；模型失败、TTS失败、网络失败分别处理，不将等待当成功。

## 媒体地址与可选组件

点歌Node在电脑可启动、停止、重启，复用当前工作台、曲库、队列与OBS播放器；搜索、解析、下载与缓存由业务主机执行，电脑可读的音频不再经推理节点中转或重复下载。

媒体地址按实际播放器所在主机验证，某台机器的localhost不作为另一台机器可访问地址。OBS在电脑本地采集、合成游戏，避免将游戏画面送往推理节点再回传编码。

游戏截图、音频和可再生调试记录有明确的缓存目录、占用显示、容量设置与清理入口，复用现有活动任务保护。主动保留的录像、动作事实记录与游戏存档继续作为持久数据管理。

来源／音质、开关、取消、音乐池15GiB上限及受保护文件继续由[直播与媒体](../live/live-and-media.md)、[媒体缓存](models-and-audio.md#媒体磁盘缓存)维护；本层只改变归属与寻址。两端显示各自缓存位置、占用和清理结果，模型资产、存档与持久记忆继续分开。环境镜像／源码分离与缺失才拉取沿现有部署规则，不为迁移默认新增基础设施或常驻模型。

## 跨主机验收

在隔离目录完成一次迁移／恢复演练，核对对话、角色、身份、关系、配置及未决任务一致性；清业务缓存后这些数据与游戏存档仍在，推理节点无另一份可写业务主数据。

分别验证推理节点重启／替换、电脑后端退出／恢复、跨机音频读取、登录持久性和原业务回归。迁移前后实测两机常驻／峰值内存、带宽、播放及业务延迟，不预设Node搬迁可释放多少内存。共享内存统计不直接相加，冷／热、缓存、并发与功耗条件单列。

迁移、节点恢复、跨机媒体及视觉资源的实测和未通过项见[双机实装结果](../../../evaluations/results/distributed-operations-20261102.md)。
