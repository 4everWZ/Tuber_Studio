# 记忆、关系与来源

## 用户身份与长期记忆

长期记忆和历史引用开关由号主在「设置 → 个性化」管理。前台聊天与后台委派均无权修改这两项配置。号主可以在私聊中更正或忘记一条具体偏好，应用按来源和当前身份处理；临时对话关闭长期读写。日常设置工具的完整范围见[前台日常设置](agent-runtime.md#前台日常设置)。

新产生的纯号主私聊按认证号主和角色 ID 保留，切换运营账号或编辑同一角色不丢失对话。号主原话中整理出的明确协作偏好也按此范围读取、更正和删除，仅用于号主私聊；源账号、角色版本和原话仍可追溯。受众私信、公开经历、直播规则、引用领域记忆的回答和缺乏主体绑定的旧资料不扩大可见范围。最近任务卡的改口、视频续跑和确认操作仍按原执行授权核对。

| ID | 原优先级 | 要求 |
| --- | --- | --- |
| MEM-01 | P0 | MUST 分开保存／引用固定角色、全局 Lore、用户关系、会话摘要、活动对话和任务暂存。 |
| MEM-02 | P0 | MUST 按 (platform, platform_user_id) 识别用户；账号运营中的关系及私密会话另以已核验account_id隔离，同账号评论／私信按OC共享关系。未知ID仅匿名／临时状态，不按昵称合并，旧未绑定账号的数据不自动迁移至新账号。 |
| MEM-03 | P1 | MUST 保存称呼、好感度／阶段、重要事件、明确偏好、上次互动、字段来源及更新时间。 |
| MEM-04 | P1 | MUST 好感度按事件类型、每日上限、冷却和反刷屏更新，不等于打赏总额，观众不能直接指定数值。 |
| MEM-07 | P1 | SHOULD 用结构化关系事件和确定性规则；不确定事实先候选，验证／审核后持久化，模型不直接改库。 |
| MEM-08 | P1 | MUST 可查看、编辑、清除记忆及设留存期限；删除失效记忆／清空用户关联档案，不永久存每条弹幕。 |
| MEM-09 | P0 | MUST 同一认证账号在网页、手机及文字／语音会话使用同一份 Agent 记忆。通过来源和接收权限控制取用，公开交付沿业务授权。 |

UC-03：观众再次出现时读取必要称呼、关系阶段及确认偏好；有意义互动产生候选关系事件，经规则或审核持久化。昵称变更只改展示，不改身份。模型产生的“事实”保存来源、时间和确认状态，不把玩笑／扮演直接当真实身份。

评论和私信在同一账号、OC 和平台 UID 下共享好感度。范围为 −100 至 +100，新关系从 0 开始。来源 ID 或近期内容重复时不再次计分，正负变化共用 60 秒冷却，各方向滚动 24 小时最多变化 10 分。礼物金额与好感分开。

评论详情和私信会话可打开同一用户档案。操作者确认称呼、偏好和重要互动后，记录确认时间与来源，供该用户后续评论和私信使用。退出个性化后停用档案并暂停累计好感度；该楼或私信会话原文仍用于当前对话。清空档案重置确认内容、上次互动和好感度，保留个性化开关、来源去重账本和运营记录。模型不会自动确认偏好。

同一账号与 Agent 拥有一份记忆。桌面网页、移动网页、文字和语音都使用该身份。角色卡更新保留 Agent 身份，历史保留生成所用的角色版本。绑定号主、运营登录与观众分别核验身份。平台来源保留真实账号、参与者和访问权限，换绑时重核原来源和批准。

管理员可经证据录入接口补记一次具体的公开互动事件，包括角色接错话的起因和后续。`public_incident` 以角色版本及稳定事件编号去重，绑定公开视频、楼 ID、评论 ID 和公开原话。聊天按相关话题召回，评论按同视频同楼或精确评论来源召回。归档退出关联召回和动态来源，仍可明确追问；删除永久清除条目。

### 长期记忆的内容与来源

号主前台聊天和私有通话常驻当前角色的名字、自述、说话风格及已核验的参与者关系。角色卡背景、卡片内经历和 lore 按本轮话题选取，最多两段卡片原文。旧卡在身份、外观、性格或口头禅字段里写的相关细节也可取用。单问身份、关系、说话风格或互致问候时，无需附上旧经历。同一句另问具体往事或事物时，按该小问选材。文字追问「后来呢」沿用当前可读窗口中最近一轮的话题，原文仍从当前卡片读取。

号主长期记忆另查有效笔记及获准来源。自动召回先去掉「平时」「喜欢」等常用问法，再匹配实际主题。精确来源可直接读回对应条目。角色卡选段和本轮主题筛选均在本地完成。

记忆服务属于[通用 Agent 底座](agent-runtime.md#入口与能力)。SQLite 按认证主体和 Agent 保存一份权威记录及摘要。记忆按内容组织主题，各业务场景只提供来源和当前受众。对大肥鱼，记忆回答她认识谁、共同经历过什么、号主目前关心什么以及下次怎么接续。

| 内容 | 写入与取用 |
| --- | --- |
| 号主档案与关系 | 称呼、经确认的背景、兴趣、稳定偏好和协作方式。按人物、主题与有效时间归并。角色与他人的关系保留各自来源，玩笑和扮演可保留为角色故事。 |
| 项目、约定和长期规则 | 持续目标、重要决定、限制、交付偏好与后续线索。实际任务进度、是否已经履约和授权状态从原任务读取。规则可指导候选行为，授权由工具边界验证。 |
| 角色经历 | 值得记住的对话、视频、公开互动、直播、游戏进展与转折。保存参与者、发生时间、影响及来源。视作角色已经说过／做过需要相应已送达、已播完或动作确认。号主陈述可记录为号主提供的线索及其确认状态。 |
| 近期与精确回查 | 当日运行事实和历史会话通过各自来源索引查询，支持按业务日、人物、原话、视频分 P 和时码取证。会话摘要、活动窗口、待办与游戏存档分别续接，记忆以来源 ID 和任务 ID 关联。 |

每条有效长期记忆保存命题或经历、证据引用及访问权限、主体、发生及有效时间、确认状态和版本。后台整理号主原话、核实的事件或工具结果，以及获准的文件和连接器结果。模型可提出新增、合并、更新或跳过，程序先确认原始依据可用、主体一致、事实与来源相符，再提交并按源事件防重。明确的记住与纠正经同一协议保存，下一轮和其他客户端可用。模型回复、生成摘要、台词、草稿、未确认语音转写和未核对的动作只能成为线索。拼接多个模型输出或重复引用同一说法不会增加证据强度。号主陈述、外部可核实事实、角色设定与剧情分别保留其来源性质。

模型生成的回复、任务总结和已发送台词留在各自的会话或回执中供回看。长期摘要和后续任务自动使用可追溯、仍有效的原始陈述和已核实事实。后台整理可提议分类，正文取自符合当前受众权限的原文。旧条目缺少明确编写或更正来源时，自动召回、摘要和聊天查询只取已核对的原话。管理入口展示当前内容和当前来源，号主可直接更正或忘记。同一来源被更正后，较早入队的整理请求无权覆盖。公开发送、游戏动作和任务状态依据各自回执。更正或撤销使共享摘要、索引及依赖的待执行工作重新核对。

同一偏好更正后沿用条目 ID，以当前内容和本次更正来源取代先前说法。普通聊天、私有通话和任务只接收当前适用的文字；历史聊天中的失效偏好及其应答退出模型上下文。内部并发与撤销校验在读取、继续生成和交付时核对。历史事实与已交付成果按各自回执读取。来源明确且时间不同的状态可以同时保留有效期。明确的号主纠正优先于后台推断。新的平台事实用实际来源更新。遇到矛盾或证据不足，标示出处和不确定性，必要时追问。以官方介绍的后台整理、长期个性化和用户控制为体验参考，来源绑定、时态与状态由本规范定义。 [ChatGPT 记忆整理](https://openai.com/index/chatgpt-memory-dreaming/) · [ChatGPT 记忆控制](https://help.openai.com/en/articles/8590148-memory-in-chatgpt)

召回先检查身份、来源权限、当前受众、有效时间和记忆开关，再按当前问题和任务做筛选。结合结构化条件、精确引用、中文全文与语义召回，按相关性、显著性、时效和证据强度选择预算内材料。短实体名和中英混合词有可验证的索引路径。先实测 SQLite 全文检索、结构化时间／实体索引和语义查询改写，对比中文同义表达和跨会话检索。需要向量召回时验证增益、运行成本和删除同步，索引可依权威记录重建。普通聊天可以直接使用就绪的相关记忆，回顾、查证和任务续接可按需调用查询工具。上下文优先保留当前用户消息与最近的纠正。 [SQLite FTS5](https://www.sqlite.org/fts5.html) · [Generative Agents](https://arxiv.org/abs/2304.03442) · [上下文与压缩](context-and-compaction.md)

MemoryStore.get_relevant(character,user,session,budget) 仅返回必要、预算内且有来源的信息，不绕过退出设置和审核。记忆查看／修改／删除属于认证管理接口；REST 命名可变化，身份和失败语义不可省略。任务暂存不自动升级长期记忆。

### 号主可查看的记忆

「设置 → 个性化 → 记忆摘要」展示一份按主题综合的自然语言摘要、最近更新时间及可展开的来源。根据内容呈现号主概况、共同关系、兴趣、目标、持续项目、重要经历和相处偏好，空主题省略。用户在底部「询问或更新」询问依据、增补、纠正或忘记，也可直接管理单条。普通聊天里的「你记得我什么」读取同一份摘要。普通聊天和任务卡直接显示答复和成果，偏好的整理与引用在后台完成。摘要按版本原子更新，撤销或更正后待重整段落先隐藏。所有端读取同一版本。

「近期趣事」展示按时间和来源归并的实际经历，可从设置与角色工作室打开。宽泛回顾按业务日查询号主权限内的经历，结合上下文选择值得说的一件或几件。用户限定「今天」时以今天为界，近期补充明确标日期。回复引用按展示顺序保存，供下一句追问原话、作者、时码或回执。原评和回复用各自的来源，确认送达后更新同一经历。

### 可见性、撤销与留存

号主助手使用统一私有记忆，界面按主题显示。公开回复、平台私信、直播与游戏的上下文按当前任务、受众及原始来源授权取用材料。公开端可读取已核实的公开证据或获准交接的成品，私信按参与者取证。私聊、附件、草稿、个人材料和权限绑定的工具结果默认为私有。既有条目的收窄授权随迁移保留。对话原文、截图、音频和桌面遵从各自的采集授权。启用记忆不授权动态取用号主私聊或其改写；指定话题的单次草稿不产生后续公开权限。[动态来源规范](../operations/dynamic-operations.md#自主运营与来源)

后台文本模型逐条判读普通私聊。模型先只读当前号主的原话，用相同字段描述持续合作、当前事项、社交或其他含义，并给出原文摘录。应用按原句标点和做法的起止位置补全范围分句，保存模型原选跨度和送审跨度。独立复核确认该范围确实修饰这项具体做法，并保留条件和否定。已有笔记仅用于定位可能的更正。覆盖前另读两份约定，核对新旧取值及两份原文都能定位的具体字段或旧值。两项可以并行，或对应旧条目的依据不足时，保存独立条目。号主可在设置或语音确认中按内容指定要更正的条目。惯例可用自然语言表达。闲聊邀请、一次委托、玩笑和转述留在当次对话。旧误录保留原来源供号主检查、更正或忘记；缺少有效依据的自动条目不进入私聊召回、写作审查或旧成果再编辑。设置保存和语音确认沿用各自的认证与版本检查。

号主可在设置中分别控制长期记忆与文字对话历史引用，在个性化设置中查看当前原话和来源。普通私聊里明确表达的长期偏好由后台自动整理。从普通私聊直接拨号时，若开启长期记忆与历史引用，可用当前角色与号主最近 30 分钟内最后一条可见的普通私聊原话检索话题相关记忆。无合适来源或匹配结果时，通话不带记忆。拨号前指定的话题优先。点「我说完这句了」会在下一块采集音频送达后封闭当句。已提交的号主音频取得最终转写后，只加入本次通话的待选列表。号主主动打开「查看通话转写」并选句后，才可核准保存、交办或更正；挂断会清空列表。私聊网关协商到一次转认时，还可点「转认下一句」，待界面提示后说话，再点「结束并转认这句」。网关只将所选麦克风音频送交 Omni；号主可在机器原稿旁改正误听，再明确确认保存、更正或交办。工坊验证普通网关为本次票据、录音标识、样本数和机器原文签发的回执。私有记忆分别保存机器原稿与号主确认稿；号主可到设置的「个性化」核对语音来源，忘记条目会一并删除原稿。号主可用最终转写更正本次通话引用的一条偏好，预览显示当前内容和号主确认稿；多个相关偏好按内容区分。确认后更新同一条目，旧票据失效。临时对话与临时通话使用窗口内上下文。仅含私有附件的文本子任务可检索获准来源、提出原句建议，私有视频与附件成果的后台编辑按写作用途选择号主偏好；偏好独立于候选证据，只进入私有编辑请求。应用按已授权条目绑定本次写作约定，成品落库前逐条检查实际字段；明确的前后缀、包含文字和长度按字段检验。每项执行规则保存当前号主原话或亲自编辑的文字跨度与修订号。模型提出的规则无法绑定原文时，仅在私有审稿诊断中记录丢弃原因，措辞和组织方式由后台模型复核。标题约定句式时，单独读取去掉末尾标点的标题，区分发问、陈述和名词短语，摘录实际疑问核心或主句谓语。有主帧的标题还要核对其中的事实或问题预设，并从该帧的观察中指出依据。仅重写未满足的字段，沿用原证据审核，仍不符合时不交付。后台重新取材不会获得带私有偏好的旧版成果。交付与语音播放前核对授权及引用版本；撤回后新生成的成果使用当时有效的资料。

记忆开关按号主身份及角色保存，迁移保留原设置。关闭立即暂停后台整理与自动召回，用户仍可在管理入口查看及清理。支持单独关闭跨会话历史引用，保留显式保存的长期记忆。临时对话可保留本轮窗口，并停用长期记忆读取和写入。停止主动提起、收窄共享、归档、忘记及删原文各有独立操作，支持一次清空记忆并关闭。归档条目仅供授权管理和显式回查。忘记删除可召回内容并保留最小抑制标识，后台整理、重建索引和回放旧消息时延续抑制。记录撤销后使所有依赖它的摘要、检索、待播和未交付稿失效。依赖可撤销记忆的内容须在对外显示前复核，工具执行和最终交付也核对版本，另一个客户端的修改及时生效。

会话清理触发依赖失效。显式确认保留的长期记忆和来自独立业务事实的经历按自身留存管理，私聊临时摘录和纯会话派生索引随来源到期，不凭已清理原文重建。记忆管理显示来源与是否独立保留，支持删除两者或仅停止用于个性化。已发布、已播和已执行回执仍按各业务管理。

「本场讲一下」从指定视频时码、私聊讨论或游戏状态提炼获准的文字交给当前直播场次。直播表达偏好与其他偏好一起管理，消费端按当前任务判断适用性。卡片在播放器完成后显示已播台词。源内容修改或撤回时，尚未播出的任务重新取材，已播台词由播放回执管理。

| 更正或忘记 | 更正在 `daily_highlights` 的同一行更新内容和并发戳。新库只另存独立原始来源，升级后停用旧的正文快照触发器，已有离线记录原样留存。忘记操作按原始来源写入 `memory_source_tombstones`。写作和播放使用的引用绑定 ID、修订和设置状态，继续交付前重新核对。 |
| 切换运营账号或编辑角色卡 | 长期记忆开关跟随号主与稳定角色。迁移前按账号关闭的旧限制在原账号继续有效，号主在那个账号显式开启后解除。号主对某项业务动作的授权仍由领域模块独立核对。 |

### 记忆验收

更正后的同一条目按当前来源读回；旧来源键只可帮助定位当前偏好。用隔离库检查发给模型的普通聊天消息、私有写作工具回包及通话会话指令，核对更正后的文字。设置只展示当前偏好和来源。历史聊天及成果由各自入口按权限回看。

工作站普通网关和隔离库已核对自然改口后的聊天请求及私有文本委派的 Responses 请求。两者只读到当前偏好。Chromium 回归检查设置页及通话发出的会话指令，迁移回归检查旧快照保留及后续写入。

用真实 Provider 验证文字和语音、两台设备和独立会话读取及更新同一份记忆，实际工作能遵守已保存偏好。覆盖时间更新、纠正、临时会话、禁用或在途撤回、会话到期、后台重整和重建索引。注入假号主、虚构已发送回执、误转写及模型声称已经完成的动作，检查后续设备、摘要、运营草稿、直播和游戏仍以可核实事实及正确受众为准。中文持出按跨会话回忆、时序、纠正和证据不足分别评估。 [LongMemEval](https://arxiv.org/abs/2410.10813)

## 来源记忆与核对线索

在Codex压缩核心之外维护轻量来源记忆。每项绑定场次／评论楼scope、角色ID＋版本、原事件ID、说话角色与不可改写原句；结构化地点、人物、动作、物品和数量必须有原句中的quote／span依据。首版用保守已发生句式提取，未知形式只索引原句，不编造字段。角色故事标记role_story／fictional，不升级成用户现实事实；用户原话仅表示其说法。引用已有证据形成的派生回答只留审计，不再成为独立事实，防止模型补写反复自证。

当前问题明确回顾已发生事件，或命中已知来源实体／事件ID时，检索本scope中有关联的少量原句；最多3项、证据JSON约1800字符，候选扫描有界，不把全部旧对话塞回活动窗口。原句作为无指令权的数据补入当前上下文；摘要遗漏细节不等于原句或事实索引丢失，不从摘要重新抽取无来源事实。

对当前问题涉及的地点／人物／物品／数量记录字面核对线索，保留首答和相关原句。词面未匹配时标记待核对，语义评价保持待审；核对过程不触发台词重写。日常闲聊和角色剧情自由表达。sources、required_slots、missing、method、status、semantic_verdict随草稿／任务供工作台审阅，身份、渠道、工具参数与发送授权由各自程序接口校验。
