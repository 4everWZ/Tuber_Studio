# 上下文与压缩契约

## 分层和真实窗口

本规范维护通用上下文树（`ContextNode Base -> Branches`）、每个会话的活动窗口和压缩。跨会话长期记忆从[记忆服务](memory.md#用户身份与长期记忆)按当前作用域（`owner` / `public`）与上限（`100`）取用，进行中的任务从[持久检查点](agent-runtime.md#常驻任务与恢复)恢复。窗口摘要仍绑定原会话与来源。

### ContextNode Base → Branches 通用上下文树

`src/tuber_studio/persona/context/tree.py` 为私聊、视频主评、评论楼层与平台私信统一构建标准 OpenAI 多轮消息树（支持直接渲染为 Chat Completions `messages` 或 `Responses` `input`）：

- **不可变 `Base` 节点（`build_base_node`）：** 固定包含 4 支柱元认知 `self_model` 系统消息（`persona/self_model.py`）、当前作用域获准的 Layer 1 记忆列表以及渠道共享基座材料（如刷视频场景下的 `Video Base`：投稿元数据、UP 主、覆盖标识、首观印象与有界字幕／帧观察摘要，默认基础文本上限 `DEFAULT_VIDEO_BASE_TOKEN_LIMIT = 24_000`）。`Base` 节点创建后不可直接追加对话轮次，确保同视频下多个分支共享完全一致的稳定前缀。
- **轻量 `Branch` 分支（`fork_owner_chat_branch` / `fork_top_level_comment_branch` / `fork_comment_floor_branch` / `fork_dm_session_branch`）：** 从 `Base` 分叉出独立对话线，保留按真实时间顺序排列的楼内／私信／私聊消息（并将 `[人工接管 · ...]` 作为 `user` 轮次明确保留）、当前任务目标，以及轮内原生 `assistant` `tool_calls` 与 `tool` 执行结果（`append_assistant_tool_calls` / `append_tool_result`）。

| ID | 原优先级 | 要求 |
| --- | --- | --- |
| MEM-05 | P1 | MUST 有会话摘要和活动窗口，将过期对话压缩／按留存规则清理，不能无限增长；当前首版已提前要求真实长窗口和模型压缩。 |
| MEM-06 | P1 | MUST 真正token预算，固定核心与系统规则优先，其余按相关度／重要性／新鲜度取舍，不截断关键安全规则。 |

上下文窗口以认证网关模型卡实报的容量为准。输入、系统规则和预留输出共同受此上限约束。

Omni 使用认证网关模型卡实报的 `max_model_len`，纯文本通过同一 Chat 模板计量，计量请求不执行生成。图像等多模态输入采用实际请求用量。模型卡表示推理服务报告的窗口，接近该窗口的实际执行与质量分别实测。 [Omni API](omni-deployment.md)

语义组装顺序为角色设定 → 当前交流场景 → 命中Lore＋当前用户必要关系 → 本场摘要与有关联活动历史 → 当前观众消息 → 本轮任务与输出协议。角色设定读取[当前角色卡](runtime-and-characters.md#角色生成方式)，历史与任务的权限、证据和计量沿用同一契约。角色句长作为表达指导，交付体积与结构化字段由接口校验。明确的私聊邀请先由程序路由。具体chat template角色封装按模型适配，消息来源与角色层级保持。

业务历史窗口以 90% 触发压缩，硬边界采用模型卡的完整窗口。Omni Chats 每次放入一份完整 OC、当前身份、获准记忆和当前消息原文。可选历史按模型 token 计量，先为本轮输出保留基本空间，再从最近的完整轮次向前填入。额外输出预算使用窗口余量。

固定核心、Lore／关系、活动历史、当前任务和输出约束分别组装。历史积累至阈值后由模型摘要压缩，不固定只留最近几轮、不静默整块丢弃。直播按场次＋角色ID＋版本隔离，评论按账号＋平台＋视频＋对话楼＋角色ID＋版本隔离，不将整视频评论当成一个对话；只有completed语音进直播历史。评论草稿仅保留在任务／审核记录，成功发布且有有效回执才作为助手回复进入该楼对话；保存、批准、复制、拒绝、失败及未知回执均不冒充已说过的话。原观众来文仍可作为同楼来源。旧无账号窗口不自动认领到当前账号，旧整视频窗口不混入任意新楼。SQLite保存逻辑消息、源ID、截断完整性、压缩代数与错误，重启可恢复。

评论历史、事实索引及转入私信的公共上下文共用真实发布来源校验。压缩前排除未发送助手正文，新的摘要保留逐来源回执与正文身份链，后续使用时再次核对；旧来源不可验证的摘要不进入模型或再次压缩。被替换原件留在不参与召回的审计中，沿原留存期限及窗口删除一并清理，不重置年龄或保留时长。

接近窗口上限时，分别验证服务能接收请求，以及模型能根据指定来源给出正确答案。[接入验收](omni-deployment.md#接入验收与切换)

评论楼窗口缺失或因[留存规则](runtime-and-characters.md#对话留存)失效时，从该平台／视频／楼的本地现存评论原文重建，仍按角色ID＋版本隔离；不读其他楼、不把旧草稿当成已发言，不重新生成被清理的角色故事或从旧摘要恢复事实。没有原文须提示重新读取／导入，不能凭空宣称恢复。

自动回复在下一次真实生成中重新prefill；人工“重建上下文”在容量／token检查和必要的完整Codex压缩后，执行真实模型prefill，再原子安装候选窗口。模型失败、取消或超窗不安装半份上下文；已有非空窗口不直接覆盖。重读保留数据集是新会话输入，保留原始来源标识，不延续已清理的摘要年龄。

## Codex公开local核心

固定参照 [openai/codex f021168bde5357009fceb0477835ad90bd54c17c](https://github.com/openai/codex/tree/f021168bde5357009fceb0477835ad90bd54c17c)，保留Apache-2.0归属。compaction.py拥有算法，context.py拥有本项目集成；不得用简单截断／关键词摘要替代核心。

| --- | --- | --- |
| core/src/compact.rs：run_compact_task_inner_impl | 克隆原历史、追加摘要提示、模型生成完整摘要、成功后重建并安装。 | 使用本地或兼容API完整HTTP响应及finish_reason；无远端Responses压缩会话。 |

业务侧实现上表列出的文本历史压缩步骤，保留消息来源、预算和计量。网关负责模型执行。

摘要只整理历史话轮里的话题、事件、已确认要求和来源。常驻角色、账号资料和检索出的记忆在生成时重新组装。旧摘要在读取时使用工坊标题，历史正文原样保存。保留窗口预算、超窗恢复、退避和原子安装；小窗口缩放保留预算，仍超窗时保留原数据并报告结果。

## 首轮后40%复检

摘要默认预算为2048 tokens。外围根据待保留的来源事实、实质事件和约束粗估需要，低信息量可降到512（Think模式至少1024），较密集时适度增加，默认上限6144；配置可调整基准／上限。每轮选用预算记录在summary_budgets_last，实际输入与输出预算继续执行真实tokenizer／硬窗口检查；不完整结果仍不安装。该策略不修改Codex核心，不把较短摘要当成质量得分，需看必要信息及后续回答是否保留。

本项目在ContextManager编排层增加用户要求的二轮规则，不改动每一轮的Codex公开local核心。一次压缩操作最多执行两轮完整核心：首轮后用真实tokenizer计量重建的完整输入帧，包含固定prefix、规范上下文、保留历史，以及存在的当前pending输入和输出格式suffix；以模型总窗口为分母计算占用，不只计算历史，也不以95%有效窗口为分母。

首轮后的输入tokens×100 ≥ 总窗口tokens×40时，自动把首轮结果送入同一完整核心再压缩一轮；低于40%则结束。比较使用真实整数tokens，不依靠UI四舍五入后的百分比；131072窗口下52428 tokens低于阈值，52429 tokens触发第二轮。各 Provider 的自动阈值和硬边界继续按本规范计量。

两轮属于一次原子操作，首轮结果只在内存中暂存；任一轮失败、取消、不完整、最终超硬边界或提交失败时不安装任何中间历史，原记录保留。两轮均成功但仍≥40%时，在既有硬边界内可安装最终结果并给出明确warning，不无限循环，也不宣称已降到40%以下。占用warning不是容量验证失败，不能仅因此禁用生成。

状态分别报告occupancy_percent、compaction_passes_last、last_compaction_warning和secondary_threshold_percent=40。compact_count累计成功安装的实际核心轮数，一次操作可增加1或2；失败不增加累计数，最近尝试轮数结合last_compaction_error表示结果。UI显示近似百分比、最近轮数和独立提示；分别展示模型卡窗口、实测用量、压缩失败和占用告警。

## 失败与验收

没有完整stop、空摘要、传输中断、取消、重建仍超窗或持久化失败时，不安装半份摘要；原历史保留，错误可见。SQL安装提交失败须回滚，再独立记录错误，不能将失败安装随错误记录提交。核心／当前输入自身超大且无可压缩历史须明确失败，不能删核心／当前输入凑数。

验收覆盖真实服务／原生元数据、接近窗口上限的token输入；20K选择、UTF-8边界、summary排除、canonical插入；超窗／重试／取消／不完整输出；40%上下边界、pending／suffix计入、二轮失败整体回滚、二轮仍高warning与累计轮数；提交失败原历史不变；SQLite重启与角色／模式隔离；真实摘要及压缩后继续回复。长输入可执行不证明召回质量、摘要语义或实时性能，须按对应任务独立评估。
