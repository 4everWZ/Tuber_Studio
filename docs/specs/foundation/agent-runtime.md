# 常驻 Agent 底座契约

本规范维护创作工坊的常驻 Agent、任务授权和成果交付。Agent 可以独立配置、启动和验收。大肥鱼作为应用层角色，通过配置、事件和工具接口接入。已部署能力见[当前计划](../../plans/current.md#常驻-agent-与跨端记忆)，记忆数据语义和大肥鱼的记忆投影见[记忆规范](memory.md#用户身份与长期记忆)。

## 用户体验

工坊优先服务号主和当前角色的长期创作，默认角色为大肥鱼。Omni 负责听懂要求、决定分工、汇总与交付；后台文本工作者只拿本项工作允许使用的材料，没有自己的对外人格或平台写入权。长期目标、一次执行和可修改的私有成果分别保存。停止一次执行不会结束整个目标，修改成果不会篡改观察记录。主动取材限于获准来源，只有新发现、需要决定或状态实质改变时才提醒；对外提交始终核对具体授权。

号主在桌面和手机工作台接续同一个 Agent 的聊天或任务，可以闲聊、提问、交代一份工作、中途改要求、打开活动看进度或叫停。Agent 能接住当前话题、回忆相关信息、查资料、动用获准工具并交付结果。大肥鱼接入后沿用同一套交互。视频、直播和游戏各有自己的场景与控制入口，任务、可用经历和状态经业务主机接续。

普通聊天优先流式接话。需要事实时，模型按语义查询人、时间、主题、经历或任务，读到证据再提结论。需要做事时，允许多步取材、执行、检查和调整。耗时工作先保存，再告诉号主它在做什么，聊天可继续。任务完成、需要输入、授权变化或失败时，在私有活动里给结果和续接入口。公开发声使用场景自身的权限、时限和交付回执。拟人表达沿用角色卡，事实及已执行动作可以回查。

开启历史引用后，号主可以在私聊中用任务 ID、BV、原来源或理由原文查找旧成果，也可指定长期目标或 `r1 v2` 这样的版本。检索覆盖同一认证号主和角色可读的任务及成果版本；编辑角色卡或更换运营账号后仍可查阅。询问当时的选择依据时，Omni 从可读版本中选择来源版和理由原文行。工坊回读该版，核对原文后以纯文本显示作者、版本、行号和引文。缺乏对应理由时显示缺口。「查看引用原稿」打开所引版本和已有来源链接。其它私聊仍可自然生成。临时聊天、动态与直播交接不读取这份私有回查。改口与审批仍使用各自的执行授权。

私有视频选材的每项成果绑定一个主帧。后台 Responses 提交候选，前台 Omni 按号主当前要求选材、写理由并核对文字。独立网页出处可以共引；附加视频时点须有同源同窗的抽样回执。工坊从持久回执显示 BV、分 P、实际采样秒数、链接与覆盖缺口。单帧只覆盖该时点，同窗多帧仍属抽样。音轨需要独立听审依据。一般文字研究可继续在一项内引用多份来源。

主帧称呼复审核对标题及理由的画面依据，包括问句预设的物名。整句对照两边沿用同一物名时，逐字段提取的该词另作局部复读。局部读图只接收原帧与位置坐标。返修后按最终提交文字复审未锁定字段。私有任务的 `plan.visual_reviews` 保存送审原句、初采与库存观察、主帧和时窗、逐阶段回包及最终定位词，供排查漏判和误拒。

私有视频成果中，若某项标题或理由在局部返修后仍未通过，工坊可交付本轮已审通过、引用仍有效的其余项。缺口按原项号注明未通过的字段和原因。号主从另一端打开该版时能看到保留的正文、证据和缺口，也可查看先前版本。

[Chats](../tuber-studio.md#号主对话与任务)提供 Higgs 式双工语音会话。语音、文字、获准视觉输入与后台任务接入同一 Agent。实时 Provider 负责感知、重叠语音与输出，Agent 负责状态、统一记忆、授权、后台工具和任务结果。原生双工工具可用时接入同一工具校验与审计。也支持由确认后的用户语句把工作交给后台 Agent，结果按任务 ID 回流，挂断或推理断线后从活动恢复。 [Omni 与 Avatar API](omni-deployment.md) · [Higgs Realtime Duplex](https://www.boson.ai/blog/higgs-realtime-duplex)

目标参照 ChatGPT Dots 公布的持续运行、跨入口接续、多任务、主动查资料、进度查看、纠偏和审批体验，及 ChatGPT 的记忆摘要与控制。产品资料用于确定可观察行为。Tuber Studio 的状态存储、工具权限、终端和模型属于本项目设计。 [Introducing dots](https://openai.com/index/introducing-dots/) · [Meet dots](https://learn.chatgpt.com/docs/dots) · [Dots 权限与活动](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs) · [ChatGPT 记忆整理](https://openai.com/index/chatgpt-memory-dreaming/)

## 入口与能力

通用能力包含计划与多步工具循环、并行子任务和结果合并、研究与网页搜索浏览、读附件及在指定工作区生成文件、可授权的连接器和沙箱代码执行、定时与事件触发工作、审批、通知、取消和恢复。文本网页、交互式浏览器、附件、文件和代码执行作为独立能力注册。交互式浏览器可查看进度并接管。文件和代码工具只访问明确提供的输入和隔离工作区，由后端限时、限网、限资源，输出以可下载工件返回。电脑屏幕、麦克风、游戏输入及账号连接各走显式设备或应用授权。现有 Provider 负责模型推理，工具执行和凭证留在业务侧。

底座使用稳定的 Agent 与认证主体标识。应用层提供角色配置、受众、场景及可用工具。领域适配器提供事件、可执行动作和可核对结果。底座通过注册接口调用适配器。角色卡与 B 站 UID、直播场次、TTS 和游戏状态都由相应适配器提供。通用任务、记忆、模型接入和活动接口在未配置这些适配器时也可运行和验收。

## 常驻、任务与恢复

业务主机维护会话、事件、任务、工具及记忆的唯一可写状态。浏览器可离线，服务器仍处理已获准任务。业务服务重启后从检查点继续，推理节点只负责调用。模型在有交互、观察结果或到期工作时按需运行。业务服务离线和推理不可用分别展示。 [跨主机规范](distributed-runtime.md)

| 持久实体 | 需要表达的状态 |
| --- | --- |
| 事件与会话 | 来源事件 ID、Agent、主体、渠道、可选场景标识、发生时间和接收顺序。传递消息、工具结果、领域回执及计划触发。同一来源重放幂等。 |
| 目标与任务 | 任务 ID、来源、所属主体与 Agent、按需附带的领域绑定、意图和完成条件、步骤检查点、依赖、预算、截止时间、权限版本、待输入／待审批／待资源状态、子任务与成果链接。多端复用同一 ID。 |
| 工具调用 | 调用 ID、工具与参数、对应任务、授权及前置状态、尝试、结果或待核对状态。涉及外部动作时先持久化执行意图，再交给适配器，并以适配器的实际结果推进。 |
| 计划与通知 | 一次／周期／事件触发条件、时区、可执行渠道、暂停／撤销、最近及下次触发、重复和失效处理。通知带任务或来源链接，去重后发给获准的受众。 |

运行顺序是接收事件并判定作用域 → 保存当前修订的工具计划 → 按步骤校验并执行工具 → 记录结果和检查点 → 继续、等待或交付。普通闲聊可一次生成。显式工具与快捷操作走同一执行边界。计划限制可执行工具和用户明确指定的步骤次数。条件读取本轮已保存回执，缺少可核验条件时停下。工具参数使用已注册的契约，网页地址来自目标中直接给出的链接或本轮检索回执。模型进入推理前若被共享网关拒绝准入，任务保留原游标并等待后续准入。

后台任务的交付由本次修订的已保存工具回执生成。缺少可用事实、明确要求的只读工具或有效执行回执时保留已取得的材料和缺口，任务显示未完成。相同只读请求后续成功可解除该读取错误，但仍遵守用户的重试限制。搜索候选链接保留作为发现线索，事实引用绑定已打开来源。转题或更正产生新任务修订，旧回执仍可回查。

独立任务可并行。会话和各适配器声明的控制资源按键保序，例如同楼回复、同一私信会话和同一游戏会话。当前交互优先使用闲置生成机会，同时保障后台推进并遵守已接入的运营公平规则和直播时限。后台任务达到单步预算时保存进度并报告等待或失败原因。委派继承父任务的身份、可见范围和更窄的能力，带独立预算及回传产物。纠偏更新目标版本，已受理的改变从下一可中断边界生效，尚未提交的旧动作失效。停止区分当前生成、指定任务和后台计划，各适配器另提供急停及接管。取消未执行动作，已发出但未知的副作用进入核对。重启、网络断开和客户端重发按原 ID 查询。已确认动作可被续接使用，未知结果先核对，按工具语义再决定重试。

允许号主安排一次或重复事项、订阅获准来源的事件和监控条件。任务可提出有明确目的的下次检查时间或等待条件，调度器按既有权限和时限保存。主动调研可读取获准来源并准备私有材料，后台事件按既有授权启动领域任务。安静时段内非紧急通知留在活动页，重复发现合并。扩大受众、改变权限、公开发送和游戏输入依各自的授权和控制权完成。客户端通过活动、状态快照及可重连续读的事件查看进行中、等待、完成、失败、取消和待核对。任务视图展示本轮交付与可展开的原始回执，运营和直播状态直接显示在各自的工具步骤上。

## 工具、身份与交付边界

- 指定视频的取材或投稿页遇到平台 HTTP 412 时，主工具回执记录 BV、分 P、读取阶段和状态码。缺少必要材料时，号主任务列出可补的来源、授权已有素材或稍后续办的选项。已取得的网页正文、字幕和画面保留在原读取步骤。
- 私有工坊可将号主授权的原件目录只读挂载，用 `TUBER_PRIVATE_SOURCE_MANIFEST` 指定清单、`TUBER_PRIVATE_SOURCE_URL` 指定对应的 BV 和分 P 原始网址。目标明确授权该分 P 后，视频、相关检索和已收录的来源页才使用归档。当前平台账号可以为空。其它检索和获准的网页补读走原有工具。工坊在读取时打开清单，归档故障随相应步骤返回，普通聊天和历史可独立使用。
- 归档投稿及节目元数据保留原网址。画面按原件呈现时间戳换算为原分 P 秒数，回执列出左闭右开的可用时窗。实时平台可达性单独记录。
- 归档首轮读帧与私有创作使用同一视频文本结构。投稿题名、分 P 名、作者、投稿简介和归档节目资料各随其原网址使用。清单 `source.description` 可保存投稿简介，`source.subtitle_segments` 可保存该 BV／分 P／CID 的字幕原文及 `start`、`end` 秒；缺项保持缺失。素材窗口和号主授权共同限定使用的字幕。创作以主帧能支持的普通描述、时码和出处交付，节目背景不能单独证明画面中的物件、人物身份或剧集对应关系。
- 每个工具声明结构化输入输出、适用受众、读／写及外部副作用、权限范围、是否支持取消与结果核对。业务端验证账号／角色、对象、参数、权限和版本。浏览网页、文件、弹幕、评论及模型文字只提供数据，自带的指令无权授权操作。
- 管理会话、角色绑定的号主、运营所登录账号、观众和平台收件人分别绑定。读取角色绑定号主的主页使用已核验 UID 和只读接口。读取绑定、重新核验主页、查近期公开投稿可组成任务。登录账号变化不替换角色绑定，绑定资料变化使该读取结果重新核对。绑定缺失、查无结果和平台不可用各自可见。
- 工具调用、审批和交付使用相同的授权范围。需确认的动作展示目标、渠道、拟发送内容或动作参数，确认绑定版本和期限。已有明确自动授权的同一动作不重复确认。暂停和撤销先阻止新的相关动作，未知结果只沿原回执核对。已有业务规则继续控制草稿审批、渠道额度及发送。
- 权限过滤在召回与工具调用前完成。跨向公开场景只使用可公开来源或经许可、可复核的派生材料，并在送出前复核来源版本。草稿、模型自述、生成完的音频和发起中的动作分别显示。平台成功回执、实际播放完成及真实游戏执行结果是各自的完成证据。

## 精细化委派与控制

号主可以在一句话里指定做什么、对谁或什么资源做、做多少、何时做、在什么条件下继续、何时停及把结果交给谁。Chats 把这些要求保存到同一任务的当前修订，活动页显示已理解的范围、接下来的动作以及仍需号主决定的事项。视频、直播、游戏、连接器和受限工作区遵循同一个任务规则。 [Dots 的任务与记忆](https://learn.chatgpt.com/docs/dots/tasks-and-memory) · [Dots 的活动与控制](https://learn.chatgpt.com/docs/dots/controls)

| 控制维度 | 任务应保存并执行的约束 |
| --- | --- |
| 来源、身份与对象 | 记录实际连接、登录账号、角色、渠道、读取位置和输出受众。人、会话、消息、评论、视频、直播场次、游戏存档、文件和设备均用适配器核验的稳定标识及来源绑定。昵称用于查候选，重名或跨平台同名时由用户选定身份。读取公开主页、读取私有会话和联系对方分别核验能力和权限。 |
| 时间、筛选与覆盖 | 记录业务时区、起止时间和取样截止点。`今天` 在一次性任务确认时解析为对应业务日，周期任务在每次触发时解析。单独表达来信时间、同步游标、未读、待回复和已回复。由适配器按可用数据执行筛选，返回覆盖范围、排序和缺口。目标缺少所需平台信号时提示选择可核实的条件。 |
| 排序、数量与排除 | 明确按时间、优先级或用户给定顺序选取，排序冲突时用稳定 ID 定序。「最多三条来信」「三个人」「三次发送」是不同计数，限定的计数在业务事务中落实。工作开始前保存本轮候选对象与实际排除理由。快照外的新事件按后续任务或用户明确指定的持续窗口处理。涉及未知发送结果时保留原计数占位，沿原动作核对。 |
| 步骤、条件与完成 | 保存明确的先后、依赖及跳过条件，条件引用同一任务中指定步骤和对象的可验证字段。「只看／先起草／先问我／符合才发／失败就停」会约束可执行步骤。条件未满足时记录跳过，条件所需数据缺失时等待或给部分结果。完成判定核对覆盖需求和真实回执。 |
| 权限、改动与交付 | 区分读、起草、通知号主、对外发送、修改及控制设备。授权绑定能力、对象范围、内容或参数、数量、有效期和触发条件。已有授权范围内按既有规则推进，需确认时展示实际动作。改单产生新修订，保留已核实结果并撤回尚未提交的旧动作。通知、文件、视频引用和公开表达各按实际选择的交付渠道发送。 |

### 任务怎样落到现有 API

1. **入口和持久状态。** 沿用 Chats 的 `POST /api/chat/intelligent/stream` 和 `POST /api/agent/tasks`。保留 `request_id`、自然语言 `goal`、现有一次预约 `run_at`，并在业务侧把本次修订解析成可检查的对象选择、操作约束及完成条件。先保存再执行，相同请求重发查询原任务。新结构作为兼容扩展，由旧 Chats、活动页、其他客户端共用。 [Chats 接口](../../../src/tuber_studio/agent/operator_chat.py) · [任务接口](../../../src/tuber_studio/agent/task_api.py)
2. **能力选择与授权。** 业务端从当前主体获准的连接、设备及领域服务构造工具目录，按此任务的读取、草稿、写入和受众缩小可见能力。模型从目录规划并提出结构化参数。选择集合、限额、顺序、条件与权限由业务程序验证。通用 Agent 通过适配器内部服务方法执行，沿用原账号围栏、调度和事务。`/v1/chat/completions` 或按能力协商的 Realtime 只负责推理。浏览器和代码执行在获准环境内使用，平台支持的受管发送由领域接口办理。 [现有工具注册](../../../src/tuber_studio/agent/task_tools.py) · [部署接口](omni-deployment.md#首版协议与-provider-边界)
3. **准备与执行。** 查询返回带游标的候选、来源和覆盖。准备动作固定对象与正文或参数版本，返回草稿、可审阅的动作或等待状态。需要审批时沿用 `PATCH /api/agent/tasks/{identity}` 的 `revision`、`action` 和 `step_id` 控制，域内审批仍按既有规则提交。执行前重新读取身份、授权、对象状态和去重回执。提交意图先落盘，每一步有稳定幂等键。写入结果由领域服务确认，未知提交只核对原记录。 [任务与恢复](#常驻任务与恢复) · [运营事务与回执](../operations/operation-continuations.md)
4. **中途控制与可见反馈。** 用同一个任务 ID 跟踪子步骤、委派、外部动作、产物和交付。用户可以缩小对象范围、停止待办、补材料、变更通知和接管需要人工完成的动作。区分等待输入、权限、执行资源、平台核对、部分完成和失败。活动页能展开原始回执，展示实际读取、选中、跳过、起草和成功的对象。回到另一台设备接同一进度。项目和单次任务过程材料按作用域保留，共享记忆只吸收有来源、获准且适合跨场景使用的内容。

## 实现取舍

独立建设共用的持久任务与工具执行边界。接入号主工作台时替换原意图白名单和单次分发。底座依赖通用存储、模型接口及能力注册，由应用层注入领域适配器。消息流、Provider、运营调度、播放与游戏适配器各自维护已有语义。首选在现有 SQLite 单写者上实现任务与检查点，复用领域事务和回执。LangGraph 的检查点／长期存储分层和 Temporal 的工作流事件历史可用作语义对照。引入框架需证明能保留同一业务写入权并改善实际恢复或维护成本。 [LangGraph Persistence](https://docs.langchain.com/oss/python/langgraph/persistence) · [Temporal Workflow Execution](https://docs.temporal.io/workflow-execution)

Provider 可用原生工具调用或经验证的结构化调用协议。模型按当前能力挑选工具并消费结果，执行授权始终在业务端。先测现行 9B 的开放对话、中文指代和多步工具能力。对照使用相同证据和工具、不同 Provider 的表现，将缺证据、路由、工具、模型理解和表达分别定位。语音实时路径保留短调用和可取消期限，复杂规划走异步任务。

## 验收

| 范围 | 可观察结果 |
| --- | --- |
| 通用底座先验 | 用通用 Agent 和真实 Provider 从工作台完成开放对话与多步工作，例如检索获准材料、委派独立核查、整理并生成文件。关闭客户端、重启服务并从另一设备接续，验证纠偏、任务取消、审批、定时和事件触发、通知、权限撤销、未知副作用恢复及可编辑记忆。该用例可独立运行，无需加载角色卡或连接运营、直播及游戏服务。 |
