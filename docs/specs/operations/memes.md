# 共享表情包契约

本规范维护共享表情图库、模型选图和图片传输。私信与动态沿用各自的来源、审核、发送频率与回执。直播表情动画见[直播与媒体](../live/live-and-media.md)。

| ID | 要求 |
| --- | --- |
| MEME-01 | MUST 保留素材作者、来源与修订。已有六个 GIF 保留原字节和启用选择，八张静态表情初始启用。启用、禁用及删除选择跨重启保留。 |
| MEME-02 | MUST 角色共用一个图库，私信与动态使用同一份启用列表。模型在启用项中选择一个 asset_id 或 null。使用时校验素材状态与字节完整性。 |
| MEME-03 | MUST 上传为内联图片字节，单图最多8MiB；只接受实际PNG／JPEG／GIF／WebP，并有原生解码、尺寸、帧数、超时与并发上限，不接受SVG、任意下载地址或本机路径。动画保留原文件，不能由此声称平台支持动画播放。 |
| MEME-04 | MUST 用户上传原件持久保存在独立图库，不作为媒体缓存自动清理。已有项目素材只做引用，不因图库删除而删除项目原件；正在审核、准备或结果不确定的草稿占用图片时禁止删除。 |
| MEME-05 | MUST 模型选图为独立的小结构阶段，不把图片ID混入正文JSON或让模型绑定账号。默认关闭自动选图；开启后仍沿用模型思考配置、生成锁与父轮预算，选择失败停待审，不自动发出替代结果。 |
| MEME-06 | MUST 私信在文字和单图片中二选一，切图后重新审核；原文字保留作审阅及文字替代，不暗中连发两条或作为已发送内容记入记忆。图文动态保留正文并最多附一图。图片草稿不能把复制文字冒充图文交付。 |
| MEME-07 | MUST 上传前检查授权，最终提交前复核来源、账号、角色、启用状态与发布权限，最终发布才预约同一来源的唯一意图。上传失败不代表已发消息，可重新准备；最终提交无有效回执、超时或发送中重启保留不确定状态，禁止自动重发。 |

模型选择只使用图库标题与情绪元数据，不宣称已理解图像内容。私信的简单问候、致谢、情绪互动可以选择单图；事实回答、重要信息及证据引用保留文字。动态图片不能替代正文的来源与隐私校验。评论仍使用文字回复，不由私信或动态图片接口推定具备评论图片权限。

管理预览可查看禁用素材。素材和草稿占用保存在本地数据库，预览通过认证后的本地接口提供。共享文件按 SHA 校验。可选生成服务通过 `MemeGenerationService` 复用图库校验，生成图片初始未启用。

实现参考[astrbot_plugin_meme_manager](https://github.com/anka-afk/astrbot_plugin_meme_manager/tree/d5e9475b00669aecd6596bf49af159c889725a3b)的分类、角色图库和受限选择方式；图片传输协议核对[bilibili-api-python 17.4.2](https://pypi.org/project/bilibili-api-python/17.4.2/)，不引入整套机器人框架或SDK依赖。既有鲸鱼素材的作者、来源与声明见[形象清单](../../../assets/whale/manifest.json)。

验收覆盖原图与动图字节保留、跨角色和渠道共享、禁用与删除占用、无效 ID 与篡改、模型选择失败、单条最终发布、上传失败后人工重试，以及结果不确定时核对原提交。新增静态图的上游图集及裁切帧见[素材清单](../../../assets/whale/memes/manifest.json)。
