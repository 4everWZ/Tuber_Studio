# 共享表情包契约

本规范维护共享表情图库、模型选图和图片传输。评论、私信与动态沿用各自的来源、审核、发送频率与回执。直播表情动画见[直播与媒体](../live/live-and-media.md)。

| ID | 要求 |
| --- | --- |
| MEME-01 | MUST 保留逐图作者、原文件出处、来源修订与许可。原有六个角色 GIF 保留启用选择，八张原图集静态表情、六张动作表情和三张 CC0 投稿表情初始启用。启用、禁用及删除选择跨重启保留。 |
| MEME-02 | MUST 角色共用一个图库，三个渠道使用同一份启用列表。允许图库配图时，模型可选一个已启用的 asset_id。使用时校验素材状态与字节完整性。 |
| MEME-03 | MUST 上传为内联图片字节，单图最多8MiB；只接受实际PNG／JPEG／GIF／WebP，并有原生解码、尺寸、帧数、超时与并发上限，不接受SVG、任意下载地址或本机路径。GIF 登记须核对完整数据块并逐帧解码。内置表情失败时显示名称、文件和原因，同一图库读取错误跨页面只列一条。动画保留原文件，不能由此声称平台支持动画播放。 |
| MEME-04 | MUST 用户上传原件持久保存在独立图库，不作为媒体缓存自动清理。已有项目素材只做引用，不因图库删除而删除项目原件；正在审核、准备或结果不确定的草稿占用图片时禁止删除。 |
| MEME-05 | MUST 配图与正文分开生成。工坊绑定渠道和账号，工作站后台在一次调用中决定沿用正文、选图库图或用角色参考生图。各渠道读取统一的图库和生图开关，待审核草稿显示失败原因。 |
| MEME-06 | MUST 旧单图片私信仅发图片。图文私信明确绑定图片和正文，按图片、文字顺序发送，两步独立保存消息 ID。图文评论与普通图文动态随正文附一图。换图须重新审核。图片草稿不能把复制文字冒充图文交付。 |
| MEME-07 | MUST 上传前检查授权，最终提交前复核来源、账号、角色、启用状态与发布权限，最终发布才预约同一来源的唯一意图。上传失败可重新准备。最终提交超时、缺有效回执或发送中重启时，保留待核对状态并查询原提交。 |

模型选择只使用图库标题与情绪元数据，不宣称已理解图像内容。工作站私信可按来信和正文选择图库配图、生成角色配图或纯文字，图片可随完整正文发送。人工明确选成单图的草稿仍按单图发送。动态图片不能替代正文的来源与隐私校验。视频一级评论使用评论端点的 pictures 表单，核对 BV 和资源 ID。楼内回复使用纯文字表单，核对楼根和父评。隔离传输验证请求格式，账号发图权限以平台实报为准。

管理预览可查看禁用素材。素材和草稿占用保存在本地数据库，预览通过认证后的本地接口提供。共享文件按 SHA 校验。工作站后台配图任务按账号、角色、渠道和原始来源保存决定。图库附件绑定 asset_id 和 sha256，生成配图绑定 artifact_id 和 sha256。各草稿通过认证接口预览自己的工件。

实现参考[astrbot_plugin_meme_manager](https://github.com/anka-afk/astrbot_plugin_meme_manager/tree/d5e9475b00669aecd6596bf49af159c889725a3b)的分类、角色图库和受限选择方式；图片传输协议核对[bilibili-api-python 17.4.2](https://pypi.org/project/bilibili-api-python/17.4.2/)，不引入整套机器人框架或SDK依赖。既有鲸鱼素材的作者、来源与声明见[形象清单](../../../assets/whale/manifest.json)。

验收覆盖原图与动图字节保留、跨角色和渠道共享、禁用与删除占用、无效 ID 与篡改、模型选择失败、单条最终发布、上传失败后人工重试，以及结果不确定时核对原提交。新增静态图的上游图集及裁切帧见[素材清单](../../../assets/whale/memes/manifest.json)。

## 对话宠物

手动选图和前台 Omni 共用角色级服务。清单取当前角色绑定的形象素材，以及该清单配套的已启用表情。自有图片沿用角色清单的来源与 `license_status: owned` 声明；第三方图片须有作者、许可名称和 HTTPS 来源及许可链接。候选携带已有资源 ID、名称、已登记的风格、情绪和实际动静状态。只有共享图库身份的图片不能据此认定为当前角色。大肥鱼内置「花花」「被窝」「鲸鱼思考」保留档案馆的原始 WebP 和投稿人 1cyberlangke1 的 CC0 声明。[原投稿与授权](https://github.com/lmy414/ai-girl-stickers/issues/32)

选中的资源按角色 ID 持久保存。打开对话、重新进入或其他设备刷新时，随角色读取当前选择。清单中的图片失效时显示角色默认形象。Pets 显示开关独立，隐藏时换图会保存选择，打开后可见。手动入口可查看来源、选图或恢复默认形象；前台按清单中的现有风格、表情或名称选资源。

Python 调用方从本轮已绑定身份取 `character_id`。用 `await runtime.pets.options(character_id)` 读取 `items`，把选中项的 `asset_id` 交给 `await runtime.pets.select(character_id, asset_id)`，传 `None` 恢复默认。`runtime.pets.state(character_id)` 回读当前选择，`runtime.pets.set_visible(character_id, enabled)` 接受严格布尔值。手动入口使用认证的 `GET /api/pets/{character_id}` 和同路径的 `PUT {"asset_id": …}`。角色切换后旧请求失效。
