# 私信运营契约

正文篇幅与独立运营生成额度沿用[运营正文契约](comment-operations.md)。邀请确认使用程序规则与真实账号关系，正文使用正常私信生成额度。旧配置 `channel_max_tokens` 继续可读取，当前流程不使用该额度，界面已移除对应设置。

渠道及正文生成的具体反馈、检查点、平台拒绝修订与未知发送核对沿[运营任务继续契约](operation-continuations.md)；原收件人、来源与私域边界继续由本规范维护。模型可与评论任务一样按需选择公开HTTPS页面，不要求来信先附链接；材料足够时直接回复。网页工具仍为单页、3秒取材及有限摘录，直播不接入该工具链。

私信是自主运营内的私密工作区，与评论、动态共用账号配置、当前角色卡和模型调度；不通过直播队列或TTS输出。真实平台能力与发送权限须另做账号验收，隔离传输测试不代表真实私信已经发送。

## 联系依据与发送状态

| 实际来源 | 行为 |
| --- | --- |
| 对方发来新私信 | 合并同人连续消息，自动决定回应内容。 |
| 对方在评论中邀请大肥鱼私聊 | 按作者、父评论及真实 @ UID 确定受邀者，自动首发并接原话题。 |
| “查到了私信告诉我”等约定 | 保留来源、目的和同一草稿；真实工具或任务完成证据回绑约定后联系一次。未完成不发送，不用模型自称完成作证。 |
| 普通提问、聊天，或 @ 自己的 OC／其他人 | 按原讨论公开接话，不因此开启私聊。昵称相似不算账号相同。 |
| 曾经聊过但无新来信、无约定 | 不主动找人。 |
| 我方已发、对方未回应 | 等待；同一事由跨入口合并，不追问或重发。 |

主动联系记录 `purpose`、真实 `trigger_source`、程序核对结果及发送状态。当前账号昵称与 UID、发言者昵称与 UID、实际父评论作者和真实 @ UID 随来源进入上下文。收件人始终取来源作者的 UID。明确邀请直接创建现有私信任务，省去模型渠道选择和首次联系的额外模型核对，正文只生成一次。

程序按已核验的原评论和账号关系入队。视频字幕和画面由公开视频任务独立取材，私信保留原评论以及相应通知来源。

邀请确认复用当前待处理评论或合并评论组，识别直接私聊请求及条件约定，并核对真实回复关系或 @ UID。引用中的请求、明确否定、第三方邀请、混合且无法确认对象的 @ 均不能建立主动联系。历史 root、parent、timeline 和 items 供解析人物关系，不能单独重新授权一次私信。当前评论撤回私聊意愿时，本组更早邀请失效。无法确认的来源留在公开处理路径，模型不能自行给它添加私信权限。

“查到了私信告诉我”等真实约定先保存为等待完成，取得绑定本约定、账号和 OC 的成功工具回执后，唤醒同一个草稿并生成正文。等待期间不先生成一段假定已完成的私信。普通评论或面向其他账号的旧候选进入 `not_initiated`。旧记录只有程序等待说明而没有邀请核对结果时，不启动约定任务、工具完成唤醒或重试。

`not_initiated` 表示没有取得主动联系依据，进入历史；`waiting` 明确区分等待约定完成、等待对方回应或等待有效邀请，不等于待人工审核。旧待发候选同样重新核对，旧理由不能直接获得发送资格。界面区分“回复来信”和“主动私信”，显示触发来源、联系目的与原回执；公开活动不展示私信正文。

审核模式同样执行主动联系依据核对。来源、账号或编辑状态变化时保留最新状态。正文输出无效则记录单次诊断并保留 continuation ID，显式恢复继续使用同一来源与检查点。模型错答不自动追加渠道判断或补救生成。

专门的 review 验收会话在 `starting/running` 期间阻止该账号的自动及手工平台写入；私信发送入口在刷新身份、生成或图片上传前检查同一写入限制。旧已审核稿不能借手工接口出站，未知回执仍允许只读核对。会话明确停止后解除这一临时限制，历史验收元数据本身不会永久封锁发送；自动发送权限仍按保存的设置执行。

当前平台适配接账号范围内的文本或单图片私信，图片来源与选择由[表情包规范](memes.md)维护。图片先上传准备，最终只发一条type=2消息，不自动补发原文字；只有最终提交才预约防重复意图。上传明确失败保留草稿可人工重试，最终提交结果不确定仍不可重发。仅使用固定HTTPS地址和现有登录凭证；不自动解决平台验证，不因可读推断可写。收信先确认登录UID，只导入属于该账号、来自该会话用户的正常文本；忽略本人、群组、撤回、系统或其他收件人的消息，不调用已读接口。最近20个会话、每会话30条是本轮读取上界，不声称已读完整历史。

评论转私信后，公开草稿只显示移交标记。私信草稿保留来源评论 ID 和用户身份，可在运营内审核、修改、拒绝、复制、发送或恢复未发送的生成失败。收件人由来源绑定，账号切换后按原账号隔离旧来信。视频评论和通知共用真实邀请移交路径，邀请原话和程序移交状态记录在实际私信任务中。

私信助手历史和长期召回按账号、收件人、角色版本和真实发送回执核验。回执对应的最终正文或已发图片描述可进入私域上下文。草稿和未核实提交留在运营记录中，公开召回始终隔离私信内容。

工作台在页内区分待处理与历史；发送、拒绝或持久复制成功后移出待处理并清空详情，失败保留正文。切换会话时立即清除旧来信和关系展示，迟到响应不能覆盖当前选择；未保存编辑按草稿保留，回来可继续。

好感区间为 −100 至 +100，新关系从中立开始，已有分值保留。评论与私信共用按账号、角色、用户 UID 隔离的档案。正负变化按来源去重并受冷却和日上限约束。直播短期观察与长期档案分层，好感只参与语气和熟悉程度，打赏金额、处罚与发送权限独立。

### 号主手动回复与接话

会话按账号、角色与对方 UID 隔离。以平台消息 ID 去重、会话序列排序并补页，区分来信、号主发言和已确认发送的角色发言。发送前刷新会话。平台明确关联或已确认发送可以结算来源 ID，语义覆盖不明时保留待判断。号主全部答完时结束待办，部分答完时仅继续尚未回答的来源。结果不确定的提交继续按原回执核对。

私信收件、发送草稿／回执与关系账本持久保存在本地数据库，与媒体缓存分开。模型活动窗口及来源检索索引沿用对话留存；原始私信和发送审计不因媒体清理或窗口到期被删除。这与原始评论、草稿和回执的独立保留方式一致。

收件／草稿身份、关系和私密scope包含当前已核验账号。同一账号内公私渠道共享关系；切账号不展示或继承旧账号私密窗口。旧无账号记录保留在旧范围，不自动认领给新账号。视频移交持有公开证据引用；父轮取消会收齐其未提交生成，压缩、修复和思考tokens均计入实际用量；自动批次不据此增加隐藏累计上限。直接私信仅在正文含受支持视频标识或延续该用户已关联话题时重读视频材料。

未提交的排队／生成任务在停止、网络失败和重启后保留为可恢复队列。服务冷启动待命，用户明确开始自主运营且已保存对应私信权限后，再按当前账号与OC范围少量补入恢复任务，给新来信留出位置。恢复按当前保存的自动／手工授权执行，不继承已经撤销的发送授权，也不恢复已归档的旧人设生成。有效新来信与真实邀请无需重新逐条审核；依据不足的主动联系等待或不发起。发送中断仍只核对原提交，已生成草稿与回执独立留存。

验收覆盖：新来信合并→自动回复→单次发送回执；真实我方邀请／第三方邀请分流、约定完成一次联系、同事由未回应不再联系；任意收件人字段拒绝；历史不追发；停止、取消和重启不重发；同昵称不同UID／不同OC隔离，同UID跨渠道共享数值；私信不进入公开素材；无凭证、平台拒绝和不确定结果可见。有效邀请在模型漏选渠道时仍入队，第三方邀请在模型误选渠道时仍不能发送。正文生成与真实平台发送分别验收。

缓存与收发路径、渠道质量及真实账号的证据与验收状态见[当前计划](../../plans/current.md#运营主线)。
