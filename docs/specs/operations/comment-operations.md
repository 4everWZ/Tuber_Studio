# 评论运营契约

首版优先评论浏览、导入、分类、草稿与默认审核，以下原P2标签保留以追踪输入；完整聚类／map-reduce／运营摘要等条目仍是未来验收目标，不表示已全部实现。

## 输入、分类与批次

运营正文按交流情境决定篇幅，角色style的min_chars／max_chars仅用于直播台词，不作为评论、私信或动态的生成／审核硬限。三者共用llm.operations_max_tokens，默认8192，可显式设置1–65536，实际输入与输出预留仍须满足真实窗口；直播llm.max_tokens与120字Reply结构独立保留。运营使用OperationReply与既有结构化Provider，账号、来源与事件引用继续由程序校验。finish_reason=length或空正文不作为完成输出。相邻短语循环和大量重复长段保留原文与诊断供审核，不追加自动模型修订。正常口癖、笑声和长文保留原文。

生成、审核及发送适配器采用统一256KiB UTF-8正文资源边界，不把原有100／120／500／1000字本地数值宣称为B站平台限制。平台明确拒绝与发送结果不确定分别记录，正文不做程序截断。网页完整保留正文供编辑；私信正文只在私信区域展示。

模型的行动、理由、目标和证据与可发布正文分字段保存。评论生成、人工审核和最终提交校验实际正文，明确泄漏结构字段或控制载荷的正文保留原稿和诊断，修正前不得发送。外层 JSON 合法也须校验正文。自然标点、正常引用与角色口吻照常保留，单条语义问题按诊断处理。正文以 `@用户名` 开头且用户名匹配已绑定回复对象时，名称与后续正文之间须有空白。缺少分隔的候选留审并由号主确认写法，楼内回复身份仍以 root／parent 和实际 UID 为准。共用正文边界已通过原样例回放和隔离发布验收，修订后的真实平台提交见[当前计划](../../plans/current.md#运营主线)。

点击发布即确认当前正文。手动发布核验当前 B 站账号、原评论与作者、历史回执和额度，按审核正文提交。账号资料更新时沿用同一账号已确认的正文。平台明确拒绝时保留原稿及原因，由号主修改或主动继续修订。手动发布全程零模型调用。当前账号已直接回复同一目标时，草稿结清为「账号已在原楼回复」，保留可核验的号主原话。平台动作和额度见[自主浏览](autonomous-browsing.md#互动与发布)，评论点赞在运行记录中审核与查看。

生成错误、平台反馈修订、检查点继续与未知发送核对沿[运营任务继续契约](operation-continuations.md)，继续保持评论来源与原有审批方式。

读取／导入、选择评论、生成和审核组成同页连续路径。读取后仅展示该视频来源并清空旧选择；生成时显示本任务进度，结果按本次任务实际生成／更新时间优先，不混入无关旧草稿。生成任务成功提交后清空本次勾选，失败保留选择；已有草稿可直接编辑，不再勾选重复生成，不覆盖原稿。工作台把草稿审核和自动刷视频回复结果放在同一页，状态横向选择。默认待办排除已发布、已拒绝、已持久标记复制或已移交私信的条目；这些操作成功后清空对应选择与右侧详情，刷新不自动重新选中，历史筛选仍可查看。保存／审核通过但未发布的草稿仍留在待办。仅复制未审核或尚未保存的正文不冒充处理完成。编辑区提供保存、拒绝、发布、复制；发布一次操作保存当前正文并人工审核提交，无需重复确认。当前角色的历史版本草稿可手动发布，保留原生成版本；自动任务仍绑定当前启用版本。同一楼层生成、保存和发布按会话串行，等待后刷新来源，防止视频评论扫描和消息通知同时回复同一目标。

草稿队列在勾选首项后进入复选模式，展示跨页已选数量及当前筛选下的全选／全不选。一次提交全部已选可发布草稿，按渠道、草稿 ID 与已见更新时间冻结选择，逐项走同一手动发布流程。列表排序不改变同楼顺序，有实际评论时间时按时间提交，缺少时间时按平台评论 ID 排序。每条处理完立即回传并更新已处理数量、结果及原因。连接中断时保留已收到的结果，其余按草稿状态和回执核对。重试沿用原提交状态和回执防重，待核对项仅核对原提交。

读取B站热门公开视频，接受BV／av／标准视频链接及顶层评论；外站、短链、非法资源不能成为任意URL请求。认证、权限、平台风控失败可见，不伪成功。以平台＋视频＋评论ID去重，以平台＋用户ID识别观众，不按昵称合并。授权的PlatformConnector.publish_comment(...)返回Receipt；接口可替换，不能从读取成功推断具备写权限。

单批导入1–1000条，可直接导入，也可选择预览规范化结果；预览不写入，不作为必须点击的前置步骤。field_mapping为目标→来源字段名，支持comment_id／platform_user_id／display_name／content／like_count／created_at，标准字段不必映射。错误保留输入。读取或导入后立即在同一评论工作台展示对应视频，选择、生成、审核和发布连续完成。生成任务持久关联所选评论与实际新草稿，完成后优先显示本次结果并选中首项；已有草稿明确注明，不冒充本次生成。列表分页，无内嵌滚动区。分类可筛选和人工修改，人工分类不被自动覆盖。

持久语义包括comment_items的平台、视频、评论ID、用户、内容、时间与分类；comment_jobs／drafts的批次、来源ID、输入摘要、角色不可变版本、模型、任务／审核状态及发布回执；job_runs的ID、kind、parent_id、状态、输入／结果引用和错误。重跑不能覆盖既有草稿或重复答复。

## 默认审核与自动策略

正常状态为 imported → analyzed → drafted → pending_review → approved/rejected → published/copied。生成草稿不等于已审核，通过／复制不等于已发布。手工发布可另存Operator完成标记，不冒充API回执。重启恢复待审核草稿，取消未完成批次而不假称完成。

自动浏览委托[自主运营](autonomous-browsing.md)唯一控制器调度，指定BV按运营设置中的来源处理。旧评论页独立自动浏览开关、轮询设置和重复发送限额已移除。自动回复使用统一发送限额，`0`不限，不再被遗留评论渠道默认值额外拦截。视频相关发言使用实际字幕或画面材料。

自动或审核方式由运营设置中明确保存的权限决定，开始不强开其它通道，旧手工草稿不追发。账号、来源、限额与平台回执继续校验；模型诊断不添加隐藏的发送开关。凭证不回显或放Prompt。提交中的HTTP以实际回执为准。

每次发布尝试只发一次平台写请求。成功码和有效评论ID同时存在才published并保存回执；明确拒绝保留原草稿及原因。超时、非JSON、无有效回执、发送中取消／重启、平台成功但本地记账失败均为publish_uncertain或不可重发状态，先只读核对平台。已发布／发送中／不确定草稿不可编辑、覆盖或直接重发。

### 只读回执核对

评论适配器按原oid、type、root、parent读取首屏20条，直接核验原始楼层字段、作者UID和实际发送正文；存在原rpid时只认该ID，无rpid时还须满足发送开始时间并唯一匹配。缺失root／parent不能用读取预览的回填逻辑补猜。type=1视频和type=17动态评论共用此规则，既有视频标识可先读取并验证其aid。

私信先读取当前登录UID，确认仍为原发送账号，再只读最近30条会话记录，核验sender、receiver、消息类型、正文、时间及原msg_key。该读取不标记已读。仅有图片草稿说明、没有原图片消息回执时返回unsupported；不拿说明文字匹配图片。动态文本有已知dynamic_id时读取详情，无ID时读取原账号动态首屏20条，核验作者、完整正文、文本类型及发布时间，唯一匹配才确认；缺少可核对的图片载荷时保留unsupported。

核对结果包含真实读取时间和覆盖范围；visible／not_visible且有匹配回执表示已找到对应记录。not_found、ambiguous、check_failed和unsupported不证明未发送，不生成重发授权。此接口仅执行GET，不提交正文、不调用模型；与修订决策、发布授权和前端工作流分别验收。

## 子任务与资源

评论处理按平台资源和根楼持久合并。同楼一次只处理一个可执行头部，先按 SQL 限量再加载正文。新直接互动与私信共用优先级，普通回访使用后台机会。新一轮的准入、评论范围和正常收尾见[自主运营调度](autonomous-browsing.md#批次进度与调度)。

草稿生成、通过、复制与拒绝均不代表角色已经发言。上下文先保存最小原始评论事件，只有成功回执或只读核对确认后，才把实际发出的最终正文记入助手历史。完整楼内输入及视频材料留在来源缓存／草稿审计，不随每条历史反复重放。拒绝使该来源的未发送助手记录退出活动召回，原件保留审计；每日趣事的“已回”同样要求真实成功回执。

旧库维护可预览并清除明确拒绝且无发送凭据的草稿、相应的生成正文与未发记忆。独立观看记录、评论游标、去重状态、成功回执和待核对写入继续保留。清理后的已看视频仍可回访评论区。

comments保存thread_id／parent_comment_id；B站root标识楼、parent标识目标评论，顶层自身comment_id作楼ID，导入可映射两字段，旧顶层行回填自身ID。只读取公开返回中已有的楼内预览，不声称已抓完全部楼内分页。压缩与占用查询须指定单楼；旧整视频窗口保留但不混入新楼。楼内发布使用对应root和parent，不能改成另一个回复对象。

评论中的公开专栏链接、附图和 GIF 可作为独立材料按需读取。使用当前回复目标的 B 站公开专栏链接与平台返回的图片字段，按限额读取专栏正文或从静态图／GIF 抽取图像，由当前视觉 Provider 观察。来源绑定原评论、附件或链接及实际读取版本，记录可用摘要、抽样覆盖或失败原因。权限、风控、网络或视觉接口失败时，已有可信文字仍可用于回应。继续同一生成时复用已读材料和已保存的观察；附件观察独立于楼层身份和目标去重键。

草稿附上原句、虚构标记、所问字段及缺项诊断。提交状态按实际回执记录。

完整OPS批处理按 map → reduce：有界读取／CPU预处理、有限LLMWorker、合并／去重和审核。生命周期 pending → running → completed/failed/cancelled → merged/archived；每项有受限评论集、任务说明、deadline、取消信号、进度及错误，输出引用来源评论ID。主调度器控制资源并合并，子任务不能直接改角色核心或绕过发布策略。

直播生成、待播和当前播放优先；离线模型任务不抢占语音。网络／CPU并发不意味着多份GPU权重，详细模型驻留和全局锁由资源规范维护。评论与直播的短期上下文隔离，经确认长期信息按记忆权限共享。

| 验收 ID | 通过条件 |
| --- | --- |
| AC-11 | 至少1000条Mock评论可去重、分组、产出批次结果，live模式不耗尽模型资源。 |

另验映射／预览无写入、人工分类保持、角色／视频隔离、错误与取消／重启恢复、单次写入和不确定结果防重发。真实写入须以配置账号的实际平台回执验证，不能由隔离传输测试推断。

## 评论转私信

启用[私信策略](private-messages.md)后，程序从真实评论关系确认面向本账号的邀请，并在生成前绑定原评论作者。公开草稿只保存移交标记。私信正文与平台回执由私信工作台维护，公开楼上下文只收录公开交流。自主运营按已保存的发送权限处理，手工生成进入审核。
