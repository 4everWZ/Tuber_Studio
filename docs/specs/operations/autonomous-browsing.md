# 自主浏览与互动

本规范维护视频发现、内容证据、通知回应和自动化调度的共同契约。评论审核、私信正文与关系分别由[评论](comment-operations.md)、[私信](private-messages.md)和[角色／记忆](../foundation/runtime-and-characters.md)规范维护；上下文计量沿用[上下文与压缩](../foundation/context-and-compaction.md)。当前部署的实测范围见[运营验收](../../plans/current.md#运营主线)。

## 授权与配置

review验收沿用生产的持久任务、模型行动与2∶2∶1调度。所有启用渠道先显式设置为审核方式，再通过`POST /api/automation/review`开始一组新的验收批次；该入口不自动修改权限。review从启动到收尾完成按账号禁止手工及自动的平台写入，包含图片上传准备；修改自动开关也不能越过这条发送边界，正常读取和草稿生成继续。验收停止后解除本次写入栅栏，保存的审核权限继续生效；重启保持待命。验收session按账号和OC版本绑定，仅隔离批次恢复与重试，不清除旧暂停批次，也不重置观看、主回复及评论去重。暂停或重启后可向同一入口传`resume_session_id`恢复原session。达到测试视频数量只代表取得审阅样本，审核发布须在本次review停止后由操作者明确执行。

自主运营只有一个控制器，冷启动保持待命。视频、顶层留言、公开回复、通知读取／回复、私信读取／回复、点赞和动态按「运营设置」中实际保存的权限运行。开始使用已确认的权限；首页、对话任务卡和运营设置读写同一份配置。直播、音乐、ASR和视觉资源启用仍分别配置。

启用前展示实际账号、角色、功能、发送方式和额度，核验登录、平台能力与模型。缺失必要能力应阻塞对应功能并说明原因。预览不发送；已有草稿和首次启用前的平台历史通知不取得自动发送资格。已采集的待处理通知及未完成分页在暂停与重启后保留，用户重新开启后继续处理。临时网络失败及日额度等待保留唤醒时间。

普通停止进入收尾，停止接纳新自动任务和发现新批次。当前批次已接纳且可执行的任务可继续，提交仍复核账号、角色、来源、当前权限和额度。等待新材料重试、未来额度、人工审核或回执核对的任务持久留存，收尾可以结束。紧急停止立即阻止新的自动收发、取消可中止的在途任务并保存断点，锁定跨重启保持，须人工解除。已提交请求只收取或核对原回执。收尾中重启仍待命，已保存任务可恢复。

首页、顶栏和运营设置按同一后端状态显示启动检查、运行、收尾、待命、紧急锁定及阻断原因。确认操作后以服务器回报更新，迟到的响应不能覆盖较新的状态。各权限有文字和状态灯，私信收取与回复分别显示。大肥鱼自行发现、取材、判断和写稿。自动发送或待审核由保存的权限与[正文、来源和回执校验](comment-operations.md)决定。视频与收件箱共用调度器，关闭网页后继续运行。工作台启停及收尾已完成隔离验收，对话卡接入和目标部署复核见[当前计划](../../plans/current.md#运营主线)。

## 批次、进度与调度

每轮检索得到一批候选，大肥鱼选择视频顺序及独立视频子任务的并发数，并发不超过用户设置与推理节点承载能力。候选、检索页位置、逐项选择及其具体理由、子任务和批次状态持久保存。模型对每个候选填写行动、具体理由及整数优先级；每个 BV 在计划中恰好出现一次，程序按优先级从高到低派生有序执行列表，同优先级保持原候选顺序，不要求重复填写另一份视频清单。原始优先级与执行计划均可查看。

自动批次保留实际调用与 token 计量，不设置隐藏的调用次数、累计 token 或固定整批时间上限。单次请求超时、输出长度、真实上下文窗口及用户配置的发布上限继续有效。信息足够时，一次调用直接选择行动并给出正文；补读、补看画面、联网取材或继续翻评论按模型的实际选择执行。每个行动保存结合当前标题、材料或会话的具体理由，程序等待不填作角色判断。

评论区任务不以观看视频为前置，未看视频也可以直接逛评论。仅浏览评论时只获取视频身份和真实楼内文字，复用已有视频材料但不自动补读字幕或画面，不新增观看次数、观看进度、视频偏好或主回复决策。评论文字不能冒充视频内容；尚无视频材料时，回应只引用实际读取的评论。以后选择观看时才按观看任务计数。未开放评论权限时，该行动不出现在本批选项中。评论任务的恢复、重读仍保持评论任务类型，不转成观看任务。

候选批次持久调度，视频内容阅读、视频主回复决定、评论区／目标回复、消息收件箱分别保存独立进度。视频进度保存原字幕、画面观察、已读范围及来源，区分开始观看、读过部分材料与完整读完；取样画面不冒充看完整片。看后不发言也保存观看与主回复决策。自主观看行动同时记录对视频的真实偏好与具体原因，喜欢内容与是否发言分别表达；只看视频也可结束观看，不为填写偏好另加模型调用。后续评论复用已有材料，主回复决策按账号、角色和视频去重，评论回复按账号、角色和目标评论去重，不以角色版本或已看状态封闭整个视频。评论区回来时先检查最新，再从持久游标继续向下；本次深度处理完后保存位置并让出调度。同楼会话串行，等待后刷新上下文，不同视频或讨论可并行准备。

公开回复、私信、新视频共用 2∶2∶1 模型处理机会，空闲份额可借用。自有视频与动态的互动、收到的回复和 @ 优先于主动回访和其它讨论。在各自通道内，同楼／会话维持到达顺序，跨楼兼顾新消息和等待最久的任务。观看中新到通知和私信进入相应的持久队列，下一次可用调度机会处理，正在生成的请求继续。已看视频的评论回访进入公开回复通道，不占新视频份额，也不增加观看次数。恢复中的观看任务与新选视频共享视频通道。候选包含观看状态、上次访问和评论进度；同批同 BV 合并来源，同视频在途任务合并。原样重现的已略过标题沿用原选择，继续获取其它候选；稍后继续的项目保存到后续队列。

网络中断、人工暂停及服务重启保存原批次、当前动作、材料、已读范围和评论游标，恢复后继续未完成项目，不重新筛选已处理项，也不重新占用已开始观看的名额。重启保持待命，由用户恢复自动任务。相同任务的相同失败合并次数和最新错误，异常只影响对应任务。候选都有去向且本批在途子任务已收尾即可结束，待审核草稿和待核对回执不阻塞下一批。全批略过仍遵守检索间隔，不高速重取同批。发送结果不明确时只核对原提交。登录与模型配置等整条链路的阻塞显示在首页。

每个展示给模型的候选必须恰好有一个行动去向，可全部略过，顺序由模型决定。批次计划出现漏项、未知BV或其它结构错误时，原计划和具体校验反馈以`invalid`留存，本批不再自动重领或请求模型修订；程序不删除冲突条目、代填选择或把无效计划标为完成观看。

单次公开回应的行动理由与视频偏好理由各最多 1,024 字符，原生结构化解码直接约束这些字段，避免模型在一个理由字符串内循环直到耗尽输出；正文仍使用现有单次输出设置，不新增整批预算。输出无效不补造偏好，也不把诊断或恢复状态冒充观看结论；已完整验证的真实偏好可以保留，模型质量问题留在诊断和审核。

视频批次以观看及评论任务交接完成为收尾条件，不等待评论区处理清空。初选评论任务和观看后的回访复用原批次条目作为持久待办，由公开互动轮按workers消费有界快照；原条目只在评论真正处理完成后记为完成。同一批其它视频仍在执行或暂停时，已经交接的评论也可独立处理。队列按预览／运营、账号、OC版本及review会话隔离，同BV合并在途任务，沿用既有评论游标、目标去重与会话串行。

## 每日计数

业务日统一按 `business_timezone`，默认 `Asia/Taipei`。`daily_watch_limit` 与 `max_replies_per_video` 为 `0` 时分别不限。

| 行为 | 观看次数 | 视频回复次数 |
| --- | --- | --- |
| 读标题、封面后略过 | 不增加 | 不增加 |
| 观看任务首次开始执行 | 增加一次 | 不增加 |
| 继续同任务或中断恢复 | 不重复增加 | 不增加 |
| 看完不发言、只逛评论、回访、翻页与点赞 | 不增加 | 不增加 |
| 生成、保存、拒绝、复制草稿 | 不增加 | 不增加 |
| 平台确认发布成功 | 不增加 | 增加一次 |

每日观看与每视频每日回复各自计数、预占与恢复。同一视频的每日回复仅合计主评与楼内回复。明确失败释放预占，未明确结果保留占位并先核对，同次提交只结算一次。数据库事务同时预占最后名额与发送尝试，避免并发超额；草稿不占成功次数。达到观看上限后，已开始任务、评论与私信继续。某视频用完回复名额后，仍可只读浏览、按授权点赞或让出轮次，其它视频照常调度。

「运营设置」中的评论点赞默认关闭，可改为审核或自动。模型只能选择给当前已核验的评论点赞。目标按账号、资源类型、资源 ID 和评论 ID 防重，换角色仍复用该动作的提交结果。评论点赞单独记录平台回执，遵守账号全渠道写入上限，独立于公开回复渠道、单视频回复额度和回复冷却。平台提交结果不确定时，按原目标只读核对当前账号的点赞状态。评论回访在有界窗口内先检查新增，再沿已保存位置翻页。到达单视频回复额度时可继续点赞，待回复来源保留到下一业务日，恢复时沿原楼顺序处理。

发送结果跨午夜确认时，成功按回执的发布时间或确认时刻归日；未确认提交跨日保留待决名额，重复核对不改变已确定的成功日期。日额度等待保存唤醒时间，本批可以收尾并处理其它内容，到期后恢复原任务。

## 评论对象与回复

公开回应使用当前来源引用协议。当前账号身份固定在系统上下文，当前原评论优先呈现一次，root／parent／timeline 通过真实 UID 和正文引用关联；内部原始数据与来源四字段哈希不变。视频主评只取该视频元数据及字幕／画面，不混入整视频各楼对话；后台仍可读取评论检查已有主评。具体评论回复只带当前楼与相关材料，上传者和当前账号的关系按 UID 明示。评论原文与视频字幕／画面可并列引用，相关同楼的真实错事经历按来源召回，可自然承认、以meme自嘲或解构，不要求每次道歉，也不把错误正文作为回答示范。来源与清理规则见[角色／记忆](../foundation/runtime-and-characters.md)。长字幕的原生输出 schema 共享全部引用编号定义，不因行动分支重复展开而超限，不删减来源或提高节点复杂度上限。私信邀请在生成前由程序按真实来源和 UID 路由，详见[私信规范](private-messages.md)。

### 评论对象、分组与视频证据
- **连续评论分组**。同一作者、同楼、同父评和同提及对象的连续评论可一起交给角色，保留每条原文和真实 ID。回复仍绑定一个真实目标。审核和未知回执时保留覆盖预占，确认发送后结算；明确未发送的终态释放组内其他评论。
- **账号与回复对象**。使用已核验账号 UID，并分别提供作者、父评对象和已核验的提及对象。角色可旁观参与公开讨论。自己的视频下也要以父评和提及对象为准，上传者身份只补充没有明确对象的顶层评论。
- **视频证据预算**。基线通常请求三帧，自适应采样按分 P 时长和 Provider 能力取最多六帧。观看同时读取可用字幕和真实画面，可按时码局部补看。缺 CC 时可以配置本地 ASR 读取已准备的有声片段。视觉事实绑定分 P、真实时码和材料版本。证据不足时可继续读、暂缓或仅针对评论原话接话。以真实消费的材料、正确细节和运行成本确定默认预算。

## 模块职责

`discovery.py` 获取候选、合并来源并维护跨批搜索分页；`batches.py` 保存批次选择与生命周期并执行独立视频、评论任务；`decisions.py` 生成行动、具体理由与正文；`thread_context.py` 统一真实作者、父评论、根楼与 @ 参与者；`evidence.py` 保存真实材料和来源；`progress.py` 执行可恢复观看与租约；`comment_reader.py` 保存逐评论处理结果并读取新增、旧页和讨论楼；`quotas.py` 维护业务日计数；`publication.py` 发布和核对；`repository.py` 负责数据库事务；`task_views.py` 统一持久任务与无需Worker的标题选择视图。`service.py` 保留装配和业务入口，沿用 `operation_turns.py` 与运行时会话锁。

批次标题选择与全部逐项去向一起提交事务。程序不会因旧评论模块的历史 `auto_browse` 设置另启轮询链路；统一开关关闭与服务重启待命都覆盖自动浏览。清理空中断轮次只移除没有材料、判断、回复、继续任务或重试引用的记录；真实观看、发送结果、去重和可恢复进度保留。

## 工作台与诊断

左栏只保留自主运营一级入口，活动、评论处理、私信、动态、运行记录与运营设置在页内顶栏切换。首页按业务日展示运营活动，统计与分页同源。视频行展示真实阅读范围、兴趣及本次主评或楼内回复，既有跟评单独标明。新增跟评显示实际正文、原评论链接、回执及本账号开的楼／其他楼。只逛评论标明“只看评论”。私信显示对象、方向与结果，草稿保留其审核状态。运行记录按轮次呈现状态、完成了什么、行动对象和结果，详情展开排队、取材、角色判断、错误和续跑操作。活动详情展开状态在轮询更新时保留，任务筛选变化后清除不在当前列表中的旧详情；告警链接定位真实任务。列表没有内嵌滚动区。评论工作台负责审核、编辑、发布及回执核对。

活动中的「异常」与全局告警共用确认状态，可按告警和错误查看，标为已读后移出未读提醒，历史及对应任务仍可查。确认状态持久保存，同一错误再发生时只累计新增次数。达到发送名额上限属于正常延期，保存唤醒时间。旧运行记录可归档；功能稳定后的清理先预览范围并备份，保留原来源、已批准草稿、平台回执、待核对提交、防重标识及观看和评论进度。回访只追加本次真实行动。历史视频未存真实偏好时显示未知。

## 发现与材料

发现支持首页推荐、用户词、获准的OC词、显式热门和指定视频。空词默认推荐；推荐失败不得暗换热门或固定词。候选合并来源去重后交给模型选择；排除词、作者、分区、时长和时间条件先于昂贵准备。大肥鱼可以选完本批、全部略过或明确稍后继续，可以零留言。只读预览保留独立资源预算，不用于中断自动批次。

观看取材读取完整简介、真实标签、作者 UID、时长和分 P／CID。搜索结果的摘要用于候选选择。按语言顺序、同语言人工优先选择CC，保留人工／AI标识、有时间的片段、轨道、覆盖、获取时间及材料版本。缓存记录 ID 与来源版本分开，文件格式和取材时间变化不影响来源判定。发布复核以来源身份及实际材料内容为准。无CC、空或仅署名、权限／风控、网络与格式失败分别记录。没有有效CC且尚未取得真实画面材料时，不生成视频相关自动发言；不能用热评、标题、封面或平台摘要冒充字幕／画面证据。可用视觉材料的条件由下文视觉契约维护。

模型明确请求补看画面时，程序在原视频任务下保存有来源绑定的取材子任务，由现有视觉资源执行。完成结果才作为下一次角色决策的材料，失败和中断保留原来源与继续位置。该子任务只取材，公开发布仍经过原账号、队列和审批边界。

字幕按真实token有界分段，记录未读P和片段范围；派生笔记须引用仍存在的原文。兴趣、值得发言和是否已看分别保存；临时错误不永久归为不喜欢。模型只能返回受校验的有限计划、兴趣、意图、正文与证据引用。不存在的引用、未完整输出、超窗、依赖未读画面或材料过期均不能产生可发送候选。外部文字是数据，无执行、改策略或指定任意目标的权限。

内容判断按视频部分与材料类型呈现自然文本行，标题明确标为“视频第x部分（Px）”，内容块用[e1|00:15]这类短编号与起始时码标记。相邻短字幕可按停顿、标点及段落长度合并，保留全部非空原文和顺序，不删拟声词、不摘要或截断单个原段；空白行可省略呈现，后台原段仍完整保留。不同视频部分、轨道／版本或视觉帧不合并，未读原段之间不拼成连续块。模型只看到一次标题、编号、来源类型与覆盖情况；真实CID、轨道GUID、Provider版本和逐段精确时码保存在本次调用的typed绑定与原始材料。segments短表仅供后端生成允许引用的schema枚举，不在实际模型正文重复序列化。

模型最多选择 8 个内容块。返回后用独立ResolvedContentDecision展开为所有被选原段，内部展开数不冒充模型选择数，也不绕过ContentDecision的8项校验。未知或直接返回原ID均拒绝，缓存、任务、证据、意图与草稿继续使用真实segment.id；短编号只在当前调用中有效。正文的内部保留命名空间为`ref:N`，普通型号R1／R84无需来源白名单或网页豁免；正文泄露内部编号时保留完整候选待审，引用字段仍严格验证本次真实来源。同一内容呈现工厂统一服务分块计量与实际模型输入，source_kinds／has_visual及coverage继续明确本次材料。性能核对分别记录字幕本体、格式包和完整实际messages的token；schema仅在Provider实际写入prompt时计入，不用仅格式包的结果代替整请求。兴趣与发言判据沿用原约定；正文使用当前角色卡，分类的显式兴趣摘要按角色卡内容匹配。内容判断决定是否准备回应，公开回应输出只含本轮公开行动。对本账号的明确私聊邀请由程序在生成前路由。interest=like、worth_commenting=true、coverage_required=provided表示准备回应，该组合的reason为specific_detail；冲突保存原输出及具体字段诊断，不追加自动修补调用。既有一致性规则也以互斥分支表达在原生grammar，后验校验不变；该校验不检查或改写OC台词。

已登记大肥鱼的ContentDecision默认采用C6i分类视图：身份、人格、兴趣和情绪摘要绑定完整core／style／rules指纹；编辑人物卡或未登记人物回完整卡。任务清楚区分已有材料和仍需内容，保留原意图类别。只有分类中间块可在原相邻段基础上按480原字符／90秒目标继续合并；不跨分P／轨道、间隔、重叠或视觉帧，长原段不切，全部原文、原ID和精确起止时间留在后台，正文使用独立ref:N命名空间引用。fetched_at及空tags保留在后台原材料，不进入分类投影；完整简介、非空标签、发布时间、覆盖和缺失信息继续提供。重复命令只在至少3行共享完整shell单词前缀、无别名冲突且有净字符收益时使用明确的可逆映射。分块继续依据真实窗口及只读预览的显式父轮预算，不对所有视频设1500–2000 tokens上限；指定教程及同素材对照见[字幕输入结果](../../../evaluations/results/subtitle-input-e2b-20261102.md)。

正文ResponseDecision采用独立呈现：每条已选原段对应一个短编号[ref:1|起止秒]，移除逐段JSON及真实CID／轨道ID包装，保留全部已选原文、精确时码及完整thread。近期已发正文只在后端用于复读比较，不作为正文生成的例句；重复反馈保留当前候选与具体诊断，不重放整批旧台词。正文不合并原段，最多8条引用仍对应最多8条真实原段；纯文字来源也通过本次一一对应映射引用；当前被回复评论的原文直接显示在对应[ref:N]行，完整楼内上下文同时保留。已归档的审计正文不重新进入近期发言提示，回执与长期防重标识仍保留。共用生成恢复只验证短编号wire结果，未知编号或直接返回旧原ID均保留为无效输出，不自动修补；仅在最终返回边界恢复canonical ID并重新通过ResponseDecision校验，缓存、意图和后续目标绑定继续使用真实身份。正文输入格式版本纳入生成绑定及容量快照签名，旧格式wire检查点不自动复用；本次不新增正文词面或长度判据。

## 互动与发布

公开正文按交流情境自然决定篇幅，旧 public_max_chars 配置兼容读入后退役。decision_max_tokens 默认 8192，保留已有显式值，可配置至 65536。思考计入同一额度，实际请求受真实窗口与单次输出设置约束；只读预览另受其父轮额度和期限约束。VideoVisionConfig.max_output_tokens 通用默认 2048，可配置至 65536。配对的 Gemma 和大肥鱼视觉档使用 8192。正文资源、未完成输出与长重复段诊断沿用[运营正文契约](comment-operations.md)。

顶层留言与定向回复使用不同 root／parent 语义。平台通知、自有视频／文字和图文动态新评、普通回访共用持久公开互动队列。处理时按平台资源类型、资源 ID 和真实评论 ID 合并来源，核对当前账号、评论作者、目标、根楼和父消息。动态 ID 用于定位原动态，评论区 ID 用于读取和提交楼内动作。长楼分页保存进度，恢复先检查楼首页变化。当前账号的评论作上下文，生成前与最终提交前均按账号 UID 和直接父评核对号主是否已回复同一目标。核对成功后结清该待办并记录原话。涉及视频事实时使用真实视频证据，仅针对楼内原话时可直接用楼内材料。无法核验的类型或目标保留具体原因。首次通知轮询建立高水位，分页事件先持久保存再推进游标，保持平台未读状态。点赞／关注通知不触发发言。已看视频上的新事件继续入队，同楼保持来源顺序。

公开回应与私信移交共享意图，不能各发一份。私信仅联系真实来信人或当前已核验评论作者，来源公开楼及必要视频引用可单向带入私信。私信原文和私密记忆不进入公开候选或搜索。关系沿用UID＋OC及现有幂等增量；视频事实不写成角色经历或用户偏好。直接私信只按其实际关联补入视频，不使用当前浏览视频作为公共背景。

所有渠道经过同一账号写入仲裁，原子预占共享额度、渠道子额度和用户冷却。每个意图保留唯一首记录；明确拒绝后，后端可签发绑定原目标／来源、修订正文、审批方式及当前权限版本的一次性票据，追加子attempt，原始记录保持。所有attempt计入账号与渠道额度；同意图已明确拒绝的尝试不冒充已投递的用户冷却。票据原子消费，旧票、分支重投及目标变化均无资格。不确定结果先核对平台状态，确定读回成功才追加resolution；查不到仍待核对。不确定状态只冻结原意图，其他视频与会话继续处理；重启后仍只核对原提交，不重发。顶层留言按账号＋OC＋视频长期防重；角色版本升级、跨日或清缓存不恢复资格。成功须平台码和有效ID；可见性另记visible/not_visible/not_found/check_failed，查不到不回退发送状态、不补发。近期正文相似度与大量重复段落属于生成诊断，保留原文供审核，不追加模型修补调用，正常口癖与玩梗保留表达自由。

## 任务继续与平台反馈

生成结果、平台拒绝修订、预算检查点及只读回执核对统一遵守[运营任务继续契约](operation-continuations.md)。有效完成、有效暂缓、完整候选待审和无效输出分别持久保存；无效输出不会跨轮触发自动补救调用。观看与评论任务的自动执行只处理一次，读取失败保留到后续调度，不在当前任务内立即连试。真实网络中断、来源或容量失败继续保留断点，程序不伪造模型选择。无效评论保留按来源绑定的诊断，其它楼层继续处理。

字幕分块按实际Provider计数完整角色、任务、原文和Schema消息，保留显式输出预留及窗口余量，不以仅材料token数代替实际生成输入；计数探针同样共享生成锁。原文全部顺序分块。固定消息和最小片段已超过容量时保留容量检查点，同一容量配置的后续发现不反复尝试该视频；调整容量或显式重读可重新准备。

内容判断申请视觉补读仍遵循前述一次补读、CC优先及Provider身份规则。

浏览续轮仅复用同账号、OC和真实来源版本／canonical片段对应的已完成判断，角色或模型变化时重新核验判断的适用性；主回复长期防重不因OC版本变化解除，不重复消耗已完成chunk。ResponseDecision原输出若包含私信动作或路由尚未可靠解析，公开任务／通知DTO仅返回状态和私域入口；完整原文由私信列表的private_continuations按当前账号与OC展示，未因此创建私信草稿或收件人。私信内容与恢复记录仅在私信区域展示。

## 并发与资源

每账号可同时有一个视频轮次和一个公开互动轮次，分别计量。只读预览与自主运营按视频并发准备材料；自主运营为每个候选执行独立子任务；新视频取材与评论回访使用独立执行窗口，在用户配置和节点容量内并发，不让整页评论占住新视频准备窗口。模型继续共享唯一生成锁，平台评论提交也走同一写锁。公开材料在同轮合并在途读取，并跨轮复用有效缓存。任务持久绑定账号、角色版本、来源、输入版本、父轮及带代数的租约；显式预览预算／期限与自动批次的无限累计计量分别保存。占有、心跳、子预算预留、结算与提交校验使用事务；未发送任务可一次接管，旧代数禁止写回，发布中任务不得接管重发。控制存储故障应阻断写入。

父轮取消须收齐本轮子任务。自有投稿扫描核验当前账号确为作者，当前实现覆盖最近三条可见视频，动态和通知按[互动规则](#互动与发布)接入。私信按会话隔离，直播按既有资源优先级先行。记录队列／锁等待、阶段时间、合并、命中、防重、接管、迟到拒绝、限流和真实资源峰值。

每日观看及单视频回复按前述业务日计数；既有账号和渠道发送保护沿用滚动 24 小时尝试数。数量额度为 `0` 时取消该项上限，其他非零额度仍分别生效。开启或停止一个轮次不会改变同源防重和平台回执约束。

浏览原始材料进入独立browsing缓存池，统一展示容量、受保护和可回收占用，不重复计入临时或音乐池。任务及待审核草稿引用保护材料；空间不足停止新增准备。清理只移除可回收缓存；独立持久的已读材料和进度继续保留，派生判断仅在全部原文依据均失效时失效；不删审计、防重、关系、账号或私信。音乐最高15GiB保持原有含义。

## 视觉与管理接口

观看任务先读取各分 P 的可用 CC，并向当前配置的视觉 Provider 请求真实抽样帧。大肥鱼收到字幕、帧观察和时码后，决定补看、进评论区、发言或结束。可按已提供的材料编号定位想补看的时码。相同补读复用现有结果，更新后的材料保留已取得的原文和帧。评论回访复用观看进度。

取材详情显示「字幕＋画面」「仅字幕」「仅画面」或「取材失败」。视觉请求失败时保存该条的具体原因，有字幕仍继续。字幕和画面都缺时，记录取材失败并按该任务的时间重试。未配置多模态接口时，设置页显示字幕模式和多模态配置入口。

视觉日常请求校验实际 Provider、真实来源、单次图像体积、窗口和超时。设备压测用于部署验收。逐帧和联合请求均将观察绑定到 BV、CID、真实帧和时码。派生缓存按 Provider 身份和取样策略隔离，更换 Provider 后可复用原字幕。自动与预览共用候选数量，指定视频预览直接取该视频。检索游标决定候选轮换，已到期的重试随候选调度。

视觉Provider可独立设置思考开关、输出额度与超时；llama.cpp的显式思考设置进入实际请求。`sampling`子配置支持temperature、top_p、top_k、min_p、presence_penalty、repeat_penalty、seed及reasoning_budget_tokens；温度默认0.2，其余默认None，显式temperature=None时也沿用服务默认。仅llama.cpp适配发送非None值，思考预算放HTTP顶层，思考开关放chat_template_kwargs；完整sampling进入资源配置身份。取帧和视觉推理从各自执行时计时，默认60秒，可配置至600秒。只读预览另受其当前轮预算和截止时间约束。

管理接口沿用本机认证与同源写保护；运营设置展示实际账号、OC及允许的通道和发送方式。支持预览、审核编辑／拒绝、只读重读、停止和诊断。运营活动中的私信记录只取当前账号与OC，供操作者查看，不进入公开来源或公开模型上下文。报告从数据库事实生成，不作为额度或防重依据。

## 验证边界

受控平台测试覆盖行为和故障；真实模型另查事实、对象、渠道、重复及结构，不把合法JSON当语义正确。平台读取、图像理解、模型资源和真实写入分别验收；取帧成功不证明模型看懂，局部帧不证明看过完整视频。发送遵守操作者在运营设置中明确选择的自动或审核权限，诊断不会伪写成验收通过。


目标部署按以下七项验收。

1. 整批略过不增加观看次数，等待正常检索间隔，不高速重搜同批。
2. 选看任务首次开始只计一次；看完不回复仍保存已看状态及不发言原因，部分材料不冒充完整读完。
3. 回访已看视频先读最新评论，再接持久旧页游标；进入回复通道，不占新视频份额。主回复按账号＋OC＋BV跨版本防重，新增评论按真实目标ID处理。
4. 每个视频每日回复名额独立，主评与楼内成功回复合计；草稿操作不占成功数，未知回执先核对。
5. 网络中断、手动暂停和服务重启后继续原批次、材料与各自进度，不重复观看计数、原判断或提交。
6. 评论与私信持续到来时仍按2∶2∶1及空闲借用给新视频处理机会；同楼有序，独立讨论可并发准备。
7. 同一自动批次超过16次模型调用仍可继续，不制造隐藏累计调用／token或整批期限检查点；单次窗口、输出和明确取消继续生效。
