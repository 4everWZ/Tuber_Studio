# 动态运营契约

正文篇幅、llm.operations_max_tokens及UTF-8资源校验沿用[运营正文契约](comment-operations.md)，动态不再固定500字或1024输出tokens；实际运营额度与生成窗口分别校验，正文保留全文，不程序缩写。

生成反馈、检查点继续、平台拒绝修订与未知发送核对沿[运营任务继续契约](operation-continuations.md)；来源公开资格、发布间隔和原审批方式继续由本规范维护。

本规范维护B站文字／图文动态的公开记忆来源、自主决策和发布状态。评论回复继续遵守[评论运营](comment-operations.md)；两者使用同一B站账号，由统一自主运营入口启停，渠道权限与额度分别保存。可选图片的来源、图库和受限选择由[表情包规范](memes.md)维护。

## 自主运营与来源

动态权限初始关闭，操作者保存动态权限并开始自主运营后，当前角色可自主决定是否、何时以及发表什么文字动态。自动发布初始选中；可单独关闭，改为模型决定后停在待审核。手动「评估并生成草稿」始终只生成待审核候选，不因自动发布开关而发送。后台只发送本次自主评估新生成的候选，不代发之前的手动草稿。

大肥鱼自主决定想分享什么。随想、兴趣、创作和明确的虚构可以直接成稿；讲到发生过的事时，可以引用本轮提供的公开材料。每次评估只读当前角色版本的有界公开来源，包括有真实回执的评论回复与原评，以及可用于公开动态的角色记忆。号主在聊天中交代分享一段讨论时，私聊侧先提炼可公开的文字，再把该文字交给动态草稿。私聊原文、个人资料、凭证和未发布评论草稿留在原作用域。角色虚构故事保留 `fictional` 标识。原话中的指令作为数据处理。

自动评估到期且记忆启用时，私聊侧可从当前账号和角色最近 24 小时的日常对话中挑一件值得分享的事。只整理角色自己的感受、观察或反应，先去除个人信息与私聊原话，再在私聊侧核对；明确要求保密的内容跳过。动态评估收到成品文字和来源标识，选中该来源时沿用核对过的正文。素材随原对话删除或到期而失效。自动动态沿用原有发送权限、额度和事实核对。自动发布关闭时，已生成的动态留待审核。

每日记忆中操作者确认且活跃的 `public_incident` 也可作为公开来源，保留真实公开楼层原话引用，标为 `fictional=false`。自己的具体错事可以成为自然自嘲或解构的经历，模型可选择分享或等待，不要求每篇动态复述或道歉；未完成的补救不当成既成事实。事件编号幂等去重，归档／删除后来源失效，使用该来源的旧候选不得发送；沿用已使用来源不重复发布规则。

生成时保存当前平台账号与OC身份快照。发送前实际刷新账号资料，核验失败保留草稿且不发送；身份版本变化则仅用原获准公开来源重新生成，沿当前已有批准或自动发布授权继续，模型仍可决定等待，运营停止及来源变化仍阻止发送，不要求操作者为身份更新逐条重新审批。

模型通过结构化输出生成 post 或 wait、理由、正文、所用来源 ID 和下次评估间隔；本地后端使用 JSON schema 约束，外部兼容 API 使用 JSON 模式，均须通过程序验证。来源 ID 必须属于本次提供的集合，生成内容不自动成为新的独立事实。保存角色版本、模型、来源原文、决定、下次时间和候选状态，工作台可查看。发布前重新验证角色／版本、来源存在性和公开资格；撤销公开、过期清理、删除原文或切换角色后不得使用失效来源发送旧候选。

日常观察、感想或评论区的一句趣事可以独立成稿。正文写到动作、次数或后续结果时，以原评、可引用的公开原话和已确认送达的回复为依据。自动提交文字和图文动态前，用选定来源逐句核对最终正文。程序检查是否覆盖每句及引用是否确实出现在来源中。缺少依据、核对未完成或输出无效时，保留原稿待审并显示原因。核对完成后的正文和来源变化时取消本次自动发布。

运营记忆摘要与模型上下文分别计量，默认 2,048 tokens，可调为 256–4,096。每次读取最多 8 项、6,000 字符。模型选择原句摘录，程序核对来源 ID 和引文，并使用当前模型的 tokenizer 计量完整摘要 JSON。决策使用当前摘要。生成不完整或超预算时记录原因。

公开正文采用当前角色面向粉丝的自然文案，内部来源 ID 和 fictional 等技术元数据只存在后台字段；正文出现这类标识时拒绝提交，不能把调试引用直接发布。

摘要每个角色版本只保留当前快照，来源和授权变化、预算或 Provider／模型变化时失效重建。核对用的原句与摘要分存；摘要不能成为脱离原文的新事实。对话清理事务中若有过期来源，同时先清派生摘要缓存；工作台显示实际占用、上限、摘录、来源 ID 与更新时间。仅有摘录不代表所有可公开来源均已进入当前预算。

## 节奏与防滥发

默认每 1800 秒评估一次，最短 300 秒；模型可以选择更晚再看。发送至少相隔 6 小时，每滚动 24 小时最多 2 次尝试，操作者可设置更长间隔或更低额度。明确拒绝、超时及结果不确定均计入尝试，不能用重试绕过额度。

无新公开来源时仍可按评估节奏写感想或创作，也可以等待。已使用的来源及规范化后相同正文继续去重，人工拒绝稿的来源退出后续自动评估。引用为空的候选也记录生成时读取过的可撤销记忆，来源失效时阻止交付。模型选择等待不产生待发送动态。直播有排队或播放任务时后台运营延后，推理经过共享的唯一生成锁。动态开关、额度、退避和下一次评估时间持久化。

发布使用共享 B 站写入锁，每个候选只执行一次平台提交；平台成功码与有效动态 ID 均存在才记 published。明确拒绝保留原因；发送中取消、超时、无效响应或服务重启遗留 publishing 记 publish_uncertain，不自动重发，仅冻结该提交，等待操作者核对；其他有效任务继续运行。关闭运营或自动发布会在后续提交前重新检查，已提交请求以回执为准。

## 工作台与验收

提供统一自主运营启停、动态权限与自动发布设置、节奏与额度、手动评估、来源记忆公开标记、决定记录、草稿审核／修改／发布、平台回执与错误。所有接口要求管理员权限和同源写入，账号凭证统一在设置页维护，不回显或写入模型上下文。

工作台在页内区分待处理与历史。正文、配图与来源随实际选中草稿同步；编辑内容必须进入本次审核或发布请求。发布、拒绝或持久复制成功后移出待处理并清空编辑区与来源，普通保存仍留待处理；切换草稿保留未提交编辑，失败保留正文与可重试操作。

对已发布的工作台文字或普通图文动态，号主可以在聊天提供原动态链接或 ID 和修订要求。聊天显示原文与建议文案。确认时核对当前账号、原动态正文及配图和剩余编辑次数，提交到原动态并保留现有图片。原动态回读与修订一致后才更新本地正文，保留初次发布回执和时间。提交结果未确认时，后续操作只读核对该动态。

公开互动附图沿引文的父链追溯起因，选择相关的后续回复和已确认的结果。根评论独立显示，楼内回复缩进并显示「回复 @用户名」，父评资料缺失时显示其评论 ID。卡片显示已有用户名、UID 和业务时区的时间，保留原文换行，超长摘录可从原评论查看全文。每张图最多六条评论，按真实时间排布，缺时间的历史材料按评论 ID 排序，关键原评缺失时在图中标明。正文与来源预览为同一 BV 只展示一处具体评论链接。新草稿的 PNG 预览与提交共用快照，旧稿和已提交载荷按各自版本回读。

默认不自动选图；开启use_memes后由小结构阶段选一个当前OC图库ID或null，正文和来源完整保留。手工选／换／清除配图均回待审核，正文不清空；附图草稿不能仅复制文字冒充已复制图文。评论图按快照顺序上传，最多九张，与单张图库配图一样使用一次 scene=2 提交。每次上传前检查授权，最终提交预约唯一发布意图并保存本次正文和有序图片回执。图片准备失败或准备阶段取消保留可审核草稿。最终结果不确定时只读核对原账号、正文和有序图片回执，证据不足时继续保留待核对。图片被禁用或来源公开性撤销时提交拒绝，审核及不确定草稿保留占用防止图片被删除。

验收覆盖默认不发送、开启后的自主选题、无来源的表达与事实核对、手动草稿停审核、私聊交接脱敏、撤销／删除后的提交拒绝、去重、额度、停止、恢复与未知回执。真实账号发布以平台回执确认。
