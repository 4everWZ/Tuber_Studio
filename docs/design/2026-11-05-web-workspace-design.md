# Tuber Studio Web 工作台改版提案

采用常驻文字侧栏，默认打开「自动刷视频」，首屏可以改来源、看待办、轮次进度与最近活动。大肥鱼在服务端连续找视频、取材、判断、写稿和发送。操作者只需启动一次，之后可以关掉网页。服务重启后待命，由操作者再次启动。

## 现状依据

- 用隔离实例查看了评论、自主运营和独立直播页。评论首屏优先展示 BV 取材，自动候选在另一页审核。侧栏只露出四个分组，每组的具体栏目需切过去才能看。直播控制又分布在主界面和独立场景页。
- 对照改版前的 `automation.js`，旧版能查字幕轨、分 P 覆盖、引用片段和回执。现版浏览任务详情主要显示结果与理由，候选详情主要显示引用数量。服务端任务接口仍返回可用证据和缓存状态。
- 自主运营空页会在服务待命时显示「正在自主巡航」。现版「停止本轮」只调用普通停止，私信和评论提示中提及的「紧急停止所有自动收发」在 Web UI 缺少对应动作。
- 服务端有周期调度和推荐发现，但调度入口依赖自主运营总开关。该开关的预检同时探测公开通知和私信。现有代码和旧测评无法证明目标部署能在关网页后连续刷视频，持续运行要单独验收。

## 信息架构

侧栏常驻四个运营入口、直播工作台、角色工作室和设置。场景、曲库、语音和素材在所属工作区切换。同一任务的配置用页内区块或折叠项呈现。列表用于选记录，详情用于阅读和处理。窄屏使用导航抽屉。保留选中项、筛选和滚动位置，浏览器返回能回到原记录。顶栏常驻当前 OC、推理连接及模式、后台运行状态。

| 侧栏分组 | 栏目与职责 |
| --- | --- |
| 运营 | **评论与草稿**处理公开草稿和回执。**自动刷视频**控制后台运行、看轮次、视频证据及点赞收藏。**私信**处理会话、移交和私域恢复。**动态**处理公开素材、决策、草稿和发布。 |
| 直播工作台 | **控制与输出**处理会话、播放、队列、事件和 OBS 浏览器源。**场景**编辑画布、图层和属性。**曲库与点歌**管理音乐、在线组件及候选确认。**互动与游戏**管理规则和模拟。 |
| 角色工作室 | **角色卡**呈现模型内建 OC 与可编辑角色卡，角色记忆在页内展开。**语音**配置来源与试听。**素材与表情包**按角色维护形象和许可。动态页处理来源的公开授权。 |
| 设置 | **推理与模型**管理 Jetson 配对、模型和兼容 API。**账号与权限**维护凭证、授权与额度。**存储与维护**集中呈现缓存、运行诊断、上下文和留存策略。 |

栏目内部按当前对象分层。评论的取材、批量分类和生成在「评论来源」视图，当前楼的上下文维护在楼详情。直播场景和曲库直接可达，开停播、暂停队列、跳过和紧急静音归到直播控制。账号、模型或缓存出问题时，任务旁显示阻塞和直达链接，具体表单集中在所属栏目。

## 评论首页

```text
Tuber Studio                    当前 OC ｜ 推理模式 ｜ 自动刷视频：待命
运营
  自动刷视频    评论与草稿                   [评论来源与手动取材]
  评论与草稿    状态筛选 [待审核 ▾]
  私信          ┌───────────────────┬────────────────────────────┐
  动态          │ 公开评论待办      │ 来源视频／评论楼／草稿来源 │
直播工作台      │ 1. 状态、来源     │ 草稿正文与编辑             │
角色工作室      │ 2. 状态、来源     │ 引用片段与发布资格         │
设置            │ …                 │ 审核、拒绝、复制或提交     │
                └───────────────────┴────────────────────────────┘
```

- 初始筛选为「待审核」，现有渠道的待审草稿和手动草稿在同一列表，标明「自主浏览」「公开互动」或「手动」。浏览页的对应候选链接到同一条详情。点赞和收藏仍在自动刷视频的互动记录中审核。移交私信只显示移交状态和入口，正文留在私信。
- 有可用内容时，详情把原文、草稿和当前可用动作放在首屏。字幕／帧引用、续接历史和平台回执在同一条记录内展开。核对中只开放只读核对，明确拒绝才沿现有规则修订。状态和动作由各渠道的真实记录决定。
- 「手动取材」提供按 BV／链接读取和 JSON／CSV 导入，打开才显示表单。保留页数、导入预检、原始评论、筛选、按楼上下文、批量生成和既有任务记录。
- 空态随真实状态变化。待命时给「开始自动刷视频」入口，后台运行时显示当前阶段，连接或刷新失败时标明原因及数据更新时间。只有请求成功且列表确实为空时显示零条。

## 自动刷视频

开始一次即授权本次运行的新公开回应。大肥鱼自行取材和判断，愿意回应时发送主评或楼内跟帖。单条失败立即重试一次，再失败则下轮补一次，第三次仍失败记为跳过。

首页上方是运行状态、启停和可直接编辑的发现来源。关键词与指定 BV 按来源显示，保存从下一轮生效。需要操作者处理的事项优先显示，当前视频、处理阶段、轮次计数和最近五条活动仍可见。点开活动就地查看完整内容和回执。较早的记录在「全部运行记录」，报错集中在「告警与错误」。回复上限、轮次间隔和全渠道控制在设置。

## 实现边界

- **管理壳**持有认证、路由、全局状态和共用请求客户端。各栏目持有自己的筛选、选中记录、编辑和请求生命周期。后台服务状态可订阅，列表和详情按可见范围刷新。过期请求不得覆盖较新的筛选或未保存输入。
- **评论队列**提供手动草稿和浏览评论意图的只读聚合，保留渠道与原始 ID 作为记录标识，回写继续使用各自接口。先核对现有接口的条数上限与分页；若不能准确给出待办总数或打开历史记录，补兼容的服务端列表或详情查询。公共聚合只读公开字段。
- **自主浏览**复用服务端周期、预算、证据、防重和轮次生命周期。把启用配置、当前运行和上次结果拆为可区分的状态。按账号与 OC 绑定开始、停止和重启状态，验证快速启停、重复开始和运行中切换身份。采用兼容 API 扩展表达独立刷视频状态及控制。
- **直播**保留 `/live` 直达和 `/overlay` 独立播放边界，复用场景、曲库和播放器逻辑。管理栏目共享会话状态和动作实现，场景编辑可在独立焦点视图展开。进入页面和编辑场景不启动会话或切换推理模式。
- 按完整工作流逐个替换现有入口，保留已有书签的跳转。新路径覆盖原有操作、状态及失败恢复后，清除重复入口和隐藏表单。保留现有原生模块及交付方式。

## 交付与验收

| 顺序 | 交付 | 可观察的通过条件 |
| --- | --- | --- |
| 1 | 自动刷视频端到端 | 受控平台验证一次开始后自动发送主评与跟帖、连续多轮运行、失败三次跳过及未知回执只读核对。目标账号的真实发布由操作者启动。 |
| 2 | 新导航和评论首页 | 用一条自动评论草稿、一条手动草稿、一条待核对及一条私信移交走完整流程。首屏能看来源和当前动作，审核后更新正确记录，刷新不覆盖编辑，待核对不会出现重发，私信正文不出现在公开队列。按 BV 和文件导入仍可走通。 |
| 3 | 自主运营详情和其余栏目迁移 | 从候选追到真实字幕或帧、续接及回执。覆盖视频证据失效、权限部分失败和急停。按原功能迁移私信、动态、角色、语音、缓存和直播，分别验证本地直播控制、场景保存、点歌、OBS 入口及移动端暂停／静音。已保存布局、凭证、会话及已有记录应继续可用。 |
