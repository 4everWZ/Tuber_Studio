# 长期目标的来信与评论楼跟踪

适用于「这位观众下次来信时，在这个目标里提醒我」。来源是工坊已经同步到本地的 B 站私信收件箱。它和每日／每周主动读取的周期跟进互不启用，也不改变私信同步或发送策略。

## 设置与读回

1. 在「对话 → 活动」打开任务，选择「设为长期创作目标」，或直接打开已有目标。
2. 打开「来信事件跟踪」，核对接收账号和角色，填写**发送者的数字 UID**，再选择「授权跟踪此 UID」。每个目标只跟踪一个 UID；不支持昵称、关键词或所有会话。没有已核验的接收账号时不能授权。
3. 新回执出现在已有的私有提醒和目标执行记录里。打开能核对发送 UID、接收账号、平台消息 ID 和本地收件箱条目 ID。已读仅清除对应提醒，不删除执行记录。正文仍在私信工作区。
4. 修改 UID 并保存可替换授权；「停止事件跟踪」立即停用。关闭目标、切换账号／角色或改版导致执行 epoch 变化后，旧授权也不会恢复。已有回执按目标的读取权限保留。

## 哪些事件会提醒

- 只消费授权生效后**新入库**且平台、接收账号、角色、对方 UID 都匹配的来信。这是本地入库事件，不是平台实时推送；后来补同步的较早消息也可能触发。已入库的历史、号主发出的消息及其他会话不触发。
- 初次授权、换目标 UID 或重新启用时从当时收件箱末端开始。同一有效配置重复保存不会跳过待消费事件。跟踪不调用模型、不读取消息正文、不联系平台，也不生成回复草稿。
- 消费使用独立的目标读取位置，按本地收件箱 ID 前进，不改私信同步的翻页游标。现有任务 worker 每次选择一个有新事件的目标，最多取 16 条，再让出执行机会。停机时已入库的记录在重启后继续处理。
- 活动、提醒与读取位置在同一 SQLite 事务提交。私有回执按「目标 + 来源 + 接收账号 + 平台消息 ID」去重；同一事件重新消费不会重新弹出已读提醒。写库失败回滚并重试。可靠消费以原业务库及其保留的收件箱为前提，不跨数据库重建推断身份。

## 管理 API

`GET /api/agent/tasks/{goal_id}/goal/events` 返回当前账号、角色、执行 epoch、跟踪状态、配置版本和读取位置。此路由与活动共用管理认证，目标不属于当前可见范围时返回 404。

`PUT` 到同一路由，提交 `source: "bilibili_inbox"`、`sender_uid`、GET 返回的 `epoch` 和 `revision`。账号和角色由服务端绑定。停用使用 `DELETE .../goal/events?revision=<当前版本>`。配置过期返回 409，应重新读取并核对目标后再保存。提醒直接使用已有的 `/api/agent/attention` 与任务详情／已读接口。

## 跟踪指定评论楼

长期目标还可以独立跟踪一个公开评论楼。通过管理 API 读取 `GET /api/agent/tasks/{goal_id}/goal/comment-events`，向同一路由 `PUT` 返回的 `epoch`、`revision`，以及 `resource` 和 `root_id`。视频资源填完整 BV 号，动态填 `dynamic:<动态数字 ID>`，楼层填平台根评论 ID。更换楼层时使用最新版本。停用使用同一路由的 `DELETE ?revision=<当前版本>`。

工坊在业务模块首次核实并保存该楼的新评论时记录事件。同一账号、角色和平台楼层下的重复观察只通知一次。号主自己的评论、既有评论的刷新和其他楼层不触发。授权只消费本地记录；取材或同步仍按原运营设置运行。

每个私有提醒带 BV 或动态 ID、楼层、评论 ID、作者 UID 和原评论链接。待消费事件与首次观察一并写库，消费和提醒在同一事务提交。关闭目标、更换绑定、替换楼层或撤权后，旧配置中的待处理事件失效。已有提醒继续按目标读取权限保留。对观众回复需另行选择来源并审批。[限定回复](selected-replies.md)
