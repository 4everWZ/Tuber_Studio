# 评论、私信与动态运营

打开「评论与草稿」处理自动与手动草稿，按授权审核、提交并核对回执。配对使用 Jetson 配置的运营模型。大肥鱼 V6 的台词共用精简 OC 卡，视频画面补读在设置中完成视觉资源验证后启用。Gemma 4 E2B、其他通用 VLM 和兼容 API 使用完整角色卡。[双机部署](deployment.md#电脑业务主机与独立推理节点) · [角色指南](characters.md#选择角色生成方式)

## 账号与登录

在「设置 → 账号与权限」保存 SESSDATA 和 CSRF／bili_jct，留空保留原值；更换或清除账号也在这里操作。点击验证或刷新后，该页显示平台确认的 UID、头像、硬币和粉丝数，未知统计显示「—」。服务重启或验证过期后显示待验证，保存凭证本身不表示已登录。

本机可直接进入工作台。远程管理登录和 B站账号分别保存，平台 Cookie 失效时到设置更新。远程访问和令牌配置见[部署与启动](deployment.md)。

## 取材、审核与权限矩阵

「评论与草稿 → 评论来源与手动取材」支持填 BV 号或标准视频链接读取评论，以及导入 JSON／CSV。随后可按楼查看和批量生成。手工生成的回复进入待审核，支持修改、审核、复制与发布。草稿待办通过状态筛选查看待审核、待核对、处理中或历史。

点击运营工作台的权限状态，或进入「设置 → 账号与权限」。矩阵按动作配置禁止、待审核或自动提交，覆盖主评、跟帖、评论转私信、点赞和收藏。切换后核对账号、动作级别与额度；矩阵显示的是配置和状态，实际提交仍由服务端检查。私信独立读取／发送和动态发布沿用各自工作台的策略。矩阵与工作台显示不一致时，以刷新后实际保存的渠道策略为准。

工作台默认打开「自动刷视频」。点一次「开始自动刷视频」，大肥鱼自行选视频、取材、判断是否回应，并发送它决定的公开主评或跟帖。关网页后继续，服务重启后待命。首次失败自动重试一次，再失败就处理其它视频，下一轮补一次，第三次仍失败就跳过。提交超时会核对原回执。

在「设置 → 刷视频与运营」选择发现来源并调整视频 Agent 并发数、回复上限和轮次间隔，改动从下一轮生效。这里也可启动只读单轮预览或管理全渠道运营。首页显示当前或最近一轮进度及最近五条活动；点开已发送活动会进入「评论与草稿 → 已执行／历史」。较早结果在「全部运行记录」，报错在「告警与错误」。

打开评论详情或选择一个私信会话后，可进入「用户档案」确认称呼、偏好和重要互动，或清空这个用户的档案。退出个性化后，评论和私信都暂停使用档案与累计好感度。

## 大肥鱼自己决定发动态

1. 在评论设置配置同一个 B 站账号。
2. 打开「动态运营」。已发布的公开评论回复可作为来源；也可在来源记忆中勾选「允许用于公开动态」。未勾选的会话不会进入运营输入。角色故事会显示为虚构，保留虚构语境。
3. 可先点「评估并生成草稿」，查看决定、正文及引用来源。这个按钮不会自动发布，审核通过后可手动发布。
4. 开启「动态运营」后，角色在后台判断是否值得分享及何时再看；默认允许直接自动发布。关闭「自动发布」则后台只生成待审核草稿。

新安装的动态运营保持关闭。默认每 30 分钟评估，发送至少相隔 6 小时，每滚动 24 小时最多 2 次尝试；可以降低每天额度、延长发布间隔。没有新公开来源、内容重复或额度已用完时等待。平台拒绝和不确定结果也占用尝试额度。

决定记录显示为什么发或不发、下次评估时间、角色版本和来源原句；动态列表显示审核状态、错误与真实平台回执。可随时点「停止动态运营」。若显示「发布结果待核对」，可点「核对发送结果」只读查询原提交；匹配回执后同步本地记录，查不到或读取失败时保持待核对，不补发。

「运营记忆摘要」显示当前摘要的实际 token 占用、上限与带来源摘录。默认上限 2048 tokens，可在策略中调为 256–4096；它与 128K 活动上下文分开计量。公开记忆更新时覆盖当前摘要，不把旧摘要一直追加下去。撤销公开、清理原文或更换模型后，旧摘要会失效，待下一次评估重建。

切换角色或版本、删除来源、撤销公开都会使相关旧候选失效。公开标记不会延长会话的保留期限。更换模型／API 前先停止自动评论和动态运营；运营共用当前文本模型，不额外驻留一份模型或 TTS。


## 私信工作台

进入「私信工作台」，使用设置页维护的共享 B站账号。启用私信后可手动读取最近会话，选择用户与来信生成回复，再审核、修改、复制或发送。已发送显示平台消息ID；超时或发送中断显示待核对并禁止重发。当前只处理正常文本来信，不将本人、撤回、群组或系统消息交给模型，也不标记平台已读。

需要自动运营时分别开启自动读取、自动发送。新启用只处理之后的新来信，不追发历史；手工选中生成仍先审核。可设置读取间隔、每小时／每天上限和同用户冷却，点击「停止自动收发」阻止后续操作。平台验证、权限失败在页内显示，不会代为绕过。

「允许模型把评论讨论转入私信」开启后，角色根据当前公开楼选择回复渠道；不适合继续公开讨论时，评论草稿显示「已转私信」，在私信页处理。收件人固定为原评论作者；模型不生成任意目标地址。渠道判断沿用模型思考模式，可在私信策略中设置独立的「渠道判断输出额度」，默认2048 tokens（含思考），范围256–65536；正常回复和摘要额度不变。结构化生成失败或渠道与理由矛盾时，带原输出与具体反馈继续判断，未完成则保留检查点。

评论详情和私信会话显示同一OC对同一平台UID的好感度与阶段。昵称变化不创建新关系，同昵称不同UID不合并，不同OC相互隔离。共享数值不共享私信正文；私信也不会进入动态素材列表。

## 生成反馈与继续处理

正文不按固定字数截断。平台明确拒绝提交时，Agent结合原稿和实际错误决定修订、暂缓或放弃；原账号、收件人和来源保持绑定。人工发布产生的修订仍进入审核，自动模式继续沿用当前授权与额度。Agent暂缓后，也可自行改稿并重新审核，再直接发布这一修订版。

在自动化设置中调整每轮恢复次数，默认8，范围0–64，0关闭自动恢复。任务详情显示原稿、反馈、修订、调用与token用量；达到预算或期限后保存进度，可点「继续处理」启动下一轮。公私信路由未确定的生成原文到私信工作台查看。

发送超时或结果不确定时先点「核对发送结果」，查询匹配的平台记录；此时不会让模型改稿后重发。读取未找到记录不代表原提交失败，界面继续显示待核对。

## 大肥鱼表情包

在「素材 → 表情包图库」选择角色，预览已有鲸鱼素材及来源、许可，再按需启用；也可导入 PNG、JPEG、GIF 或 WebP，每张最多8 MiB。图库原件独立保存，不随媒体缓存清理；被草稿占用的图片须先处理对应草稿才能删除。

私信草稿可选择文字或单张表情包，选图后重新审核，最终只发送一条图片消息；原文字保留作审阅及文字替代。动态草稿可保留正文并附一张图，换图或清图后重新审核。评论目前仍使用文字。

模型自动选图默认关闭，开启后只从当前角色已启用的图库选择；选择失败保留待审。现成图库可直接使用，图片生成接口预留且尚未挂载模型。实际账号发图权限和 GIF 播放效果仍需单独验证。

## 缓存大小与清理

在「设置 → 存储与维护」查看音乐、语音、临时产物和浏览材料的已用／可回收／受保护容量，并设置最大缓存。独立直播工作台底部也提供缓存入口。浏览池默认512 MiB，任务和待审核候选引用的原文受保护；清理后旧分析不能脱离原文用作事实。音乐共用一个池，最高15 GiB，新安装默认15 GiB；旧在线缓存上限继续保留，浏览材料不重复计入音乐池。

「清理可回收缓存」保留曲库引用、当前／待播和刚上传素材。需要释放曲库原文件时，先从曲库移除条目，再清理；降低容量到受保护素材以下会被拒绝。模型、音色包、登录信息、原始项目素材、评论／私信记录和关系数据不受媒体清理影响。
