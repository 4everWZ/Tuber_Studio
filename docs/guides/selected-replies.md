# 在号主任务中处理选定回复

评论工作区已绑定账号的视频评论草稿、私信收件箱来信产生的回复草稿，可以交给 Agent 逐项处理。号主通过 Studio 管理 API 固定选择，再在对话目标中带上返回的选择编号。活动中的每条审批显示发送账号、角色版本、公开楼层或私信收件人、平台来源 ID 和实际正文。图片私信显示素材 ID 与内容指纹。

1. 请求 `GET /api/agent/reply-selections`，核对当前账号和角色，取得执行 `epoch`。
2. 请求 `POST /api/agent/reply-selections`，传该 `epoch` 和 `items` 数组。每项给出 `channel`、`draft_id` 和 `source_ids`。评论用 `comments` 和本地评论条目 ID；私信用 `messages` 和本地收件箱条目 ID。收件人从业务记录读取。只有和草稿实际回复范围完全一致的来源可以一起选中。
3. 将返回的 `selection_id` 随目标交办。Agent 可以查询所选条目，再逐条提出审批。到达发送边界时重新核对正文、来源、审批、账号和角色。已收到号主公开回应的评论跳过；后续来信可以同步进收件箱，只结算被选中的来信。
4. 可用 `DELETE /api/agent/reply-selections/{selection_id}` 撤回尚未提交的动作。已有发送在任务活动中按原发送令牌核对。结果不明确时保留待核对状态，复核成功可查看对应平台回执。

发送令牌与该条领域发送记录的 ID 在同一事务绑定。进程在平台确认后中断时，如果草稿和该次发送记录都已保存同一回执，恢复会用已存回执补齐账号账本。缺少回执时只核对原提交；记录不匹配时继续保留待核对状态。

选择集合只适用于当时的账号、角色版本和运营授权。来源、正文或账号绑定变化后，重新选择并审核。原评论工作台、私信工作台及自主运营共用账号发送账本；同一会话或评论楼存在待核对提交时，后来发送须等待原回执。评论转私信仍通过原领域移交流程处理。
