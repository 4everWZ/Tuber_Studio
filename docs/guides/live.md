# 直播工作台与点歌

从主界面侧栏进入「直播工作台」，或打开同一服务的`/live`，沿用管理员登录。它与评论工作台共享角色、声音及运行状态。打开页面和编排场景不启动直播，也不切换资源模式。

源码模板默认关闭直播，须由Operator在设备配置中显式启用`features.live_enabled`后再开播；ready镜像新安装的默认行为见[部署指南](deployment.md)。

## 编排画面

在画面或左侧图层选择组件，鼠标拖动移动、拖右下角调整大小；方向键微调1px，Shift＋方向键微调10px。右侧可输入位置、尺寸和层级，设置显示／锁定。背景可选深海场景或透明；标题、角色、当前歌曲、歌词、队列、弹幕、礼物和装饰独立编排。

点击「保存布局」才持久保存并更新overlay；刷新后恢复已保存布局。未保存时可「撤销布局修改」，「恢复默认布局」会先确认，再作为未保存修改呈现。预览静音，编辑或保存不会重新播放音频。

「打开OBS播放器」打开独立`/overlay`，也可从主界面设置复制播放器链接给OBS浏览器来源。链接含独立播放凭证，请勿公开分享。只有一个输出页面获得播放权，其余待机；工作台预览不参与竞争。OBS输出不含编排手柄和管理控件。浏览器确认不代表OBS本体已验收。

## 曲库与正常点歌

1. 导入16-bit PCM WAV、FLAC或MP3歌曲，每个文件最多96MiB、时长0.05至600秒、单／双声道。原始文件直接缓存与播放，使用对应媒体类型，支持范围请求。填写歌曲名、演唱者、来源与用途说明；未确认目标直播用途的条目可保存，不能播放。商业模式另检查商业用途。
2. 可同时提供独立人声用于开／合嘴；未提供时提示口型降级，保持待机，不以伴奏振幅驱动张嘴。默认嘴型复用已有大肥鱼图集，其他OC可提供`sing_open`／`sing_closed`标签。可选伴奏作为后续演唱接口的素材预留，当前直接播放仍使用完整歌曲文件。
3. 可提供带时间戳的LRC歌词，如`[00:12.00]第一句`。歌词以实际播放器时钟逐行更新，未提供时显示无同步歌词。
4. 显式开始Mock直播并打开播放器，从曲库点歌即可正常播放现成音频，不经过TTS唱歌。TTS继续用于互动说话。`song`事件可用`metadata.song_id`明确曲目；纯歌名只接受唯一精确匹配，同名须在曲库确认。

队列可上移、移除和清空。点歌设置可修改音乐音量、队列上限、同用户冷却；同曲排重。当前歌曲与互动串行播出，避免两路人声叠播；歌曲中穿插讲话的ducking策略后续接入。

「暂停歌曲」冻结当前音频／歌词／口型，「继续歌曲」恢复同一位置；「暂停队列」只阻止后续任务开始。跳过、紧急静音、停止或播放器断线会取消当前任务，已取消内容不自动重播。只有实际开始并正常结束才记为完成；歌曲播放不写入角色对话记忆。

## 可选在线点歌

先按[组件安装说明](../../components/song_requests/README.md)安装 Node.js 22+ 与本目录锁定的依赖，再开启工作台「在线点歌 → 启用点歌」。默认关闭，不随进入工作台启动。普通程序安装／镜像不携带 Node 或这部分依赖；可单独构建带组件的镜像。记录音源与目标用途说明并确认使用范围，沿用本地曲库的用途检查。

开启后可搜索歌名／歌手并确认专辑和版本，再加入现有队列；音频由原有 OBS 页面播放。弹幕 `点歌 歌名` 按规则识别，唯一精确匹配自动入队，有歧义时工作台展示候选。持有稳定平台用户 ID 的观众可在同一房间、120 秒内回复序号，主播也能点击确认；昵称不作为身份。没有匹配时不会擅自选首条或让 TTS 念歌词。当前可从 Mock 入口验证规则，真实直播平台 Adapter 仍后置。

默认按波点 → 咪咕顺序，先请求 FLAC，再尝试该音源的高码率，随后才换下一音源。高码率默认要求320 kbps，不接受更低音质；可在设置修改阈值并显式允许低码率。咪咕需要服务环境变量 `MIGU_COOKIE`，界面显示是否配置，不回显内容。实际文件的格式、采样率／位深或码率在播放信息中显示，不把上游声明当作实测音质。

只预备当前及下一首歌曲。缓存默认512 MiB，单曲默认96 MiB／600秒，下载最长90秒；源地址使用前重新解析，缓存不存签名 URL。缓存音频完整下载后检查实际流时长，与已确认版本相差超过3秒即拒绝。歌词取逐行LRC，主接口缺失时尝试另一歌词接口，仍缺失则显示无同步歌词。检索记录和播放任务保留歌曲ID、歌手、专辑、版本标题与时长。

关闭、重新配置或重启组件会停止当前在线歌曲、取消在线待播及准备，并退出旧 Node 进程；缓存与配置保留，本地歌曲和 TTS 互动不受关闭动作清理。组件故障时查看错误并点击「重启点歌组件」。准备失败的队列项会显示原因，可移除后重新点歌；不会静默降低到被禁止的码率或替换其他版本。

## 后续挂载演唱模型

当前没有默认演唱模型，WebUI显示「模型待接入」并禁用该模式；不能将它设为默认，也不会自动下载模型、转换音色或修改现有说话TTS。

开发者实现`src/tuber_studio/singing.py`中的`SingingProvider`，在应用构造时通过`create_app(..., singing_provider=provider)`挂载。Provider声明`id`、`version`、有界`timeout_seconds`，实现异步`prepare(request)`和`close()`。框架提供已验证的歌曲／可选人声／伴奏路径、歌词、当前音色配置／可选参考及受控输出目录；模型返回`SingingResult`，声明声音ID、Provider身份、音频和可选人声轨。

模型只负责生成音频，不自行播放。服务统一校验输出路径、格式、非静音、声音／模型身份并隔离缓存，沿用原播放者与ACK；取消／超时会传播到Provider，具体实现须释放自身推理／子进程资源。接口测试不证明音质通过，未来模型须另做人工试听与设备资源验收；详细契约见[声音规范](../specs/models-and-audio.md#说话与演唱能力)。
